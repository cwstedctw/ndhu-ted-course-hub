> **對比門檻寫死 WCAG 2.1 AA ＝ 一般文字 4.5:1**（不臨場改標準）。
> 建立：2026-07-26（洄瀾 W4-D）｜量測環境：Chromium 147、Playwright、DPR 1

## 0. 這些數字是怎麼量的（不是手算）

設計計畫 §4.1 白紙黑字：「手算 ≈ 值不得當定案引用」。所以這張表兩種來源都是實測：

| 來源 | 做法 | 用在哪 |
|---|---|---|
| **A. 逐節點掃描** | 把 `out/` 起成本機站，Chromium 開 `prefers-color-scheme: light/dark` 兩種情境，逐頁走訪**每一個直接帶文字的元素**，取 `getComputedStyle` 的文字色，再沿祖先鏈把背景色逐層 alpha 疊起來算對比 | 底色是純色的配對（絕大多數） |
| **B. 像素取樣** | 直接截該元素的圖，丟掉「像文字」的像素後統計剩下的底色像素，用**對比最差的那顆背景像素**算 | 底色是水彩圖／漸層的配對（hero、課程頁 hero） |

- 覆蓋範圍：`out/` 的 **28 個 HTML**（27 條 Next 路由＋根目錄 `404.html`；不含 3 份 deck 簡報與 `mc/` 小站，那兩者不吃 `globals.css`）
- 兩種寬度都跑：**390px（手機）／1280px（桌機）**
- 一輪共量到 **4,445 個文字節點**（亮暗各一輪）

腳本不在 repo 內（施工期工具，放在 scratchpad）。重跑方式見 §5。

## 3. 品牌色刻意不翻面（D1 退場線條件①）

| token | 亮版 | 暗版 | 為什麼不翻 |
|---|---|---|---|
| `--gold-500` ＋ `--ink-900` | `#D9A441` ＋ `#1A1A1A` | 一模一樣 | **離站加入 CTA 專用色**；兩版同色學生才認得出同一顆鈕（7.74:1） |
| `--teal-500` ＋ 白 | `#0E7C7B` ＋ `#FFFFFF` | 一模一樣 | 主鈕、頁首、選中態；5.01:1 兩版都過 |
| `--cream-100`、白 | 深底上的文字色 | 一模一樣 | 這兩支在暗版**仍是文字色**，翻了會變成深字壓深底 |
| `--ink-900` | gold 底上的文字色 | 一模一樣 | 同上，翻了 gold CTA 就爛掉 |

**唯一的連帶改動**：`--color-badge-cond-border`（有條件開放徽章的外框）在暗版跟著 `--gold-700 → --gold-200` 變成淺金。徽章的底＋字（`#D9A441` ＋ `#1A1A1A`）不變，AA 相關的那一組沒動。

## 4. 邊界與例外（誠實揭露）

1. **404 頁大字（亮版 4.26:1）**
   `.nf-code` 亮版是 `--teal-500` 壓在 cream 底上＝4.26:1。58px 粗體屬 WCAG 的「大型文字」、門檻 3:1 → **AA 過、但沒到 4.5**。這是 v1 就有的設定，本次沒改亮版；暗版改吃 `--teal-200` ＝ 6.96:1。
2. **課程頁 hero 的膠囊與連結**
   逐節點掃描（方法 A）會把它們讀成 3.42:1，原因是那層底是「深 teal 紗＋水彩圖」，程式只讀得到 `background-color`（teal-500）讀不到上面那層紗。像素取樣（方法 B）實測 **6.28:1**。**兩版數字完全相同**——這塊在暗版根本沒動。
3. **首頁搜尋框目前沒有樣式**
   `.v3-search-input` 的樣式寫在 `app/v3-extra.css`（W4-G 軌），**那支檔案還沒被 `app/layout.js` import**（該軌檔頭註明「import 一行交給洄瀾接線」）。所以現在它是瀏覽器原生外觀：暗版下 Chrome 畫成深灰框、placeholder 只有 2.43:1。
   接上 import 之後會自動好——`v3-extra.css` 的顏色全部吃 semantic token（`--color-surface`／`--color-text`／`--ink-40`），暗版對應值是 6.14:1。**這條不是暗版造成的，是接線還沒做。**
4. **量測方法本身的限制**
   方法 B 會把「元素外框的顏色」也算進背景候選（例如膠囊的 `--teal-mid` 邊框）。表內數字已排除這類邊框誤判；若自己重跑看到 2.08 之類的極低值，先確認命中的是不是邊框像素。

## 5. 退場線自檢（D1 條件②）

> 「W4 週中任一核心頁未過對比與手機實測 → 該頁保亮版；整體未穩 → 退回『亮底＋兩處暗舞台』上線。」

| 檢查 | 結果 |
|---|---|
| 28 頁 × 2 寬度 × 亮暗兩版，逐節點對比掃描 | **暗版新增的未達門檻節點＝0**（扣掉 §4-2 的量測誤差後，亮暗兩版都是 0） |
| 目視抽查（暗版、390px 全頁截圖）：首頁／演講牆／課程頁／演講詳情頁／關於頁／404／成績頁／開課清單 | 8 頁全數可讀，無深字壓深底、無亮底殘留 |
| 桌機 1280px 抽查：首頁 Hero＋焦點卡、演講牆 | 過 |
| 三態切換（系統暗自動暗／手動亮蓋過系統暗／手動暗蓋過系統亮／localStorage 記憶／無 JS／localStorage 被擋／列印） | 30 項全過（腳本 `toggle_test.py`） |
| 列印：手動選暗時列印是否回亮版 | 過（`§12` 全段只掛 `@media screen`，列印時 token 自動回 §1b 亮版） |

**結論：不啟動退場線，全站自動暗版可以留著。**

暗版踩到的三顆地雷（都已修，記在這裡免得下次再踩）：

1. `contour-cream.webp`（全站紙紋）是**不透明**的米色圖（實測 RGB 236,233,214、無 alpha）。暗版不關掉會把整頁鋪成米色。
2. `valley-hero.webp`（hero 水彩）也是亮圖，上面那層 cream 紗 `.74/.54/.28` 在暗版要加濃到 `.90/.80/.62`，標題才壓得住。
3. `.nf-art`（404 小紙船）用 `mix-blend-mode: multiply`——那是為亮紙底設計的，壓在暗底會被乘成一團看不出東西；暗版改 `screen` ＋ `opacity: .32`。
4. **切換鈕擠爆手機頁首**（跟顏色無關，但同一批做的）：多一顆 44px 的鈕之後，340–375px 與 420–479px 的頁首會折成兩列，sticky 頁首從 68px 長到 108–120px。原因是 flex 在「縮」之前會先「換列」。修法＝`<760px` 關掉 `flex-wrap`＋品牌名截字、`115-1` 徽章 `white-space: nowrap`。320–1280px 全段實測現在都是 68px 一列、零橫向捲動（420px 這一段本來就是 108px，順手一起修好）。

## 6. 怎麼重跑（改了顏色一定要重跑）

```bash
npm run build                      # 先出 out/
python audit_contrast.py           # 逐節點掃描（方法 A），輸出 contrast_result.json
python diff.py                     # 比對亮暗，列出「暗版變差且未達門檻」的節點
python pixel_pairs.py              # 像素取樣（方法 B），出上面兩張表的數字
python toggle_test.py              # 三態＋無 JS＋列印，30 項
```

腳本目前在 W4-D 施工用的 scratchpad；要長期留著就搬進 `scripts/`，並在 `package.json` 加一條 `a11y` 指令（本次沒動 `package.json`）。

**改色時的規矩**：`globals.css` 的暗色 token 有**三個檔位**要一起改——§1d（暗場舞台）、§12-1（系統暗）、§12-2（手動暗）。三處值必須一樣，不然「亮站上的暗舞台」跟「整站暗版」會長出兩套暗色。
