一顆開關，怎麼記住「第一次碰到」

接對兩個訊號時，閂鎖為什麼擋得住彈跳；兩腳按鈕為什麼要補一腳
這一頁在做什麼

兩顆 NAND 閘（兩個輸入都是 1 才輸出 0）交叉接起來，就變成一個會記住狀態的電路，叫閂鎖（latch）；它記住的是「第一次碰到」某一邊，也就是第一次把那個輸入拉成 0，所以開關碰上時金屬片彈好幾下（彈跳，bounce），它也不怕。工作台一先用理想的按鍵看它怎麼記住，工作台二換成三腳的撥動開關看它為什麼擋得住彈跳，工作台三換成兩腳的按鈕看它為什麼擋不住。最後一段給按鈕三條解法：ESP32 補一腳、純程式等一下、交給晶片的硬體幫忙記。

姊妹頁：按鈕彈跳實驗台（四種治法總覽）、ESP32 腳位透視鏡（腳位怎麼把電壓讀成 1／0）、程式在睡的時候，按鈕怎麼辦（sleep 卡住整支程式的問題）。

現在：兩個都放開＝保持

按左邊的 S̄ 接地鍵 或 R̄ 接地鍵，訊號會一級一級走給你看。

    兩顆 NAND 閘交叉接起來，就是一個會記住的電路：閂鎖。NAND 閘只看一件事：兩個輸入都是 1，才輸出 0；其餘都輸出 1。兩顆交叉接的意思是：NAND 1 的輸出 Q 接到 NAND 2 的上面那個輸入，NAND 2 的輸出 Q̄ 再接回 NAND 1 的下面那個輸入（圖中間兩條線交叉的地方沒有圓點，表示沒接在一起）。左邊兩顆接地鍵，平常被一顆電阻拉到 3.3 V，讀起來是 1（上拉，pull-up）；按住才接地，變成 0。

    S̄、R̄ 上面那條橫線的意思是「給 0 才算數」（低電位有效，active-low）：按住 S̄，Q 變 1，叫設定；按住 R̄，Q 變 0，叫重設（Set／Reset）。兩個都放開時什麼都不改，Q 保持原來的值。閂鎖記住的「第一次碰到」，就是第一次把某一邊的輸入拉成 0；同一邊之後再來幾個 0，都只是把同一件事再說一次。想自己控制節奏，按「暫停」再按「單步」。

    換成三隻腳的撥動開關：公共腳（圖左邊、轉軸那一腳）接地，開關裡會動的那片金屬（動片）一次只碰得到上面或下面。開關碰上的那一瞬間，金屬片會彈好幾下，一下接上、一下分開，這就是彈跳。開關裡真正碰在一起的金屬點叫接點（contact）；三隻腳的開關有兩個接點，上面的接 S̄（A 側）、下面的接 R̄（B 側），各有一顆 10 kΩ 上拉。ESP32 用兩支腳位（GPIO）來數：GPIO4 直接接在 A 側，GPIO5 接閂鎖的輸出 Q，跟 03 那支程式一樣，計數器數兩邊各變了幾次。

    彈跳只發生在動片正碰上、或正要離開的那一邊；另一邊在空中不動；閂鎖只認第一次碰到。

    一撥的過程：離開 A（在 A 抖幾下）→ 空中（兩邊都是 1＝保持，Q 不動）→ 碰到 B（在 B 抖幾下）。在 A 抖的時候 R̄ 一直是 1，Q 本來就是 1，再設定一次也不變；第一次碰到 B，R̄ 變 0，Q 翻成 0；之後 B 再怎麼彈回 1，S̄、R̄ 都是 1，只是保持。Wokwi 實跑撥 6 下：幾乎每一撥都印「直接接的腳位變了 3 次；經過閂鎖只變了 1 次」，只有一撥直接接的也只變 1 次。

    接法①：按鈕那一點接 S̄，R̄ 沒有接開關，只靠上拉一直是 1。按第一下，Q＝1；放開，S̄、R̄ 都是 1＝保持，Q 不回 0；第二下再按，Q 本來就是 1，看不出有按。不管按幾下，Q 一共只變 1 次。

    沒有人重設。兩腳的按鈕只有一個接點（按下時碰在一起的那一對金屬片），只夠接 S̄；閂鎖的另一個輸入沒人管。

    接法②（最直覺的補法，04 那個專案）：按鈕那一點接 S̄，再經一顆 NOT 閘（把 1 變 0、0 變 1）接 R̄。在這張簡化圖裡，S̄、R̄ 當成同時相反；實體閘還有很短的延遲。問題是兩邊都來自同一個接點：按鈕一抖，S̄ 跟 R̄ 一起抖，閂鎖一下被設定、一下被重設，Q 就跟著抖。Wokwi 實跑按 8 下：直接接的每按變 4／6／6／4／6／4／4／4 次，閂鎖 4／6／4／6／4／4／4／6 次，一樣抖。

    閂鎖要的是「兩個接點各抖各的」，NOT 閘做不出第二個接點。

    接法③：按鈕那一點接 S̄，R̄ 改由 ESP32 的 GPIO25 給，平常給 1。按下去的第一個接觸，閂鎖自己就記住了（Q＝1），不用等程式；之後的彈跳只是再設定一次，Q 不動。程式看到 Q 變 1 就開始計時，等按鈕放開、而且安靜 20 ms，才讓 GPIO25 給 0 一下，把 Q 清回 0，準備下一次。

    把控制板上「程式多久看一次按鈕」拉到 200 ms：Q 回 0 變晚了，可是按下的那一刻 Q 馬上變 1。程式晚一點處理也不會漏掉這次；但重設完成前不能接下一次：下一下如果在清掉之前就按，會跟上一下併成一次。

    Wokwi 實跑：直接接每按 4～6 次、Q 每按 2 次（按 8 下，八次都是 Q 變 2 次），跟離線模型算的一致；模型也算出 S̄、R̄ 同時是 0 的時間＝0。

    按鈕要怎麼配閂鎖：三條解法

    解法一

    ESP32 補第三腳（硬體閂鎖＋一點程式）

    一句話：按鈕接 S̄，R̄ 交給 ESP32 的 GPIO25；按下的第一個接觸由閂鎖記住，放開而且安靜 20 ms 之後，程式才把它清回 0。

    好處
    第一次碰到就記住；程式在忙，這一下也不會漏。
    代價

    # 05 兩腳按鈕 + 兩顆 NAND 閂鎖 + ESP32 補上「重設」。
# 閂鎖要兩個輸入：S（設定）和 R（重設）。三腳開關有兩個接點，一邊接 S、一邊接 R；
# 兩腳按鈕只有一個接點，只夠接 S。少掉的那一腳，由 ESP32 來當：
#   按下去 → 第一次碰到就讓 Q 變 1（閂鎖自己做，不用等程式）；之後的彈跳只是重複「設定」，Q 不動。
#   放開後 → ESP32 等按鈕安靜 20 ms，才給 R 一個 0，把 Q 清回 0，準備下一次。
# 接法：按鈕那點（10k 上拉）→ NAND1 的 A，也接 GPIO27；Q（NAND1 輸出）→ GPIO26；GPIO25 → NAND2 的 B（R）。
from machine import Pin
import time

raw = Pin(27, Pin.IN)               # 按鈕那一點：沒按＝1、按下＝0，會抖；只用來判斷「放開夠久了沒」
q = Pin(26, Pin.IN)                 # 閂鎖輸出 Q：按下＝1，要等 ESP32 重設才回 0
r = Pin(25, Pin.OUT, value=1)       # 接閂鎖的 R（低電位有效）：平常給 1；給 0 一下＝重設

QUIET_MS = 20                       # 放開後要安靜多久才重設：跟 02 一樣用 20 ms


def reset_latch():
    r.value(0)                      # 放開那一腳「接通」一下
    time.sleep_us(10)
    r.value(1)


reset_latch()                       # 開機先清一次，Q 從 0 開始

presses = 0
n_raw = 0                           # 按鈕那一點變了幾次（統計用）
n_q = 0                             # 閂鎖輸出 Q 變了幾次（統計用）
p_raw = raw.value()
p_q = q.value()
last_low = time.ticks_ms()          # 最後一次看到「還按著」的時間
latched = False                     # 閂鎖正記著一次按下、還沒清
last = time.ticks_ms()
dirty = False

print('按一下按鈕，看兩邊各數到幾次變化')
while True:
    now = time.ticks_ms()
    a = raw.value()
    if a == 0:
        last_low = now              # 還按著，或還在彈

    # ESP32 當「另一腳」：按鈕放開、而且安靜 QUIET_MS → 重設
    if q.value() == 1:
        if not latched:
            # Q 剛變 1：從現在起算安靜。按下那一瞬間的彈跳很短，程式可能根本沒讀到 0，
            # 只看 a 會把「彈開的那一下」誤當成已經放開很久，當場就清掉。
            latched = True
            last_low = now
        elif a == 1 and time.ticks_diff(now, last_low) >= QUIET_MS:
            reset_latch()
            latched = False
    b = q.value()

    # 以下只是統計，跟去彈跳無關
    if a != p_raw:
        n_raw = n_raw + 1
        p_raw = a
        last = now
        dirty = True
    if b != p_q:
        n_q = n_q + 1
        if b == 1:
            presses = presses + 1
        p_q = b
        last = now
        dirty = True
    # 安靜超過 300 ms 才報告：只是用來把每次按的統計分開
    if dirty and time.ticks_diff(now, last) > 300:
        print('第', presses, '次按：直接接的腳位變了', n_raw, '次；閂鎖 Q 變了', n_q, '次')
        n_raw = 0
        n_q = 0
        dirty = False

    解法三

    中斷＋一次性計時器確認（不加零件）

    一句話：腳位一從 1 變 0，晶片的硬體就把你寫的一小段處理函式叫起來，主程式正在 sleep 也一樣（中斷，interrupt）。這個處理函式只管一個只響一次的碼表（一次性計時器）：硬體一叫就重啟 20 ms 碼表、碼表到了再確認，按鈕還是 0 才算按了一下；按下與放開的彈跳都吃掉。

    看片段、什麼時候用、代價

    處理函式只收一個參數，就是那支腳位。

    09 那支程式裡去彈跳的那幾段（片段）
    deb = Timer(1)                      # 去彈跳用的一次性計時器（硬體計時器 1）


def confirm(t):
    # 最後一個邊緣之後 20 ms 才會跑到：按鈕還是 0 ＝ 真的按著，算一次
    global presses
    if btn.value() == 0:
        presses = presses + 1


def on_edge(pin):
    # 硬體叫的：每個 1→0 邊緣都會進來（包括彈跳）。只做一件事：重新啟動 20 ms 的一次性計時器
    global edges
    edges = edges + 1
    deb.init(period=20, mode=Timer.ONE_SHOT, callback=confirm)


btn.irq(trigger=Pin.IRQ_FALLING, handler=on_edge)   # 按鈕 1→0 就叫 on_edge

    作業要你用一顆按鈕做，正解不是硬把兩腳按鈕接進閂鎖，是替它補上第二個訊號。

    試試看：先猜，再按（課後練習，五題）

    每張卡先想一下答案，再按按鈕，上面的工作台會跳到那個狀態。

    ① 兩個都按著，再同時放開，Q 會是多少？

    對答案

    說不準。兩顆閘都想把輸出變成 0，慢的那一顆來不及變，輸出就留在 1。多按幾次「同時放開」，Q 有時是 1、有時是 0，結果事先不知道，所以這個組合不該用。

    ② 撥動開關碰上 B 側時抖了 10 下，Q 變幾次？

    對答案

    1 次。第一次碰到 B，R̄ 變 0，Q 翻成 0；後面那幾下只是 R̄ 在 0 和 1 之間跳，S̄ 一直是 1，閂鎖不是重設就是保持，Q 不會再變。

    ③ 接法②把 NOT 拿掉，會變成哪一種接法？

    對答案

    變成接法①：R̄ 沒人管，只能靠上拉一直是 1。按了之後沒有人重設，Q 只變一次。

    ④ 接法③把「安靜多久」改成 0 ms，會怎樣？

    對答案

    按下那一瞬間，接點彈開的那一下就被程式當成「已經放開」，當場把 Q 清掉；接點再碰上，Q 又變 1。一次按下，Q 變的次數比 2 多，閂鎖白記了。

    ⑤ 按住按鈕不放，Q 是多少、什麼時候回 0？

    對答案

    接法③：按住的時候 Q 一直是 1，程式看到按鈕還是 0，不會重設；放開、安靜 20 ms 之後，程式才讓 R̄ 給 0 一下，Q 回 0。接法①放開也不回 0；接法②放開就跟著回 0，還會抖。

    閂鎖的四種組合，一格一格推

    • S̄＝0、R̄＝1（設定）：NAND 1 有一個輸入是 0，不管另一個是什麼都輸出 1，所以 Q＝1。NAND 2 的兩個輸入是 Q＝1、R̄＝1，都是 1，輸出 0，所以 Q̄＝0。
    • S̄＝1、R̄＝0（重設）：NAND 2 有 R̄＝0，輸出 1，所以 Q̄＝1。NAND 1 的兩個輸入是 S̄＝1、Q̄＝1，輸出 0，所以 Q＝0。
    • S̄＝1、R̄＝1（保持）：兩顆閘都得看對方。原本 Q＝1、Q̄＝0 的話，NAND 1 看到 Q̄＝0，輸出 1，Q 還是 1；NAND 2 看到 Q＝1、R̄＝1，輸出 0，Q̄ 還是 0。兩邊互相撐著，停在原本的值。原本 Q＝0 也一樣推得出來。
    • S̄＝0、R̄＝0（兩個都按著）：兩顆閘都有一個 0，都輸出 1，Q 跟 Q̄ 都是 1，不再相反。放開時兩顆都想變 0，慢的那一顆輸出留在 1，結果看誰慢。

    為什麼叫 SR

    S 是 Set（設定：讓 Q 變 1），R 是 Reset（重設：讓 Q 變 0）。有人寫 RS、有人寫 SR，講的是同一種電路。

    為什麼寫 S̄、R̄

    上面那條橫線表示低電位有效：這兩個輸入平常是 1，給 0 才算數。用 NAND 接的閂鎖剛好就是這樣，所以開關、按鈕都是接到地，碰上時給 0。

    為什麼閂鎖自己不會抖

    Q 的值繞一圈回來撐住自己：Q＝1 讓 NAND 2 輸出 0，這個 0 回到 NAND 1，又讓 NAND 1 輸出 1，也就是 Q。輸出回頭撐住自己的輸入，叫正回授（positive feedback）。外面沒有新的 0 進來，它就一直停在原本那一邊；被推過去之後，也會自己撐在另一邊站穩。所以同一邊再來幾個 0，只是再說一次「設定」，Q 不會再變。
