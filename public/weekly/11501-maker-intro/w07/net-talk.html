上網怎麼講話實驗台

上週 ESP32 跟小螢幕講話只隔兩條線；今天它要跟你的手機講話，隔著整個網際網路。四個分頁都是慢動作模擬（不真的連網）：先看懂每一步在等什麼、對方回什麼，再去 Wokwi 真的跑。

實驗台卡住怎麼辦Wokwi 動手做找碴五題數字出處
① WiFi 報到：喊名字、等點頭、拿門牌（IP 位址）。對應 Wokwi 卡 01
② 寫一封信：網址三段、信封裡的 JSON（「名字：內容」的寫法）、回信的狀態碼（三位數）。對應 Wokwi 卡 02
③ 一條線回 40 位元：溫濕度感測器怎麼把兩個數字排成 40 個 1 和 0。對應 Wokwi 卡 03
④ 節奏與門檻：多久寄一次、超過幾度才寄——期中「判斷」的雛形（模擬已含寄一封的 5 秒）。對應 Wokwi 卡 03、04

喊名字：SSID

基地台有名字（無線網路名稱，SSID）。Wokwi 的叫 Wokwi-GUEST、沒密碼；真板要改成教室或家裡的名字和密碼。名字大小寫錯一個字就是另一個網路。

等點頭：status 1001 → 1010

喊完名字不會馬上好。程式用 while not wlan.isconnected() 一直問；1001＝還在連、1010＝拿到門牌、201＝找不到那個名字。

拿門牌：IP 位址

接上以後基地台給四樣東西：IP 位址（你的門牌，Wokwi 固定 10.10.0.2）、遮罩（哪些算同一條巷子）、閘道（出巷子一定經過的路由器）、DNS（把名字翻成號碼的服務）。

網址三段

https://api.telegram.org 寄到哪；/bot<token> 哪一個機器人（token 是它的密碼；寫網址時 <token> 整個換成那串，角括號不留）；/sendMessage 做什麼。

信封裡用 JSON

「名字：內容」一對一對，像 {"chat_id": "…", "text": "…"}。用 requests.post(url, json=…) 會自動封好；寫在網址上（GET）中文會變成 %E6… 那種碼。

回信一定有 ok 和狀態碼

200＝收下了，回 "ok": true；4 開頭＝你寫錯（401 token、400 chat_id、404 網址），回 "ok": false 和一句 description。網址本身被打壞（例如 token 裡有空格）對方回的就不是 JSON，程式會停在 ValueError。

一條線、40 個位元

ESP32 把線拉低一下＝「請回答」，感測器回五個位元組。短高＝0、長高＝1——跟上週的單線燈同一招。

最後 8 位元是檢查碼

前四個位元組加起來的尾數。對不上就整筆丟掉（驅動丟 Exception: checksum error），不會給你一個錯的數字。

DHT11 跟 DHT22 差一個字

DHT11 只有整數（±2 度，一秒問一次）；DHT22 到小數一位（±0.5 度，兩秒一次）。Wokwi 只有 DHT22 零件，程式寫 dht.DHT22；真板套件是 DHT11，改成 dht.DHT11。驅動選錯不報錯、數字是假的。

同一間聊天室一秒別超過一則

Telegram 的規矩（FAQ 原文是「避免超過」）：一個聊天室一秒別超過一則、群組一分鐘 20 則，再快會收到 429。但在 Wokwi 寄一封 HTTPS 要 5 秒左右、程式會停下來等回信——EVERY 設 1 實際也只有約 6 秒一則，快不起來；設 10 最乾淨。真板的 DHT11 也一秒才能問一次。

每次都寄 vs 跨過才寄

03 寄完等 10 秒再量，約 15 秒一則，兩分鐘約 9 則（從第 0 秒算起）。改成「只在跨過 30 度那一刻寄」，兩分鐘可能只有 1 則——這個「判斷」就是期中作品的中間那一段。

門檻附近會抖

溫度在 29–31 度晃，跨過門檻的那一刻會一直發生。真的裝置會加一點緩衝（例如超過 30 寄、要降到 28 才算回復）。

01 接上無線網路，拿到門牌

應該看到：紅燈先閃、再常亮；序列埠 開始找網路 Wokwi-GUEST → 幾個 . → 接上了，花了 … ms → IP 位址 10.10.0.2 → 遮罩、閘道、DNS 各一行 → 每 5 秒一行「還在線上嗎？ True」。燈一直閃不停＝還沒接上（看上面「卡住怎麼辦」第一列）。

# 01 接上無線網路：先報到，再拿到門牌（IP 位址）
# 前幾週 ESP32 都在跟旁邊的零件講話；今天第一次讓它跟網路另一端的電腦講話。
# 四步：① 打開網路卡 ② 說出要上哪一個網路（名稱＋密碼）③ 等對方點頭 ④ 拿到自己的 IP 位址
import network      # 無線網路卡的功能都在裡面
import time
from machine import Pin

SSID = 'Wokwi-GUEST'   # 網路名稱（SSID）。Wokwi 的模擬網路就叫這名字；真板改成教室或家裡的
PASSWORD = ''          # Wokwi-GUEST 沒有密碼；真板填密碼

led = Pin(16, Pin.OUT)                 # 紅燈（套件板面 IO4）：等待中一閃一閃，接上後常亮

wlan = network.WLAN(network.STA_IF)    # STA = 我是「用戶端」，去找別人的基地台（自己當基地台叫 AP）
wlan.active(True)                      # 打開網路卡
print('開始找網路', SSID)
wlan.connect(SSID, PASSWORD)           # 丟出「我要上網」——不會馬上好，要等

t0 = time.ticks_ms()
while not wlan.isconnected():          # 還沒接上就一直問
    led.value(1 - led.value())         # 閃燈：讓人看得出「正在等」
    print('.', end='')
    time.sleep(0.5)
print()
led.value(1)                           # 接上了：常亮
print('接上了，花了', time.ticks_diff(time.ticks_ms(), t0), 'ms')

ip, mask, gateway, dns = wlan.ifconfig()   # 四樣東西：門牌、遮罩、閘道、查名字的人
print('IP 位址', ip)        # 門牌：網路上別人找得到你的號碼（Wokwi 固定給 10.10.0.2）
print('遮罩   ', mask)      # 哪些號碼算「同一條巷子」
print('閘道   ', gateway)   # 出巷子一定經過的那台（路由器）
print('DNS    ', dns)       # 把 api.telegram.org 翻成號碼的服務

while True:                            # 接上以後就一直亮著；每 5 秒報一次還在不在
    print('還在線上嗎？', wlan.isconnected())
    time.sleep(5)

02 跟 Telegram 說「我上線了」

應該看到：已上線，IP 位址 10.10.0.2 → HTTP 狀態碼 200 → ok = True → 寄完了，去手機看；手機的 Telegram 多一則「我上線了！IP 位址 10.10.0.2」。沒貼 token 會只印一行提示。

# 02 跟 Telegram 說「我上線了」
# 01 讓 ESP32 拿到門牌；02 讓它寄出第一句話。
# 寄出去的路：ESP32 → 無線基地台 → 網際網路 → Telegram 的伺服器 → 你手機上的 Telegram。
# 你要先有一個 bot（跟 @BotFather 要）和一個 chat id（你跟 bot 那間聊天室的號碼）。
import network
import time
import requests     # 幫你把「寄一封 HTTP 信」的細節包好（舊名 urequests）
from machine import Pin

SSID = 'Wokwi-GUEST'
PASSWORD = ''
TOKEN = '貼上 BotFather 給你的 token'   # 長得像 123456789:AAHxxxxxxxxxxxx（冒號前是 bot 的號碼）
CHAT_ID = '貼上你的 chat id'             # 一串數字；怎麼拿到見投影片
WAIT = 30                                # 最多等幾秒；等不到就是閘道那端沒接上，不是你的錯

led = Pin(16, Pin.OUT)


def connect():
    # 跟 01 一樣：打開網路卡、說出網路名稱、等接上；只是多了「最多等 WAIT 秒」
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    if not wlan.isconnected():
        print('接網路中', end='')
        wlan.connect(SSID, PASSWORD)
        t0 = time.ticks_ms()
        while not wlan.isconnected():
            if time.ticks_diff(time.ticks_ms(), t0) > WAIT * 1000:
                print()
                print('等了', WAIT, '秒還沒接上：看投影片閘道掛了那一頁，等一下再按播放')
                return None
            led.value(1 - led.value())
            print('.', end='')
            time.sleep(0.5)
        print()
    led.value(1)
    print('已上線，IP 位址', wlan.ifconfig()[0])
    return wlan


def send(text):
    # 網址三段：固定的 https://api.telegram.org ＋ /bot＋token ＋ /要做的事（sendMessage）
    url = 'https://api.telegram.org/bot' + TOKEN + '/sendMessage'
    # 要寄的內容用 JSON 包起來放在信封裡（POST）：chat_id 說寄給誰、text 說寄什麼
    r = requests.post(url, json={'chat_id': CHAT_ID, 'text': text}, timeout=15)   # 最多等 15 秒
    print('HTTP 狀態碼', r.status_code)     # 200 = 對方收下了；401 = token 不對；400 = chat_id 不對
    try:
        reply = r.json()                    # 對方回的也是 JSON：ok 是 True 或 False
    finally:
        r.close()                           # 用完一定要關（就算回的不是 JSON），不然記憶體會一直少
    print('ok =', reply.get('ok'), reply.get('description', ''))
    return reply.get('ok')


if ':' not in TOKEN or not CHAT_ID.lstrip('-').isdigit():
    print('先把 TOKEN 和 CHAT_ID 貼到第 12 和 13 行的引號裡，再按播放')
else:
    wlan = connect()
    if wlan:
        if send('我上線了！IP 位址 ' + wlan.ifconfig()[0]):
            print('寄完了，去手機看')
        else:
            print('沒寄成，看投影片的卡住對照')

03 隔一會兒寄一則溫濕度，太熱加一行

應該看到：約 15 秒一行（寄一封約 5 秒＋等 10 秒）第 N 則：溫度 24.0 度，濕度 40 %＋HTTP 狀態碼 200 ｜ok = True；點 Wokwi 的 DHT22 零件把溫度拉到 31，下一則多一行 太熱了！超過 30 度。沒貼 token：印「token 或 chat id 還沒填好：只印在序列埠，不寄 Telegram」，每 10 秒一行讀數（這時紅燈不會亮，正常）。

# 03 把溫度和濕度寄到 Telegram：寄完等 10 秒再量一次（約 15 秒一則），太熱就加一行警告
# 輸入（感測器）→ 判斷（超過門檻？）→ 輸出（寄一則訊息）——期中作品就是這個形狀。
# 沒填 token 也能跑：只印在序列埠、不寄（感測器那段不用網路）。
import network
import time
import requests
import dht          # 溫濕度感測器的驅動，韌體內建
from machine import Pin

SSID = 'Wokwi-GUEST'
PASSWORD = ''
TOKEN = '貼上 BotFather 給你的 token'
CHAT_ID = '貼上你的 chat id'
EVERY = 10          # 寄完等幾秒再量下一次（寄一封本身約 5 秒，所以大約 15 秒一則）
HOT = 30            # 幾度算太熱（上課時把感測器的溫度拉過去試）
WAIT = 30           # 接網路最多等幾秒；等不到就只印不寄

sensor = dht.DHT22(Pin(15))   # Wokwi 只有 DHT22 零件；套件上是 DHT11（板面 IO7＝GPIO15），真板把 DHT22 改成 DHT11 就好
led = Pin(16, Pin.OUT)
HAS_TOKEN = ':' in TOKEN and CHAT_ID.lstrip('-').isdigit()   # 兩個都貼了才算


def connect():
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    if not wlan.isconnected():
        print('接網路中', end='')
        wlan.connect(SSID, PASSWORD)
        t0 = time.ticks_ms()
        while not wlan.isconnected():
            if time.ticks_diff(time.ticks_ms(), t0) > WAIT * 1000:
                print()
                print('等了', WAIT, '秒還沒接上：先只印不寄（看投影片閘道掛了那一頁）')
                return False
            led.value(1 - led.value())
            print('.', end='')
            time.sleep(0.5)
        print()
    led.value(1)
    print('已上線，IP 位址', wlan.ifconfig()[0])
    return True


def send(text):
    url = 'https://api.telegram.org/bot' + TOKEN + '/sendMessage'
    r = requests.post(url, json={'chat_id': CHAT_ID, 'text': text}, timeout=15)
    try:
        ok = r.json().get('ok')
    finally:
        r.close()                             # 回的不是 JSON 也要關
    print('HTTP 狀態碼', r.status_code, '｜ok =', ok)
    return ok


def read():
    sensor.measure()                          # 叫感測器量一次（它用一條線回 40 個位元）
    return sensor.temperature(), sensor.humidity()


if HAS_TOKEN:
    ONLINE = connect()
else:
    ONLINE = False
    print('token 或 chat id 還沒填好：只印在序列埠，不寄 Telegram')
n = 0
while True:
    n = n + 1
    try:
        t, h = read()
        text = '第 %d 則：溫度 %.1f 度，濕度 %.0f %%' % (n, t, h)
        if t >= HOT:                          # 判斷：超過門檻才多一行
            text = text + '\n太熱了！超過 ' + str(HOT) + ' 度'
        print(text)
        if ONLINE:
            send(text)
    except Exception as e:                    # 感測器沒回（OSError）、檢查碼錯（Exception）、回信不是 JSON（ValueError）：印出來、下一輪再試
        print('出錯了，下一輪再試：', e)
    time.sleep(EVERY)

04 回家玩：在手機上問，板子回答

應該看到：手機先收到「我醒了，可以用 /temp /on /off 跟我講話」；你送 /temp 它回溫濕度、/on 紅燈亮、/off 紅燈關；按住板子上的綠按鈕到序列埠出現「寄出」（一輪要問一次 Telegram、約 8 秒才看一次按鈕），它主動寄「按鈕被按了！…」；按住不放只算一次。

# 04 回家玩：在手機上問，ESP32 回答（雙向）
# 02、03 都是 ESP32 主動寄。04 反過來：一直去 Telegram 問「有沒有人跟我講話」（getUpdates，每輪結束後等 3 秒），
# 看到指令就回：/temp 回溫濕度、/on 和 /off 開關紅燈。按住板子上的按鈕（A）到序列埠出現「寄出」，也會主動寄一則。
import network
import time
import requests
import dht
from machine import Pin

SSID = 'Wokwi-GUEST'
PASSWORD = ''
TOKEN = '貼上 BotFather 給你的 token'
CHAT_ID = '貼上你的 chat id'
WAIT = 30

sensor = dht.DHT22(Pin(15))
led = Pin(16, Pin.OUT)
btn = Pin(5, Pin.IN, Pin.PULL_UP)      # 按鈕 A（板面 IO11）：沒按是 1、按下是 0
BASE = 'https://api.telegram.org/bot' + TOKEN + '/'
last_id = 0                            # 處理完的訊息編號，下次從它的下一個開始要
was_pressed = False                    # 上一輪按鈕有沒有按著：按住不放只算一次


def connect():
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    if not wlan.isconnected():
        print('接網路中', end='')
        wlan.connect(SSID, PASSWORD)
        t0 = time.ticks_ms()
        while not wlan.isconnected():
            if time.ticks_diff(time.ticks_ms(), t0) > WAIT * 1000:
                print()
                print('等了', WAIT, '秒還沒接上：看投影片閘道掛了那一頁，等一下再按播放')
                return False
            print('.', end='')
            time.sleep(0.5)
        print()
    print('已上線，IP 位址', wlan.ifconfig()[0])
    return True


def send(text):
    r = requests.post(BASE + 'sendMessage', json={'chat_id': CHAT_ID, 'text': text}, timeout=15)
    try:
        reply = r.json()
    finally:
        r.close()
    print('寄出', reply.get('ok'), text, reply.get('description', ''))


def reading():
    sensor.measure()
    return '溫度 %.1f 度，濕度 %.0f %%' % (sensor.temperature(), sensor.humidity())


def handle(text):
    if text == '/temp':
        send(reading())
    elif text == '/on':
        led.value(1)
        send('紅燈亮了')
    elif text == '/off':
        led.value(0)
        send('紅燈關了')
    else:
        send('看不懂，可以用 /temp /on /off')


def ask():
    # 去問 Telegram 有沒有新訊息；offset 說「編號比上次大的才給我」，不然同一則會一直收到
    global last_id
    r = requests.get(BASE + 'getUpdates?offset=' + str(last_id + 1) + '&timeout=0', timeout=15)
    try:
        data = r.json()
    finally:
        r.close()
    if not data.get('ok'):
        print('問不到：', data.get('description', ''))
    for u in data.get('result', []):
        msg = u.get('message', {})
        text = msg.get('text', '')
        if str(msg.get('chat', {}).get('id')) == str(CHAT_ID):   # 只理你本人的聊天室
            print('收到指令', text)
            handle(text)
        last_id = u['update_id']       # 處理完才記下編號：回覆途中出錯，下一輪會再拿到同一則


if ':' not in TOKEN or not CHAT_ID.lstrip('-').isdigit():
    print('先把 TOKEN 和 CHAT_ID 貼到第 12 和 13 行的引號裡，再按播放')
elif connect():
    try:                                   # 開機先跳過以前沒收走的舊訊息（只拿最後一則的編號）
        r = requests.get(BASE + 'getUpdates?offset=-1&timeout=0', timeout=15)
        try:
            old = r.json().get('result', [])
        finally:
            r.close()
        if old:
            last_id = old[-1]['update_id']
    except Exception as e:
        print('跳過舊訊息時出錯：', e)
    send('我醒了，可以用 /temp /on /off 跟我講話')
    while True:
        try:
            ask()
            pressed = btn.value() == 0
            if pressed and not was_pressed:    # 剛按下去那一刻才寄；按住不放不重複（一輪要問一次 Telegram、約 8 秒，所以要按住到序列埠出現「寄出」）
                send('按鈕被按了！' + reading())
            was_pressed = pressed
        except Exception as e:
            print('出錯了，下一輪再試：', e)
        time.sleep(3)

找碴五題：這支程式會怎樣？

想看更深（上課不講）

網址上的中文

GET 把內容寫在網址上時，空白和中文要先變成 %E6%88%91… 那種碼（每個 UTF-8 位元組一個 %）。POST 放信封裡就不用，所以 02 用 json=。上面「② 寫一封信」切到 GET 可以看。

HTTPS 的第一趟比較久

網址開頭 https 的信是加密的：寄第一封之前要先跟對方交換鑰匙（握手），所以第一趟比後面慢（Wokwi 實跑：第一趟 6.5 秒、之後約 4.9 秒；純 HTTP 1.7 秒）。MicroPython 的 requests 預設不檢查對方證書（CERT_NONE），所以 ESP32 不用先對時也能寄；要檢查證書得自己多做幾步，這門課不做。

門牌怎麼發的

接上基地台後，基地台用一套叫 DHCP 的規矩發門牌、遮罩、閘道、DNS 給你；Wokwi 的公用閘道固定發 10.10.0.2。真板在教室拿到的會是教室網段的號碼。

問 vs 推

04 是「問一次、等回信、睡 3 秒，一輪約 8 秒」（getUpdates，短輪詢）；真的服務多半讓 Telegram 主動推到你的伺服器（webhook）。ESP32 沒有公開的門牌可以被推，所以用問的。沒收走的更新 Telegram 只留 24 小時。

Wokwi 的公用閘道

免費帳號走 Wokwi 雲端的共用閘道（docs 寫：慢、穩定度中、流量被監看——別傳私人資料）。10/17 下午它回 503，整個下午連不上；上課若遇到，先用這頁把流程看完，Wokwi 回家補跑。
