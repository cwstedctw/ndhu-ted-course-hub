按鈕彈跳實驗台

按一下，為什麼程式算成好幾次？
這一頁在做什麼

按鈕裡面是兩片金屬，碰上的那一瞬間會彈幾下（彈跳，bounce），一下接上、一下分開。程式讀得比彈跳快，就把一次手指的動作算成好幾次。左邊按下去，右邊的示波器把那幾毫秒放慢畫給你看：上面一條是腳位的電壓，下面一條是程式讀到的值。下面四個分頁是四種治法，兩種改程式、兩種加零件，切過去示波器就換成對應的波形。

現在：內建上拉、按鈕接地

想看腳位「讀」按鈕時裡面那兩顆電晶體怎麼動：老師畫的 Falstad 電路「ESP32 Digit Input」——上拉、按鈕接地（這一頁的接法）／下拉、按鈕接 +5 V（真的電路模擬器，載入要等幾秒）

這一支程式什麼都不防：接上電就一直讀（polling），每 0.1 ms 讀一次腳位，只要看到值從 1 變成 0 就算一次按下。手指按下去的瞬間，兩片金屬在彈，它每彈一下就算一次——所以按一下，常常數到三、五次。

這支程式（MicroPython）
01-bounce-count／main.py
# 01 彈跳計數：按一下按鈕，程式數到幾次？
# 接法：按鈕一腳接 GPIO5、另一腳接 GND；程式開內建上拉（沒按＝1，按下＝0）。
# 這支程式「故意」什麼都不防：讀到 1 變 0 就算一次。
from machine import Pin
import time

btn = Pin(5, Pin.IN, Pin.PULL_UP)   # 沒按＝1，按下去＝0
led = Pin(16, Pin.OUT)              # 紅燈 16（跟閃爍那支一樣）

count = 0                           # 程式數到幾次
led_on = 0
prev = btn.value()                  # 上一次讀到的值

print('按一下按鈕，看右下角數到幾次')
while True:
    now = btn.value()
    if prev == 1 and now == 0:      # 從 1 變 0 ＝ 按下去的那一刻
        count = count + 1
        led_on = 1 - led_on         # 燈換一次狀態
        led.value(led_on)
        print('第', count, '次')
    prev = now

什麼時候用：多算幾次也沒關係的場合才敢這樣寫，例如只是把訊號印出來看。要拿來數次數、開關燈，就一定要治。

最省事的一招：讀到變化先不要信，等一下再讀一次。等的這段時間裡金屬片已經彈完、貼穩了，再讀到的值才算數。示波器上黃色那塊就是「等待窗」，窗右邊那一點就是再讀的時刻。等太短（比彈跳還短）會照樣多算；等太久會漏掉連按——把拉桿拉到 200 ms、再按那顆「連按兩下」自己看。等待窗比畫面還寬的時候，黃色那塊會一路延伸到「現在」，等程式醒來再讀，才會出現那一點。

02-software-debounce／main.py
# 02 軟體去彈跳（等一下再讀）：讀到變化先等 20 ms，再讀一次才算數。
# 接法跟 01 一樣：按鈕一腳接 GPIO5、另一腳接 GND，程式開內建上拉。
from machine import Pin
import time

btn = Pin(5, Pin.IN, Pin.PULL_UP)   # 沒按＝1，按下去＝0
led = Pin(16, Pin.OUT)

count = 0
led_on = 0
prev = btn.value()
wait_ms = 20                        # 等彈跳過去的時間：20 ms 是常見起點，真的開關要自己試

print('按一下按鈕，多半會剛好數一次')
while True:
    now = btn.value()
    if now != prev:                 # 讀到變化
        time.sleep_ms(wait_ms)      # 等彈跳過去
        now = btn.value()           # 再讀一次，這次才算數
        if prev == 1 and now == 0:  # 真的從 1 變 0
            count = count + 1
            led_on = 1 - led_on
            led.value(led_on)
            print('第', count, '次')
        prev = now

什麼時候用：程式簡單、停下來等個 20 ms 也沒關係的時候。缺點是等的那段時間程式什麼都不能做。

不想讓程式停下來，就改成每 5 ms 瞄一眼：連續好幾次都讀到跟現在不一樣的值，才承認它真的變了。示波器中間那條上的紫色小圓點就是每一次瞄的結果，最下面那條是程式「承認」的值。次數調少會太敏感，調多會變鈍——自己拉拉看。

4 次 ＝ 20 ms
這支程式（MicroPython）
02-software-debounce／main-stable.py
# 02b 軟體去彈跳（連續幾次一樣才算）：每 5 ms 讀一次，連續 4 次都跟現在不一樣才承認它變了。
# 好處：不用一口氣停 20 ms；每隔 5 ms 看一眼，之後要把別的工作插進迴圈也比較容易。接法跟 01 一樣。
from machine import Pin
import time

btn = Pin(5, Pin.IN, Pin.PULL_UP)
led = Pin(16, Pin.OUT)

count = 0
led_on = 0
state = btn.value()                 # 目前承認的狀態
same = 0                            # 連續幾次讀到不一樣

print('按一下按鈕，要 4 次都讀到 0 才算按下')
while True:
    now = btn.value()
    if now == state:
        same = 0                    # 跟承認的狀態一樣，重新數
    else:
        same = same + 1
        if same >= 4:               # 連續 4 次（20 ms）都不一樣，承認它變了
            state = now
            same = 0
            if state == 0:          # 變成 0 ＝ 按下
                count = count + 1
                led_on = 1 - led_on
                led.value(led_on)
                print('第', count, '次')
    time.sleep_ms(5)
再往下一步：不用 sleep 也不用一直數

也可以不用數次數，改用時間戳記：把「上一次看到變化的時刻」記在 time.ticks_ms() 裡，每次讀到變化就用 time.ticks_diff() 算距離上次多久，太近的一律不理。另外也能用中斷（Pin.irq()）處理，這裡先不展開。

什麼時候用：不想讓程式一口氣停 20 ms 的時候；之後想把別的工作插進迴圈也比較容易。

不改程式，改接法：在腳位旁邊加一顆電容，電壓就不能說變就變，得慢慢爬（電阻乘電容，RC）。但光是爬得慢還不夠——電壓爬到中間那段灰色地帶時，晶片不保證讀到什麼，值會亂跳。再加一顆施密特觸發器（Schmitt trigger，例如 74HC14 這類零件）就穩了：它往上要超過 2.475 V 才肯翻成 1，往下要低過 0.825 V 才肯翻成 0，中間怎麼晃都不理，所以一次按下只翻一次。

重點看

電容像一個小水桶：電要先把它灌滿，電壓才爬得上去，所以那幾下彈跳被磨成一條慢慢爬的曲線。施密特觸發器則像有段差的翹翹板——要推過頭才翻得過去，想翻回來也要推過另一邊。

想看數字怎麼算
1.0 ms

電容上的電壓：3.30 V。電阻乘電容 ＝ 10 kΩ × 100 nF ＝ 1 ms。

想看清楚腳位怎麼把電壓讀成 1 或 0、中間那段為什麼不保證，去隔壁那一頁：ESP32 腳位透視鏡（輸入模式）。

什麼時候用：程式改不動（別人寫的、或已經忙到沒空等）、或者同一條訊號要給好幾個地方用的時候。代價是多兩顆零件、多一點錢。

簡化：圖上的施密特觸發器畫成不反相的樣子，方便對照門檻；實際的 74HC14 輸出會跟輸入相反，接了之後程式判斷要跟著反過來。

換一種開關：三隻腳的撥動開關（單刀雙擲，SPDT），中間那隻腳固定接地，動片一次只碰左邊或右邊。關鍵在這裡——彈跳只發生在正要碰上的那一邊，碰不到另一邊。再用兩顆 NAND 閘交叉接成閂鎖（SR latch）：它會記住「第一次碰到」是哪一邊，之後那一邊再怎麼抖，它都不理。圖上直接接的那條線接在 A 側，所以離開 A 和回到 A 都會抖；閂鎖只認第一次碰到。點圖上的開關撥撥看，每個輸入輸出的 1／0 會即時標出來。

彈跳只發生在正要碰上的那一邊；閂鎖只認第一次碰到，之後那一邊再怎麼抖，它都不理。

橘線是高電位（1），灰線是低電位（0）；線上的圓點表示接在一起，跨過去的小橋表示沒接。兩顆 10 kΩ 電阻平常把兩邊都拉到 1，動片碰到哪一邊，哪一邊才變 0。

動片碰到 A 側：A 側＝0，NAND 1 有一個輸入是 0，不管另一個是什麼都輸出 1，所以 Q＝1。動片離開 A 側、還沒碰到 B 側時兩邊都是 1，但 NAND 1 的另一個輸入這時是 0，Q 還是 1——這就是「記住」。碰到 B 側：B 側＝0，NAND 2 輸出 1，Q 才翻成 0；B 側再彈回 1，兩個輸入都是 1，Q 也翻不回去。

這支程式（MicroPython）：同一顆開關，兩條路比數字
03-nand-latch／main.py
# 03 硬體去彈跳：兩顆 NAND 閘接成閂鎖（SR latch），配一顆三腳的撥動開關。
# 同一顆開關、兩條路：GPIO4 直接接在開關上（會抖）、GPIO5 接在閂鎖輸出（不抖）。
# 程式什麼都不防，只數「值變了幾次」，兩邊一比就知道硬體有沒有擋住彈跳。
from machine import Pin
import time

raw = Pin(4, Pin.IN)                # 直接接在開關的 A 側那一腳（有 10k 上拉）：離開 A、回到 A 都會抖
clean = Pin(5, Pin.IN)              # 接在閂鎖的輸出 Q

n_raw = 0                           # 直接接的腳位變了幾次
n_clean = 0                         # 閂鎖輸出變了幾次
p_raw = raw.value()
p_clean = clean.value()
last = time.ticks_ms()
dirty = False

print('撥一下開關，看兩邊各數到幾次變化')
while True:
    a = raw.value()
    b = clean.value()
    if a != p_raw or b != p_clean:
        if a != p_raw:
            n_raw = n_raw + 1
        if b != p_clean:
            n_clean = n_clean + 1
        p_raw = a
        p_clean = b
        last = time.ticks_ms()
        dirty = True
    # 安靜超過 300 ms 才報告：這 300 ms 只是用來把每次撥動的統計分開，跟去彈跳無關
    if dirty and time.ticks_diff(time.ticks_ms(), last) > 300:
        print('本次：直接接的腳位變了', n_raw, '次；經過閂鎖只變了', n_clean, '次')
        n_raw = 0
        n_clean = 0
        dirty = False

什麼時候用：程式一行都不想改、手邊又有多的閘可以用的時候。代價是要換成三腳的撥動開關，普通的兩腳按鈕接不出這個效果。

試試看：五個上課常被問的問題

為什麼燈按一下沒反應？

程式每數到一次就把燈換一次狀態。彈跳讓一次按下被算成偶數次時，燈換過去又換回來，看起來就是「沒反應」；算成奇數次才會留下變化。所以「燈有時候有反應、有時候沒有」，往往不是燈壞了。

等 5 ms 夠嗎？

要看你的開關。實測 18 顆開關，閉合時平均約 1.6 ms，去掉兩顆極端值之後最長 6.2 ms——等 5 ms 對大部分開關夠，對那幾顆比較會抖的就不夠。把彈跳程度調到「重」，5 ms 馬上破功。

等太久會怎樣？

等待時間拉到 200 ms，再用「連按兩下（間隔 100 ms）」——那是人真的按得出來的節奏，可是第二下整個落在等待窗裡面，程式醒來時只看到一個穩定的值，兩下就被併成一下。玩遊戲、打拍子的場合，這比多算一次更惱人。

只加電容、不加施密特觸發器行不行？

電容讓電壓爬得慢，但爬過 0.825 V 到 2.475 V 中間那段灰色地帶時，晶片不保證讀到什麼——波形上會看到讀值在那段亂跳，有時候反而比不加電容更慘。要就加一顆施密特觸發器，不然乾脆用軟體治。

閂鎖為什麼不會抖？

動片離開 A 側的時候，接點會先斷開、再碰一下才真的走（放開時的彈跳通常比閉合短），所以直接接的那一腳兩個方向都會抖。可是那一刻 B 側還是 1，閂鎖記得「上一次碰到的是 A」，輸出動都不動；直到真的碰上 B 側才翻過去，B 側再怎麼彈回 1 也不理。閂鎖只認第一次碰到，這就是它能治的原因。
