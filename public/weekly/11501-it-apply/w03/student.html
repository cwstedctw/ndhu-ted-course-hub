AI 幫你做網站，你決定收不收

資訊科技與應用 W3。AA：2026/09/21；AB：2026/09/22。兩節課共 100 分鐘，休息另計 10 分鐘。

今天做三件事：把一頁網站放上網、寫一份給 AI 的任務契約、叫 AI 改網站然後至少退回它一項。你會用到瀏覽器和一個 AI（ChatGPT 桌面版的 Codex，或任一網頁版 AI），不必裝 Git、不用命令列。

1. 今天交什麼

  • 課內最低（下課前）：一個打得開的網址、任務契約五格填好、AI 至少跑過一輪。
  • 完整版（AB 9/29 上課前、AA 10/05 上課前——AA 9/28 停課）：網址；repo 裡的 index.html 至少兩個 commit（原版、AI 改版）；任務契約.txt（含採用／修改／拒絕）。交到 e學苑 Week 3 作業：線上文字填網址，任務契約.txt 當附檔；也可以一起放進 repo。
  • 證據卡當堂填，老師巡場勾記或依課堂指示拍照上傳 e學苑。帳號卡關當堂登記，不扣分。

2. 先把家蓋好：一個 repo、一個網址（15 分鐘）

完整步驟在共用指南〈我的第一個 repo〉（本頁最下面附了全文；之後也會放在 e學苑「一般」區塊）。以下合計 40 分鐘的實作，濃縮成三步：

  1. 先登入 GitHub，再開 https://github.com/new?name=my-site&visibility=public，名稱 my-site、Public、勾 Add a README，Create repository。
  2. 先按頁首「下載起步檔」→ 在下載夾對 starter.zip 按右鍵「全部解壓縮」。回 repo 按 Add file → Upload files，從解壓出來的資料夾把 index.html（或你自己做的那一頁）拖進去，只放這一個檔、放最外層、不要拖整包 ZIP。Commit changes 寫一句「放入自我介紹首頁」。
  3. Settings → Pages，Deploy from a branch、main、/ (root)、Save。通常等一兩分鐘（官方說最久可到 10 分鐘）重新整理，出現「Your site is live at …」，用手機打開那個網址。還沒亮就先往下做第 3 節，回頭再看。

公開 repo 任何人看得到：不放學號、電話、地址，任何地方都不放密碼。

3. 寫任務契約（5 分鐘）

課內直接把五格填在證據卡第 2 節（或紙上）；起步包的 任務契約.txt 是下次上課前要交的檔（純文字，記事本雙擊就開），填完存到自己的雲端或寄給自己（教室電腦重開會清空），交到 e學苑 Week 3 作業當附檔。今天的題目是「請 AI 把我的 index.html 弄好看」：

格寫什麼今天可以這樣寫
成果要拿到什麼一頁比現在好看的 index.html
背景現在是什麼情況一頁自我介紹，有一顆會回話的按鈕
限制什麼不能動不改我寫的字；按鈕要照樣能按；不加彈出視窗；只改 <style> 區塊、不要重排其他行
例子像什麼樣子清爽、海洋感、好閱讀；藍綠為主、米白底
驗收怎樣才算對保留現有文字不改字；文字與背景對比加深；手機上不橫向捲動；連結都能點

「驗收」那四句就是你等一下檢查它的清單。寫不出驗收，就還沒準備好叫它做。

4. 叫 AI 改（8 分鐘）

用 ChatGPT 桌面版的 Codex 模式（W2 作業裝好的那個），或任一網頁版 AI（Gemini、ChatGPT 網頁版），同分。

  1. 先貼這段當開場白，等它回「收到」：
接下來請你幫我做事，整個過程守四條規矩：
1. 做任何「刪除、覆蓋既有檔案、寄出訊息、上傳到網路或放到 GitHub 公開、花錢」的事之前，先停下來講你要做什麼，等我回「可以」再做。
2. 不確定我的意思、或有兩種以上做法，先問我，不要自己選。
3. 我說「先解釋，別動手」時，只說明、不執行。
4. 動到我重要的檔案之前，先複製一份備份（檔名加 _backup）再動原檔。
先回我一句「收到」，我們再開始。
  1. 拿 index.html 的原始碼：回 repo 點開 index.html，按右上角 Raw 旁邊的複製圖示（Copy raw file）——不要用瀏覽器打開那一頁再複製，那樣拿到的是畫面不是原始碼。把原始碼和契約五格貼給它，最後加一句：「先用白話講你打算改哪些地方，我說好你再動手。改完告訴我你動了哪幾處。」
  2. 看它列的計畫。有一項你不要（例如它說要改你的自我介紹文字），就先說「不要那一項」。
  3. 說「好」，拿到改好的整份 index.html。它回的是「說明文字＋程式碼區塊」，只複製程式碼區塊（區塊右上角有 Copy 鈕）；它只給片段、說「其餘不變」的，要它「給我完整的整份」。用 ChatGPT 桌面版 Codex 的人：它會直接改你電腦上那個檔，先開一個只放 index.html 的乾淨資料夾給它。

5. 貼回 GitHub、看它改了什麼（7 分鐘）

  1. 在 repo 點開 index.html，按鉛筆，先點進編輯框再 Ctrl＋A 全選、貼上 AI 改好的版本，Commit changes 寫「AI 改版：對比與手機版」。
  2. 等一到兩分鐘再重新整理你的網址（手機看不到新版就關掉分頁重開）。看到新版了嗎？手機上會不會橫向捲動？按鈕還能按嗎？——這就是拿契約的「驗收」四句去對。
  3. 點 index.html 的 History，點最上面那一筆：紅色 − 是拿掉的，綠色 + 是加上的。它說的「動了哪幾處」跟這裡對得上嗎？ 整頁都是紅綠＝它把整份重寫了，這本身就可以是你退回的一項。

6. 採用、修改、拒絕：至少退回一項（5 分鐘）

它給的不是全收。在證據卡寫三欄，每欄至少一項：

  • 採用：這項我要，為什麼。
  • 修改：這項我改了，改成什麼。
  • 拒絕：這項我不要，為什麼——例如它改了我的字（限制寫了不改）、它加了我沒要的東西。

退回不是跟它吵架，是講清楚：「不要 X，改成 Y」，再要一次。理由寫得出來才算退回。

7. 改壞了，貼回上一版

網頁被改壞（字不見了、按鈕不動了）：History → 找到改壞前那一筆 → 按那一列右邊的 <>（View code at this point）→ 按 Raw 旁的複製圖示（或按 Raw 後全選複製）→ 按左上角 repo 名稱回到 main → 打開 index.html → 鉛筆 → 全選貼上 → Commit changes 寫「救回上一版」。改壞和救回都留在歷史裡，這是正常的；舊版畫面的鉛筆按不了也是正常的。

8. 沒有帳號、沒有 Codex、卡住了

  • 沒有 Codex：任一網頁版 AI 做同一件事，同分。
  • GitHub 帳號還沒好：今天照樣做第 3、4、6 節（契約、叫 AI 改、退回一項）；把 AI 改好、你驗收過的 index.html 交到 e學苑 或當堂給老師，老師在自己的示範 repo 幫你開一頁，下次上課前給你網址。證據卡「網址」填卡在哪一步、「看得懂差異」寫「下次前補」。一樣有網址、一樣的分數。
  • 卡住、看到紅字：複製錯誤訊息整段原文 → 貼給 AI 加一句「我在做 ___ 時出現這段，先解釋、再說你會怎麼查」→ 看它的計畫、不照單全收 → 自己驗一次。四格（原文／它說／我做／結果）記在證據卡。

9. 下課前

  • 離堂證據卡：網址、契約五格、退回一項、diff 一句。
  • 手機互開網址。
  • 下一堂：AB 9/29「改一個標題，目錄全亂了」；AA 9/28 停課，10/05 合併週。今天的網址留著，願意公開的成果往這裡放；作業與草稿交 e學苑。

操作文件核對日：2026/09/10（GitHub 官方文件）。按鈕位置可能調整；畫面對不上時，以官方文件與老師示範為準。

我的第一個 repo：一個網址，放你這學期的作品

全程在瀏覽器做，不裝任何東西、不用命令列。需要一樣：你的 GitHub 帳號（W2 作業辦好的那個）。
大約 15 分鐘。做完你會有一個網址，手機打得開，整學期的東西都放這裡。

先講三個詞

  • repo（repository，儲存庫）：把檔案和它的修改歷史放在一起的櫃子。裝的不只程式——筆記、圖、報告、網頁都可以放。
  • Git：記錄版本的工具。你今天不會直接碰它。
  • GitHub：放 repo 的網站，順便給你一個網址。今天全部在這個網站上按按鈕。

你要練的不是背指令，是三件事：存得住（東西留得下來）、看得懂差異（這次改了什麼）、救得回來（改壞了能復原）。AI 幫你產東西的時候，這三件就是你驗收它的方法。

1. 建一個公開的 repo（3 分鐘）

  1. 登入 GitHub，開 <https://github.com/new?name=my-site&visibility=public>。名稱沒有自動填上就自己填 my-site，並確認選的是 Public。
  2. 勾 Add a README file，按 Create repository。
  3. 看到 repo 首頁就好了。它的網址是 github.com/你的帳號名/my-site。

⚠️ 公開＝任何人都看得到。 這個 repo 只放願意給任何人看的東西：不放學號、電話、地址，任何地方都不放密碼。作業、報告草稿交 e學苑，不放這裡。

名稱被用過就加尾碼（例如 my-site-2），不要刪掉舊的重來。

2. 放進第一個檔案 index.html（3 分鐘）

  1. 拿到一個 index.html：老師給的範本（起步包裡那份），或你自己做的那一頁（任何 AI 幫你生的那一頁也可以，先存到電腦上）。
  2. 回 repo 首頁，按 Add file → Upload files，把 index.html 拖進去（老師給的起步包是 ZIP，先在下載夾對它按右鍵「全部解壓縮」，再從解壓出來的資料夾拖）。只放這一個檔、放在最外層，不要多包一層資料夾，也不要整包 ZIP 拖進去。
  3. 下面「Commit changes」的框裡寫一句這次做了什麼，例如「放入自我介紹首頁」，按 Commit changes。
  4. 回到檔案清單，點開 index.html，確認內容在裡面、檔名是小寫的 index.html。

每一次留版（commit）都要寫一句「改了什麼」。這句是給三個月後的你看的。

3. 開網址（3 分鐘，加一兩分鐘等它）

  1. 進 Settings（看不到 Settings 就按分頁列最右邊的「…」再選），左邊選 Pages。
  2. 「Build and deployment」下面，Source 選 Deploy from a branch；Branch 選 main、資料夾 / (root)，按 Save。
  3. 通常等一兩分鐘（官方說最久可到 10 分鐘），重新整理這一頁，上面會出現「Your site is live at https://你的帳號名.github.io/my-site/」。還沒亮就先做第 4 節，回頭再重新整理。
  4. 用手機打開那個網址。 隔壁同學的手機也打得開，才算數。

看到 404：先再等一下；還是 404 就核對三件事——檔名是小寫 index.html、它在最外層、來源是 main 和 / (root)。網址開了、但畫面只有一行 my-site（那是 README 的內容）：代表它找不到你的 index.html，同樣核對這三件。

免費帳號的 GitHub Pages 要用公開 repo（私有 repo 開網址要付費方案，這門課不需要）。

4. 改一行，看得懂差異（3 分鐘）

  1. 點開 index.html，按右上角的鉛筆（Edit）。
  2. 改一句——例如把興趣那一句換掉。按 Commit changes，寫「改興趣那一句」。
  3. 回到檔案頁，按 History，點最上面那一筆。畫面會分兩色：紅色、前面有 − 的是拿掉的；綠色、前面有 + 的是加上的。

指著畫面說「我把哪一句改成哪一句」——這就是看得懂差異。之後 AI 幫你改網頁，你驗收它的地方就是這個畫面。

5. 改壞了，貼回上一版（3 分鐘）

  1. 先把剛才那一句故意改壞（例如刪掉半句）並 Commit changes，寫「練習：故意改壞」。
  2. 按 History，找到改壞之前那一筆，按那一列右邊的 <>（View code at this point）——這就是那一版的 index.html。右上角按 Raw 旁邊的複製圖示（Copy raw file），或按 Raw 之後全選、複製。舊版畫面的鉛筆按不了，是正常的。
  3. 按左上角的 repo 名稱回到首頁（main），打開現在的 index.html，按鉛筆，全選、貼上，按 Commit changes，寫「救回上一版」。
  4. 再打開 index.html 看一次，確認內容回來了。

改壞的那一筆和救回的那一筆都留在歷史裡。這叫救得回來，不是把歷史刪掉。

6. 之後每週怎麼用

每週做完的東西放進來、寫一句 commit。到期末，整學期的作品都在同一個地方，而且每一步都有紀錄。

卡在帳號怎麼辦

帳號還沒辦好、驗證信一直收不到的人：把願意公開的 index.html 交到 e學苑，或當堂交給老師。老師在自己的示範 repo 幫你開一頁，下一次上課前給你網址。一樣有網址、一樣的分數。
