今天做的東西很小：算出「最近 7 天學了幾分鐘、記了幾筆」。上週你用一段話就請 AI 做出來了。今天換一種做法，是東西要交給別人用的時候用的做法：

  1. 先講清楚：把你要的規則一條一條寫下來。
  2. 先出考卷：請 AI 照規則先寫測試。功能還沒寫，測試一定不會過。
  3. 再請 AI 動手：另開一個對話寫功能，寫到測試全過。
  4. 自己驗：看它有沒有偷改考卷，再用另一個版本對照。
兩條路線，分數一樣
路線 A路線 B
用什麼自己的筆電，加上會讀檔寫檔的 AI（agent）教室電腦，加上聊天 AI
檔案怎麼改agent 直接改資料夾裡的檔AI 給你內容，你貼到測試頁和 GitHub
怎麼存檔請 agent 存檔（commit）並推上 GitHub在 GitHub 網頁上編輯，按 Commit changes

今天不用新帳號，也不用安裝任何東西。需要：瀏覽器、GitHub 帳號、你平常用的 AI。

怎麼讀這一頁

每一步先講要做的事。有分路線的地方，路線 A 和路線 B 各看各的。看到綠色的「看到這裡就對了」，親眼看到了再往下。卡住的時候，點開那一步的「卡住了」，或看最下面的卡關總表。

跟 AI 講話的地方，除了第 3 步那一句全班要一樣，其他只列「要講到的事」，用你自己的話說。

看不懂的詞，查最下面的基礎知識補給站和名詞小抄。想知道為什麼要這樣做，開互動概念頁。

第 1 步｜先猜：最近 7 天是幾分鐘、幾筆？（不用 AI）

今天是 11/23（一）。學習紀錄裡有這五筆：

日期學了幾分鐘
11/23（今天）30
11/1720
11/23（今天）沒填
11/1699
11/2450

網站上那一行「最近 7 天：共幾分鐘、幾筆」，你覺得應該顯示多少？把你的答案寫在紙上。

看到這裡就對了。 你寫下了一組數字。跟旁邊的人對一下，不一樣是正常的。

「最近 7 天」有好幾種讀法。只講一句話的時候，AI 也只能挑一種來猜。今天要做的，是把你的讀法寫下來，讓它不用猜。

第 2 步｜拿起步檔，放進一個新的 repo

下載起步檔 starter.zip，對它按右鍵 →「解壓縮全部」。裡面有六個檔：

檔案做什麼誰來改
rules.md你的規則你
tests.js測試：一條測試＝一個情況，加上它應該算出的答案請 AI 照規則寫
recent7.js功能：照規則寫的版本請 AI 寫
recent7-quick.js對照用：只用一句話請 AI 寫的版本請 AI 寫
tests.html測試頁不要改
README.md格式說明，主要給 AI 看；裡面的程式你看不懂沒關係不用改

接著把這六個檔放進一個新的 repo。repo 就是 GitHub 上放這個專案的地方。

路線 A請 agent 打開這個資料夾，建一個 repo 推上 GitHub，名字用 recent7，選公開。它要跑的每一條指令先看過再同意。它說電腦上沒有 gh：你先在 GitHub 網頁建一個空的 recent7（不要勾 Add a README），把網址給它。還是推不上去，就照路線 B 的做法在網頁上傳。

路線 BGitHub 右上角「＋」→ New repository。名字填 recent7，選 Public，按 Create repository。新 repo 的頁面上找 uploading an existing file 那個連結，把解壓出來的六個檔（不是整個資料夾）拖進去，等六個檔名都出現，在下面的訊息欄寫「起步檔」，再按 Commit changes。

然後打開測試頁。

路線 A在資料夾裡對 tests.html 點兩下。看到兩個都叫 tests 的檔，選圖示是瀏覽器的那一個；也可以請 agent 幫你用瀏覽器打開它。

路線 B教室電腦用線上的這一頁就好，不用開資料夾裡的那一個：打開測試頁。頁面最下面的「貼上模式」有三個格子，等一下 AI 給你的內容都貼在那裡。這個分頁先不要關。

看到這裡就對了。 瀏覽器打開一頁，最上面寫「還沒有測試」。GitHub 上的 recent7 最外層看得到六個檔。

卡住了點兩下 .js 檔跳出一個錯誤視窗

那是 Windows 想把它當程式執行，按「確定」關掉就好，檔案沒壞。要看 .js、.md 的內容：路線 A 用你的編輯器開；路線 B 到 GitHub 上點那個檔來看。

第 3 步｜先做一個對照組：一句話版

開一個新的對話，把下面這句話交給 AI。全班用同一句，等一下才比得起來。

照 README.md 的格式，幫我寫 recent7：算最近 7 天學了幾分鐘、記了幾筆。寫在 recent7-quick.js。

路線 A在起步檔的資料夾裡跟 agent 說這句話。寫好之後請它存檔（commit）並推上 GitHub，訊息寫「一句話版」。它會先列出要存哪些檔，看過再同意。

路線 B先按下面的鈕複製 README.md 的內容貼給聊天 AI，再貼上面那句話，請它給你完整的 recent7-quick.js。把它給的內容存到 GitHub：點開 recent7-quick.js → 右上鉛筆圖示 → 全選、貼上 → 按綠色的 Commit changes... → 訊息寫「一句話版」→ 再按一次 Commit changes。同一份內容也貼進測試頁「貼上模式」的第三格，按「用貼上的內容跑測試」。畫面還是寫「還沒有測試」是正常的，因為測試還沒寫。

現在先不要管它寫得對不對。這個對話可以關了。

看到這裡就對了。 GitHub 上的 recent7-quick.js 不再是「還沒做」那一行，多了一筆「一句話版」。

第 4 步｜寫你的規則（不用 AI）

打開 rules.md。先寫一句話「這個功能要做什麼」，再寫規則，一條一句。不一定要剛好五條。

路線 A用你的編輯器開 rules.md，寫完存檔。

路線 B在 GitHub 上點開 rules.md → 右上鉛筆圖示 → 直接在裡面寫。

怎麼知道寫得夠不夠清楚？拿第 1 步的五筆資料，一筆一筆問自己：這一筆算不算？答得出來，而且規則裡找得到那一句，才算寫到了。

寫的時候想想這幾種紀錄：今天的、剛好一個星期前的、日期寫到明天的、沒填分鐘的，還有一筆都沒有的時候。

再加一條你自己的規矩。 就是只有你才會這樣規定、別人猜不到的那種。例如：一筆最多算幾分鐘？一天最多算幾筆？少於幾分鐘的不算？挑一個，或自己想一個。

「不做什麼」也寫一行：這次不處理的事。

存檔一次（commit），訊息寫「規則」。

路線 A請 agent 把這次的改動存檔（commit）並推上 GitHub，訊息寫「規則」。它會先列出要存哪些檔，看過再同意。

路線 B按綠色的 Commit changes...，跳出小視窗後，訊息那一格寫「規則」，再按一次裡面的 Commit changes。

看到這裡就對了。 五筆資料每一筆算不算，你都能指著某一條規則回答。規則裡有一條是你自己的規矩。

第 5 步｜請 AI 先問你問題

再開一個新的對話，不要用第 3 步那個。這個對話只負責寫測試。

先不要請它寫。請它讀 README.md 和 rules.md，把規則裡講得不夠清楚、它得自己猜的地方，一條一條列成問題問你。

路線 A請 agent 讀資料夾裡這兩個檔。

路線 B把兩份內容都貼給它，每一份前面先打一行檔名。README.md 用下面的鈕複製。rules.md 到 GitHub 上點開它 → 鉛筆圖示 → 全選、複製，複製完按 Cancel changes 離開。

它如果一邊問，一邊就把程式寫出來了，請它先停：你還沒回答。

它問的每一題，你有三種回答：

  1. 我決定是這樣。→ 補進規則。
  2. 這次不管。→ 寫進「不做什麼」。
  3. 我沒想過。→ 想一下，再選 1 或 2。

把問答記在 rules.md 最下面，一題一行。老師試的時候，三個 AI 各問了 7 到 19 題。

不用每一題都答成規則。跟你的五筆資料無關的，多半可以寫進「不做什麼」。

再存檔一次，訊息寫「規則：補上 AI 問的」。

路線 A自己改好 rules.md、存檔，再請 agent 存檔（commit）並推上 GitHub。

路線 B回 GitHub 點開 rules.md → 鉛筆圖示 → 把規則、「不做什麼」和問答補進去 → Commit changes... → 訊息寫「規則：補上 AI 問的」→ 再按一次 Commit changes。

看到這裡就對了。 rules.md 比剛才長，「不做什麼」不是空的。

第 6 步｜請它寫測試，只寫測試

在同一個對話裡，請它照補好的規則寫測試。

路線 A先請它重新讀一次 rules.md。

路線 B先把補好的 rules.md 整份再貼給它一次。它手上那一份還是舊的。

你的話裡要講到這三件事：

  • 照 rules.md 寫 tests.js，每條規則至少一個情況，名字開頭標規則幾。
  • 只改 tests.js。功能先不要寫，recent7.js 不要動。
  • 寫完告訴我一共幾條，每條規則各幾條。

路線 A它改完之後，回測試頁重新整理。

路線 B請它給你完整的 tests.js，貼進測試頁「貼上模式」的第一格，按「用貼上的內容跑測試」。

檢查三件事：

  1. 它只動了 tests.js 嗎？
  2. 測試頁上每一列都是紅的，「實際上」那一格寫「還沒做」。哪一列寫的是「這條測試寫得不完整」，請它把那一條修好。
  3. 它說的條數，跟測試頁最上面寫的條數一樣嗎？老師試的時候，AI 說它寫了 25 條，測試頁數出來是 23 條。

全紅才對。 功能還沒寫，測試就過了，代表那一條什麼都沒檢查到，或是它偷偷把功能也寫了。

挑兩條測試，自己用手算一次「我預期」那一格對不對。測試也是 AI 寫的，也會錯。測試裡的日期寫成 2026-11-23 這個樣子，沒填分鐘寫成 null。

存檔（commit），訊息寫「測試（紅燈）」。這一筆很重要：它證明測試比功能早。

路線 A請 agent 存檔並推上 GitHub。先看它列出的檔：應該只有 tests.js。

路線 B在 GitHub 上點開 tests.js → 鉛筆圖示 → 全選、貼上它給的完整內容 → Commit changes... → 訊息寫「測試（紅燈）」→ 再按一次 Commit changes。

看到這裡就對了。 測試頁最上面寫「N 條裡有 N 條不一樣（紅燈）」。GitHub 上多了一筆「測試（紅燈）」。

卡住了功能還沒寫，卻有幾條是綠的

先看測試頁上「現在考的是」那一行，是不是 recent7.js（照規則寫的版本）。不是就按「考照規則寫的版本」。路線 B 再看第二格是不是空的；有東西就清掉，再按「用貼上的內容跑測試」。這兩樣都對，才是 AI 順手把功能也寫了：請它把 recent7.js 改回原來那個只寫「還沒做」的樣子，這一步只留 tests.js。

卡住了測試頁還是寫「還沒有測試」

它可能用了別的寫法。請它照 README.md 裡 addCase 的格式重寫。

第 7 步｜另開一個新對話，請 AI 寫功能

為什麼要換一個對話：出考卷的和寫答案的要分開。同一個對話又出題又作答，它看漏的地方會一起過關。

你的話裡要講到這三件事：

  • 只看 README.md、rules.md、tests.js。
  • 寫 recent7.js，寫到測試全部通過。只改 recent7.js。
  • 不准改 tests.js。規則和測試對不上的地方，停下來告訴我。

路線 A它改完之後，回測試頁重新整理。

路線 B把三個檔的內容貼給它，每一份前面先打一行檔名。README.md 用下面的鈕複製；rules.md、tests.js 到 GitHub 上複製，做法跟第 5 步一樣。請它給你完整的 recent7.js，貼進「貼上模式」的第二格，按「用貼上的內容跑測試」。它如果另外給你一份改過的 tests.js，不要貼。

還有紅的：把紅的那幾列（名字、我預期、實際上）原樣貼回給它，請它對照 rules.md 修。修完看全部的測試，不要只看那一條。

它說「是測試寫錯了」：先回 rules.md 看誰對。真的是測試錯，回第 6 步那個對話改測試，而且另外存檔一筆，訊息寫清楚改了哪一條。

路線 B測試改過之後，新的 tests.js 也要貼回測試頁的第一格，再按一次「用貼上的內容跑測試」。

看到這裡就對了。 測試頁最上面寫「N 條全部一樣（綠燈）」。

存檔（commit），訊息寫「功能（綠燈）」。

路線 A請 agent 存檔並推上 GitHub。

路線 B在 GitHub 上點開 recent7.js → 鉛筆圖示 → 全選、貼上 → Commit changes... → 訊息寫「功能（綠燈）」→ 再按一次 Commit changes。

然後看這一筆改了哪些檔：在 recent7 的首頁點 Commits（存檔紀錄），最新的一筆在最上面，點它的訊息。

看到這裡就對了。 這一筆只有 recent7.js 一個檔。tests.js 不在裡面。

路線 B你一次只改一個檔，這一筆本來就只有一個檔。你要確認的是另一件事：AI 有沒有另外給你一份改過的 tests.js。

卡住了最上面出現一個黃色的框「有檔案沒讀好，先看這裡」

常見原因：用了 export、import，括號沒對上，或函式的名字不是 recent7。把 recent7.js 的內容貼到「貼上模式」的第二格，按「用貼上的內容跑測試」，再看最上面那個框，詳細的錯誤訊息會出現在裡面。把那段訊息貼回給 AI。

卡住了「實際上」那格的數字有引號，像 minutes: "50"

它回傳的是文字不是數字。把那一列貼回給它。

卡住了資料夾裡多了別的檔

請它刪掉。README.md 的約定第 2 條：不新增其他檔案。

第 8 步｜讓一句話版考同一張考卷

在測試頁按「考一句話版」。

路線 B先看第三格有沒有第 3 步的一句話版。不見了就回 GitHub 點開 recent7-quick.js，把內容複製回來貼上。第一格要是你的 tests.js。

看它幾條一樣、幾條不一樣。每一條不一樣的，在紙上回答兩件事：它對到 rules.md 的哪一條規則？是它猜錯了，還是我沒講？

你自己的那條規矩，它只能用猜的，多半沒過。

其他條全部都一樣也有可能，代表這次它猜得跟你一樣。差別在這裡：照規則寫的那一版，你知道它為什麼對；一句話那一版，你是考過了才知道。

看完按「考照規則寫的版本」切回來。

看到這裡就對了。 你說得出一句話版哪幾條跟你不一樣。全部一樣的話，你知道那是它這次剛好猜中。

第 9 步｜改版一圈（有時間再做）

加一條新規則：多回報一個數字 days，這 7 天裡有幾天有紀錄。

順序一樣，每一步各存檔一筆：

  1. 規則：在 rules.md 加一條。
  2. 測試：回第 6 步那個對話，請它只加新規則的測試。新的那幾條紅，舊的還是綠。
  3. 功能：回第 7 步那個對話，請它改到全綠。

路線 B做法跟第 4、6、7 步一樣：在 GitHub 上改檔，新的內容貼進測試頁對應的格子，再按「用貼上的內容跑測試」。

看到這裡就對了。 舊的測試一條都沒變紅。改版沒有把原本對的弄壞，這是測試留下來的好處。

第 10 步｜交什麼，下課前

老師請你交東西時，交你的 recent7 的 GitHub 網址，和一張測試頁全綠的截圖。作業老師上課時會在 e學苑 開。

截圖之前，先確定測試頁考的是「照規則寫的版本」。

GitHub 上的存檔紀錄，從舊到新應該長這樣（GitHub 的頁面是最新的排在最上面）
第幾筆訊息這一筆動到的檔

3規則rules.md

基礎知識補給站

看不懂某個詞、想知道為什麼要這樣做，來這裡查。每一段後面可以連到互動概念頁，那裡的圖會動。

為什麼一句話不夠

「最近 7 天」聽起來很清楚，可是包不包含今天、明天的算不算、沒填分鐘的算不算一筆，每個人想的不一樣。你只講一句，AI 就替你挑一種。它挑的不一定是你要的；你不問，它多半也不會說。

概念頁：一句話有幾種讀法

規則要寫到多清楚

一條一句。拿一筆資料來問，答得出「算」或「不算」，而且指得出是哪一條規則說的，才算寫到了。只有你會這樣規定的事，一定要寫下來，因為別人猜不到。

概念頁：規則怎麼寫才夠清楚

為什麼讓 AI 先問

你寫規則的時候，會漏掉自己覺得理所當然的事。AI 讀完會發現它得自己猜的地方。讓它先問，你回答「我決定是這樣」「這次不管」或「我沒想過」，都比讓它安靜地自己決定好。

概念頁：讓 AI 先問

測試是什麼

一條測試，是一個情況加上它應該算出的答案。測試頁把每一條拿去問功能，再告訴你功能的回答跟你預期的一不一樣。

概念頁：考卷先出，紅燈與綠燈

為什麼先寫測試，而且要看到全紅

功能還沒寫，每一條測試都應該不過。這時候就有綠的，代表那一條什麼都沒檢查到，或是功能已經被偷偷寫了。先看到紅、再看到它變綠，你才知道變綠是因為功能寫對了。

為什麼換一個對話寫功能

同一個對話又出考卷又寫答案，它出題時想錯的地方，作答時會照樣想錯，然後測試全過。換一個對話，寫功能的那一位不知道出題的時候想了什麼，只能照你的規則和考卷做。

存檔是什麼

在 GitHub 上留一筆紀錄：什麼時候、改了哪些檔、為什麼。今天每改完一樣東西就存一筆：規則、測試、功能分開存。之後誰都點得開來看：測試是不是比功能早、寫功能的時候有沒有動到測試。

概念頁：存檔紀錄是證據

路線 A 和路線 B 差在哪裡

路線 A 用的 AI 會自己讀檔、改檔，所以你要看的是它動了哪些檔。路線 B 用的是聊天 AI，它只會回你文字，所以由你把內容貼到測試頁和 GitHub。兩條路做的是同一件事，分數一樣。

recent7 是什麼

它是一個函式：你給它一批紀錄和「今天是哪一天」，它還你一組數字，一開始是兩個：幾分鐘、幾筆。今天是哪一天要由外面給它，不讓它自己去問電腦；不然測試今天會過，明天日期一變就全紅。
