0四個帳號先登入

  1. GitHub：用 W3 建 my-panel 那個 repo 的帳號登入 github.com。另外兩個服務都可以直接用它登入。教室電腦對 GitHub 來說每次都是新電腦，登入時可能多問一關：開了兩步驟驗證的，用手機上的驗證 App 或簡訊；沒開的，GitHub 會寄一組驗證碼到你註冊 GitHub 用的信箱。手機要帶著，先確定收得到那個信箱的信。
  2. Supabase：開 Supabase 的註冊頁，按 Continue with GitHub，用同一個 GitHub 帳號授權。不用填信用卡。
  3. Cloudflare：開 Cloudflare 的註冊頁。按 GitHub 可以直接用同一個帳號（第一次會幫你建好帳號）；用 Email＋密碼也行，記得去信箱按驗證信。先看到「正在執行安全驗證」是 Cloudflare 在擋機器人，等幾秒它會自己跳過去。
  4. AI：路線 A用自己筆電上的 agent：Codex（在 ChatGPT 桌面版裡，免費帳號也有，額度有限）、Claude（Claude Code 要付費方案，而且要滿 18 歲），或 W10 用過的 agent（例如 Antigravity）。路線 B瀏覽器裡任何一個聊天 AI 都可以。這門課不需要你付錢。

看到這裡就對了。 瀏覽器有三個分頁：GitHub、Supabase、Cloudflare，三個都登入了（Supabase 停在「建立組織」的畫面也算，第 1 步接著做）。路線 A 的 agent 已經開好；路線 B 開好一個聊天 AI 的分頁。

1先開 Supabase 專案（它要等一下才好）

資料庫有時要等一下才開好，所以第一件事先開它；還在準備就先做第 2 步。

  1. 第一次進來，Supabase 會先請你建一個組織（organization）：名字隨意，例如你的名字；方案選 Free，不用填信用卡。
  2. 按 New project，填這幾格：
    • GitHub (optional) 那一列的 Connect GitHub：不用按。
    • Project name：learning-log
    • Database password：按 Generate a password，存進你自己的手機備忘錄或密碼管理器，不要留在教室電腦上。今天用不到；忘了可以在 Supabase 重設。
    • Region：下拉選 Asia-Pacific（亞太，不用選城市）。
    • Security：前兩格照預設打勾；第三格 Enable automatic RLS 也勾起來。多一層保險：就算 AI 忘了開門禁，新建的表也會自動開。

看到這裡就對了。 專案首頁出現：最上面是 learning-log 和一行 https://一串字.supabase.co，STATUS 寫 Healthy（老師實測不到十秒）；左邊一排選單有 Table Editor、SQL Editor、Authentication。還在準備就先做第 2 步，回來它就好了。

2讓 AI 做出網站

路線 A給 agent 一張需求卡

  1. 在自己的電腦建一個空資料夾，取名 learning-log，用你的 agent 開它。ChatGPT 桌面版的 Codex：新專案 → 選這個資料夾 → 建立專案；問要不要信任這個資料夾就按信任。權限維持「要求核准」，它要跑的每一條指令你都會先看到。Antigravity：File → Create Project → Add Folder → 選這個資料夾 → Next（有的版本最後一顆叫 Create）。
  2. 把下面這張需求卡整段貼給它。你可以改成自己的話，但「規則」那幾條要留著，後面的步驟靠它們接得上。
我要做一個「我的學習紀錄」網站，請在這個資料夾裡做。

要做到：
1. 用 Email＋密碼註冊、登入、登出，用 Supabase 的登入功能。
2. 登入後可以新增一筆紀錄：日期、今天學了什麼、花了幾分鐘、卡在哪裡（可不填）。
3. 看得到自己全部的紀錄，新的在上面；可以刪掉自己的紀錄。
4. 每個人只看得到自己的紀錄。這件事要靠資料庫的門禁（RLS）做到，不能只靠網頁藏起來。

規則：
- 只用 HTML、CSS、JavaScript，不要用需要安裝或建置的工具（不要 npm、React、Vite）。supabase-js 第 2 版從 CDN 載入。
- 檔案放在這個資料夾最外層：index.html、style.css、app.js、config.js、schema.sql、README.md。
- config.js 只放兩個值：Supabase 的 Project URL 和 publishable key，先用「貼上…」當佔位字。絕對不要用 secret key 或 service_role key。
- schema.sql 要能在 Supabase 的 SQL Editor 直接執行：建一張 learning_logs 表、打開 RLS、把這張表的讀寫權限給登入的人（authenticated）、寫好「只有本人能讀寫自己的資料」的規則。
- 介面用繁體中文，手機也好用；使用者打的字一律當純文字顯示。

先列計畫給我看，我同意再動手。做完告訴我每個檔案在做什麼，還有我接下來要在 Supabase 按哪些地方。
  1. 先看計畫再同意（W3 的規矩）：計畫裡要有那六個檔、要提到 RLS。少了就叫它補，補好再說「同意」。
  2. 做完之後，自己對這四件事。用記事本開檔（對檔案按右鍵 → 開啟檔案 → 記事本；不要點兩下 .js，Windows 會把它當程式執行），按 Ctrl+F 找字；找不到在哪一行，可以請 agent 指給你看。一件不對就退回它一次，說清楚哪裡不對：
  • 打開 schema.sql，找得到 enable row level security，也找得到 grant…to authenticated。
  • 同一份檔裡的每條規則（policy）都拿 auth.uid() 去比對 user_id。
  • config.js 只有兩個值，裡面沒有 secret、service_role 這些字。
  • 在 app.js 搜尋 innerHTML：如果拿來放使用者打的字，請它改成 textContent（不然有人在紀錄裡打程式碼，會被當成程式執行）。

看到這裡就對了。 資料夾最外層有 index.html、style.css、app.js、config.js、schema.sql、README.md 六個檔，四件事都對。

3在 Supabase 建資料表、拿鑰匙、關確認信

3-1 建資料表和門禁

  1. 回到 Supabase 分頁，左側選 SQL Editor。第一次進來會跳「Snippets no longer save automatically」的提示，按 Understood。點一下編輯區的第一行。
  2. 把 schema.sql 整份複製、貼進去，按右上的 Run。路線 B直接按下面的「複製 schema.sql」；路線 A用記事本打開 agent 做的那份，Ctrl+A 全選、Ctrl+C 複製。
  3. 跳出「Potential issue detected」說有破壞性的動作，是正常的：schema.sql 會先清掉這張表的舊規則。新專案裡沒有任何東西會被弄壞，按 Run query。
  4. 左側選 Table Editor，點 learning_logs。（離開 SQL Editor 時瀏覽器問要不要離開，選離開；查詢已經跑過了。）
看起步檔 schema.sql 全文
-- 我的學習紀錄：資料表＋門禁（RLS）
-- 用法：Supabase 左側 SQL Editor → 貼上整份 → Run。重跑也不會壞（已經有就略過、規則會重建）。

-- 1. 資料表：一列＝一筆學習紀錄，user_id 記這筆是誰的（自動填登入者，不用自己給）
create table if not exists public.learning_logs (
  id         uuid primary key default gen_random_uuid(),
  user_id    uuid not null default auth.uid() references auth.users (id) on delete cascade,
  log_date   date not null default current_date,
  topic      text not null check (char_length(topic) between 1 and 200),
  minutes    integer check (minutes between 0 and 1440),
  note       text check (char_length(note) <= 1000),
  created_at timestamptz not null default now()
);

-- 2. 打開門禁：開了之後，沒有規則允許的事一律不准
alter table public.learning_logs enable row level security;

-- 3. 先清掉這張表所有舊規則（包括別的版本留下、名字不一樣的）。
--    同一個動作只要有一條規則放行就會放行，舊的太寬規則不清掉，新規則再對也擋不住。
do $$
declare p record;
begin
  for p in select policyname from pg_policies
           where schemaname = 'public' and tablename = 'learning_logs' loop
    execute format('drop policy %I on public.learning_logs', p.policyname);
  end loop;
end $$;

-- 4. 四條規則：登入的人只能看、寫、改、刪「user_id 是自己」的那幾列
create policy "本人可以看自己的紀錄" on public.learning_logs
  for select to authenticated
  using ((select auth.uid()) = user_id);

create policy "本人只能新增自己的紀錄" on public.learning_logs
  for insert to authenticated
  with check ((select auth.uid()) = user_id);

create policy "本人只能修改自己的紀錄" on public.learning_logs
  for update to authenticated
  using ((select auth.uid()) = user_id)
  with check ((select auth.uid()) = user_id);

create policy "本人只能刪自己的紀錄" on public.learning_logs
  for delete to authenticated
  using ((select auth.uid()) = user_id);

-- 5. 誰能碰這張表：只有登入的人（authenticated）；沒登入的（anon）什麼都不給
grant select, insert, update, delete on table public.learning_logs to authenticated;
revoke all on table public.learning_logs from anon;

先看資料表再往下走。 SQL Editor 下方顯示 Success. No rows returned；Table Editor 看得到 learning_logs 和它的欄位（topic、minutes…），表格上方有一顆「RLS policies」按鈕，前面的數字不是 0（起步檔是 4 條；AI 做的版本可能 1 到 4 條）。

3-2 拿兩個可以公開的值

回專案首頁（左上角點 learning-log）。最上面那行網址旁有一顆 Copy，按下去會列出：

  • Project URL：點它就複製好了，長得像 https://一串字.supabase.co。
  • Publishable key：再按一次 Copy、點它，sb_publishable_ 開頭的那一把。

這個選單裡沒有 secret key，最不容易拿錯。找不到這顆 Copy，也可以到左下角齒輪 Project Settings：Project URL 在 Data API 頁、鑰匙在 API Keys 頁。

  • 路線 A跟 agent 說：「把 config.js 的兩個值換成：Project URL 是 ___，publishable key 是 ___」。或自己打開 config.js 貼，引號留著。
  • 路線 B先貼在記事本，第 4 步在 GitHub 網頁上貼進去。

🚨 只拿 publishable key。 同一頁還有一把 secret key（sb_secret_ 開頭），那是資料庫的萬能鑰匙：誰拿到都能讀改所有人的資料。它不能進 config.js、不能進 GitHub、不能貼給 AI。起步檔偵測到它會停止連線並提醒你。

3-3 練習時關掉確認信

  1. 左側選 Authentication → Sign In / Providers。
  2. 頁面上方「User Signups」那一區的最後一個開關 Confirm email，按一下關掉（不用點下面的 Email）。右下角如果有小視窗擋住，先按它的叉叉關掉。
  3. 按 Save changes。

看到這裡就對了。 右上角跳出 Successfully updated settings，Confirm email 的開關是灰的（關著）。

為什麼要關：Supabase 內建的寄信只寄給專案成員（也就是你自己），而且一小時只寄 2 封；全班一起測註冊，一定卡住。關掉之後，註冊完直接登入。真的要給大家用的網站，要換成自己的寄信服務，再把它打開。

路線 A3-4 先在自己電腦試一次（路線 B 跳過，直接做第 4 步）

跟 agent 說：「開一個本機預覽，給我網址」。它會給你一個像 http://localhost:8000 的網址，點開它。用你的 Email 和一組練習用的密碼註冊（不要沿用學校信箱、GitHub 或其他帳號的密碼；瀏覽器問要不要儲存，選不要），存一筆紀錄，再回 Supabase 的 Table Editor 看 learning_logs。

看到這裡就對了。 網頁清單出現那一筆；Table Editor 也多了一列，user_id 欄有一串編號。

5Cloudflare：接上 GitHub、拿到網址

  1. 直接開 Cloudflare 的建立頁（或左側 Compute → Workers & Pages → 建立）。畫面標題是「Create an app」。
  2. 按 Connect GitHub。第一次會跳到 GitHub：授權 Cloudflare Workers and Pages，安裝時選 Only select repositories，只勾 learning-log。
  3. 回到 Cloudflare 的「Select a repository」：搜尋 learning-log、點它，按 Next。
  4. 「Set up your application」照預設：Project name 自動是 learning-log、Build command 留空、Deploy command 是 npx wrangler deploy。按 Deploy。新帳號如果跳出要你幫 workers.dev 取一個子網域名字，用預設的或打你的英文名。
  5. 等建置跑完，大約一分鐘（Initializing → Cloning → Installing → Deploying），出現綠勾就好了。
  6. 按上方的 Overview：最上面那行就是你的網址；或按右上角藍色的 Visit。

看到這裡就對了。 網址長得像 learning-log.你的帳號代號.workers.dev，打開是「我的學習紀錄」的登入畫面。剛建好的第一分鐘可能出現錯誤頁，等一下再重新整理。

有時候 Cloudflare 還會在你的 GitHub 開一個 pull request（PR），想幫你加 wrangler.jsonc、.gitignore、.assetsignore 三個設定檔。有的話先看 Files changed（W5 看紅綠修改對照的規矩），再按 Merge pull request → Confirm merge；沒有也沒關係，老師 11/13 實測就沒出現，第一次建置直接上線。路線 A合併過 PR 的人，GitHub 上會比你電腦多幾個檔：下次推之前叫 agent 先拉下來（pull）。

建置失敗（紅色），紀錄裡寫 Missing entry-point？

先別一直按 Deploy。在 GitHub 的 learning-log 按 Add file → Create new file，檔名打 wrangler.jsonc，貼上下面這段（name 要跟 Cloudflare 上這個專案的名字一字不差），按兩次 Commit changes。再用同樣方法建一個 .assetsignore，內容兩行：.git 和 node_modules（不讓這兩個資料夾被放上網）。Cloudflare 會自己再建置一次。還是不行就請老師來看。

  "name": "learning-log",
  "compatibility_date": "2026-11-10",

6兩個帳號驗收：彼此看不到，才算門禁有開

這一步是今天的重點。網頁「看起來」只顯示自己的，不代表資料庫真的有擋；要用兩個帳號互相試才知道。

  1. 電腦：打開你的 Cloudflare 網址。路線 B用你的 Email 和一組練習用密碼註冊（不要沿用其他帳號的密碼），存一筆紀錄；路線 A第 3-4 步已經註冊過，直接登入（會看到剛才試存的那一筆）。
  2. 手機（或電腦按 Ctrl+Shift+N 開無痕視窗，網址直接貼過去，比在手機上打字快）：打開同一個網址，用你的另一個 Email 註冊（例如學校信箱），也存一筆。測試用的假信箱（像 test@example.com）會被 Supabase 拒絕。
  3. 兩邊都重新整理一次。

這樣才算過。 電腦只看得到電腦存的那一筆，手機只看得到手機存的那一筆。Supabase 的 Table Editor 兩筆都看得到是正常的：後台是管理者的畫面。

兩個帳號互測驗的是「看」。「新增、修改、刪除」也只准本人，靠的是第 2 步四件事的第二件：每條規則都拿 auth.uid() 比對 user_id。

如果看得到對方的紀錄：門禁沒開好，先別再存東西。最快的修法：到 SQL Editor 把起步檔的 schema.sql 整份跑一次（第 3-1 步那顆複製鈕）。它會先清掉這張表所有舊規則（包括 AI 留下、名字不一樣的），再建四條只認本人的規則；表裡的欄位和紀錄不會動（前提是你的表有 user_id 這一欄）。只叫 agent 再加一條對的規則不夠：同一個動作只要有一條規則放行，就會放行。修完一定再用兩個帳號驗一次。這就是 W3 說的「抓出 AI 講得很有把握的那個錯」。

7改版一圈：說一句話，網站自己換新

目標一樣：在紀錄清單上方加一行「最近 7 天：共幾分鐘、幾筆」。推上 GitHub 之後，不用再按任何部署鈕，Cloudflare 會自己換新版。

路線 A交給 agent

先把 GitHub 上的最新版拉下來（pull），免得跟網頁上的改動打架。
然後在紀錄清單上方加一行小統計：最近 7 天（今天和前 6 天，照日期欄算；沒填分鐘的算 0）總共學了幾分鐘、記了幾筆。
只改 index.html 和 app.js，不要動 config.js 和 schema.sql。
先列計畫；改完先給我看改了哪幾行，我說可以，再 commit 並 push 到 GitHub。

路線 B瀏覽器問 AI，自己貼回 GitHub

  1. 把 GitHub 上的 app.js 和 index.html 整份貼給聊天 AI，跟它說：「在紀錄清單上方加一行小統計：最近 7 天（今天和前 6 天，照日期欄算；沒填分鐘的算 0）總共學了幾分鐘、記了幾筆。請直接給我改好之後完整的 index.html 和完整的 app.js。」
  2. 在 GitHub 網頁上點開這兩個檔 → 鉛筆編輯 → Ctrl+A 全選、貼上 AI 給的完整新版 → Commit changes... → 小視窗裡再按一次 Commit changes。兩個檔各做一次。只貼片段、自己找位置插進去，很容易少一個括號整頁壞掉。

推上去之後，到 Cloudflare 這個專案的 Deployments，看最新那一次從建置中變成成功（GitHub 的 commit 旁邊也會從黃點變綠勾），再用手機重新整理。

做到這裡就完成。 一個網址；兩個帳號互相看不到對方的紀錄；改版推上去之後，手機重新整理看得到「最近 7 天」那一行。
