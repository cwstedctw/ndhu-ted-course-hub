從建檔到 commit

用滑鼠走一遍：一個檔案怎麼從「剛建好」，一步步變成「存進版本歷史」。 這一頁是模擬的，沒有真的程式在跑，按錯也不會弄壞任何東西。 你不用背指令，只要看得懂每一步發生了什麼。

工作區 working directory

你的桌面。檔案在這裡被建立、被修改，就是你平常在資料夾裡看到的那些檔。

暫存區 staging area

出貨前的紙箱。你決定「這一版要收哪些內容」，先放進來排好，還沒封箱。

版本庫 repository，簡稱 repo

檔案櫃。每 commit 一次就多一格抽屜，裡面是那一刻的完整快照，附時間和說明。

一張表記住

      
一個檔案在 Git 眼裡只有四種狀態

      
剛才那趟旅程，其實就是在這四格之間移動。看到 Git 回報哪個字，就知道自己在哪一格、下一步該做什麼。

      

      

        
狀態你剛做了什麼Git 的意思是下一步通常是

        
          
未追蹤untracked新建了一個檔「有個新檔案，我還沒開始管它」放進暫存區（add）

          
已修改modified改了一個已經有版本的檔「這個檔跟最新一版長得不一樣」先看差異（diff），確認沒改錯，再 add

          
已暫存staged按了 add「下一版會收這些內容」存成版本（commit）

          
乾淨clean / committed按了 commit「桌面跟最新一版一模一樣，沒事」繼續工作；要備份到 GitHub 就 push

        
      

      

    

  


  

    

      
最常搞混的五件事

      
這些不是同一件事

      
    
        
  • 存檔（Ctrl+S）＝ commit？不是。
    存檔只是把內容寫進硬碟。Git 要等你 commit，才會替這一刻留下一版。
    • 
        
  • add ＝ 上傳？不是。
    add 只是把內容放進紙箱，什麼都還沒送出去，連版本都還沒建立。
    • 
        
  • commit ＝ 上傳到 GitHub？也不是。
    commit 存在你這台電腦的版本庫裡。要送到 GitHub，還要再做一步 push。這一頁沒講 push，因為它是另一趟旅程。
    • 
        
  • 之後改了檔，舊版就沒了？不會。
    每一個 commit 都留著。你隨時可以翻回去看任何一版長什麼樣，這正是版本控制的價值。
    • 
        
  • add 之後再改檔，commit 會收最新的？不會。
    紙箱裡裝的是你按 add 那一刻的內容。之後的修改要再 add 一次才會進去。練習台最後有個小實驗可以親眼看。
