和 AI 一起寫程式　WEEK 3

你上週那頁，
今天有一個網址

上週你做的那頁，現在只活在你的電腦裡。今天下課前，它會有一個網址——你家人用手機也打得開。

做完這三件就夠了：建一個公開的櫃子、把面板放進去、打開網址。其餘是往前，不是門檻。

1　今天交什麼

不交紙、不交檔案。下課前在 e學苑 本週作業的文字框貼兩行：

網站：https://你的帳號名.github.io/my-panel/
倉庫：https://github.com/你的帳號名/my-panel

網站那一行一定要用複製的，不要用手打。從 GitHub 的 Settings → Pages 把它整行複製起來。名字被用過的人，repo 會叫 my-panel-2 之類的，手打一定打錯。

Pages 還沒亮的人：先貼倉庫那一行，後面寫一句「Pages 還在等」，亮了再回來補。貼完自己點一次，確認打得開。

2　先進得去 GitHub

打開 github.com，登得進去的做 A，登不進去的做 B。兩邊都是今天的正課，不是補救。

A・已經有帳號

先去練習台把概念跑一次，10 分鐘：從建檔到 commit。照畫面走完一個檔案的四種狀態，走完做頁尾那組小測驗。做完了就去幫旁邊還在辦帳號的同學。

B・還沒有帳號（這就是上週那份作業）

  1. 開 github.com/signup，Email 填你的東華信箱（@gms.ndhu.edu.tw）。
  2. 這一步錯了後面全錯：Student Pack 要靠學校信箱驗你是學生。用個人信箱辦的人之後領不到 Pack，還得回頭補加信箱再驗一次。
  3. 設密碼，取一個 Username。這個名字會出現在你的網址裡，用英文名或英文名加數字就好，取一個三年後不尷尬的。
  4. 過一題驗證題 → 去東華信箱收信 → 把信裡的 8 位數字填回網頁 → 後面的問卷按 Skip。
  5. 辦好了順手把 Username 填進 e學苑 上週那份作業的文字格，一起交掉。

兩步驟驗證（2FA）今天不做。它要手機驗證器 App、還要存復原碼，今天的時間跑不完，而且在教室公用電腦上做，復原碼會留在那台機器上。回宿舍再做，步驟在上週那份作業的指南裡。

卡住怎麼辦：驗證信沒來→看垃圾信匣、等兩分鐘再按重寄。Username 被用過→後面加數字。真的辦不成→跟旁邊同學共用他的帳號做完今天全部步驟，在交件那行註明「與某某共用」，同分。

3　建一個公開的櫃子

  1. 開 github.com/new?name=my-panel&visibility=public。名稱沒自動填就打 my-panel，確認選的是 Public。
  2. 勾 Add a README file，按 Create repository。
  3. 準備你的 index.html：有上週面板單檔的，把檔名改成 index.html（全小寫）；沒有的用 範例那份，同分。
  4. 起步包是 ZIP 的人：先在下載夾按右鍵「全部解壓縮」再用。在壓縮檔裡直接雙擊，改了會存到暫存資料夾，關掉就不見。
  5. 回 repo 首頁 → Add file → Upload files → 把 index.html 拖進去。拖不進去的人按框裡的 choose your files。只放那一個檔、放在最外層，不要多包一層資料夾。
  6. 下面 Commit message 欄寫一句這次做了什麼，例如「放進我的喝水面板」，按 Commit changes。

這個 repo 任何人都看得到。不放學號、電話、地址，任何地方都不放密碼。作業跟報告交 e學苑，不放這裡。

4　打開你的網址

  1. repo 上方 Settings（看不到就按分頁列最右邊的「…」）。
  2. 左邊選 Pages。
  3. Source 選 Deploy from a branch；Branch 選 main、資料夾 / (root)，按 Save。
  4. 等一兩分鐘，重新整理這一頁，上面會出現「Your site is live at …」。
  5. 拿手機打開那個網址。
  6. 給隔壁同學掃一次——別人的手機也打得開，才算數。
看到什麼先查這三件
404①檔名是小寫 index.html 嗎 ②它在最外層嗎 ③來源是 main ＋ /(root) 嗎
畫面只有一行 my-panel那是 README 的內容——代表它找不到你的 index.html，查同樣三件
還是沒亮先往下做第 5 節，回頭再重新整理。它有時候要久一點

免費帳號的 GitHub Pages 要用公開 repo。設成私有的話網址開不出來。

5　改一行，看紅綠

  1. repo 裡點開 index.html，按右上角的鉛筆。
  2. 改一句——把名字改成自己的，或換一句文字。
  3. 按 Commit changes…（字尾有三個點）→ 跳出來的框裡寫「改成我的名字」→ 再按 Commit changes。
  4. 回檔案頁，按最近一次留版那一列右邊的時鐘圖示（旁邊有數字，那就是 History），點最上面那一筆。
  5. 畫面會分兩色：紅色、前面有 − 的是拿掉的；綠色、前面有 + 的是加上的。
  6. 重新整理你的網址，確認線上真的變了。

每一次留版都要寫一句改了什麼。這句話不是寫給老師看的，是寫給三個月後的你——那時候你完全不記得今天做了什麼。

6　先弄壞它，才敢動它

今天的重頭戲。全班只弄壞同一個地方，不要各弄各的。

  1. 點開 index.html，按鉛筆。
  2. 把 <script> 那一行整行刪掉。刪這一行一定看得到後果；刪別的地方（像 </body>）瀏覽器會自己補起來，畫面常常一點事都沒有。
  3. 按 Commit changes…，訊息寫「故意弄壞：刪掉 script，預期按鈕會沒反應」，再按 Commit changes。
  4. 重新整理你的網址——按鈕按下去沒反應了。
  5. 回頭看你剛剛寫的那句訊息：預期跟實際一樣嗎？

救回來（四步）

  1. 按 History（最近一次留版那列右邊的時鐘圖示）。
  2. 找到弄壞之前那一筆，按那一列右邊的 <>（View code at this point）——這就是那一版的 index.html。
  3. 右上角按 Raw 旁邊的複製圖示（Copy raw file），或按 Raw 之後全選複製。這個舊版畫面上的鉛筆按不動，那是正常的——舊版不能直接編輯，只能複製走。
  4. 按左上角 repo 名稱回到首頁（main）→ 打開現在的 index.html → 鉛筆 → 全選、貼上 → Commit changes…，訊息寫「救回來：把 script 補回去」。

重新整理網址，確認按鈕又會動了。

救回來的方法不是「把剛剛那次刪掉」，是「再加一筆，把它改回去」。壞掉那一筆跟救回來那一筆都還留在歷史裡——這就是為什麼它安全。

這一節的做法照抄自共用教材 P7〈我的第一個 repo〉第 5 節（background-knowledge/P7-我的第一個repo/）。各科同一份，本週不另寫版本。

7　出錯了，先做這四步

  1. 複製原文整段——紅字、錯誤訊息，整段複製，不要用打的、不要只講「它壞了」。
  2. 貼給 AI，先請它解釋：「這段訊息是什麼意思？」先看懂，再談怎麼改。
  3. 看它給的計畫，不要照單全收：它說要改哪裡？那個地方是你想改的嗎？
  4. 自己驗一次：照它說的做完，重新整理，真的好了嗎？

沒有紅字的那種（按了沒反應、畫面沒變、燈不亮）：第一步的「原文」改寫成三句——我做了什麼／我預期看到什麼／實際看到什麼。

貼之前把名字、學號、信箱、任何一串登入用的亂碼遮掉。還有：教室電腦重開機會還原，東西要帶走。

四步照抄自共用教材 P9〈電腦出錯了，先做這四步〉（background-knowledge/P9-電腦出錯先做的四步.md）。從這週起，每一門課都這樣做。
