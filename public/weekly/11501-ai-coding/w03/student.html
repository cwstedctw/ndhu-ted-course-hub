稍微長一點的三件事

一、Git 三個動作，今天只用這三個

Git 是一套替一個資料夾記歷史的工具。不是整台電腦、也不是雲端硬碟自動備份——你指定哪個資料夾，它就只管那個資料夾。今天全部動作都發生在 my-panel 裡面，所以卡 1 的第一句話才是「只看、不動，告訴我你站在哪」。

  1. commit（存一版）：把資料夾現在的樣子拍一張快照，附一句「我為什麼改」。這是本機動作——做完你的電腦裡多一筆歷史，網路上還沒有。
  2. push（推上去）：把本機累積的快照送到 GitHub。commit 不等於 push。「我存了」跟「網路上有了」是兩件事，很多人半夜就卡在這裡：自己看得到、同學打開卻是舊的。
  3. 回去：分兩種。還沒 commit 的錯，用 restore 一秒拉回上一版；已經 push 出去的錯，不能抹掉，只能再加一筆改回去（revert）。原本那筆錯的留在歷史裡。

為什麼全程禁止 reset、rebase、force push：這三個會改寫歷史。在「兩個人一起改一份東西」的場合，改寫歷史等於把別人手上的版本弄丟。AI 提議用它們的時候，回一句「不要」——這是今天最容易做到的一次 A4。

二、Antigravity 畫面上四個位置，跟那道閘

這四個位置你要指得出來，比記得住名字有用。按鈕名稱以現場為準，跟這裡寫的對不上很正常（它改版很快）——對不上就看它旁邊的說明，或直接問它「這顆是什麼」。

要練的在畫面的哪裡你要做的動作
A1 看得懂它打算做什麼Implementation Plan（實作計畫）那一份讀完再按 Proceed。讀不懂就別按
A2 看得懂它做了什麼程式碼 diff 與 Walkthrough（做完的變更摘要與怎麼驗）對照 diff 跟計畫：它做的跟它說要做的一樣嗎
A3 破壞性動作先問Permissions：Deny ＞ Ask ＞ Allow 三層，動作分七種（讀檔／寫檔／讀網頁／操作網頁／終端機指令／離開沙箱執行／外掛工具）確認自己在 Request Review；把 sudo 這種丟進 Deny
A4 拒絕得了越界計畫上可以留意見，標頭有一顆 Review 按鈕——不按 Proceed，改把意見送回去今天至少做一次：留一句具體的理由、按 Review 退回、看它改了什麼

那道閘：Terminal Command Auto Execution。它有三種模式——Request Review（每條指令先問你）、Proceed in Sandbox（在沙箱裡自動跑，要離開沙箱才問）、Always Proceed（不問）。今天全班要在 Request Review。切到 Always Proceed 之後，它做什麼你都看不到，A1 跟 A3 這兩件就再也練不到了，而且畫面上看不出來。開場時打開設定，跟旁邊的人互相看一眼。

還有一條它自己畫的線：它預設只能碰你開的那個專案資料夾，碰不到你電腦上別的地方。這不是我們加的限制，是工具設計者也知道「agent 亂跑到專案外面」是主要風險。看得懂這條線為什麼存在，比背四個名詞有用。

三、gh 是什麼，為什麼 AI 需要它

GitHub 是一個網站，你平常用滑鼠在上面點。gh（GitHub CLI，command line interface，命令列介面）是同一套功能的打字版：在終端機打一行字，等於在網站上點好幾下。

關鍵在這裡：AI agent 沒有手，也沒有滑鼠，它會的是打字。所以你叫它「幫我建一個公開 repo」「幫我開網址」，它靠的就是 gh。沒裝 gh，它只能教你怎麼點，不能替你點——這就是卡 2 要先裝它的原因，也是今天跟前幾週最大的差別。

而 gh 要先知道「你是誰」才動得了你的帳號，這就是卡 2½ 的 gh auth login：把一把代表你的鑰匙放進這台電腦。鑰匙不經過 AI——它不需要知道你的密碼，也不該知道。之後它下 git push，用的是這把鑰匙。

這一節的事實來源：共用教材 P1〈GitHub 共用基礎版〉、P2〈AI Agent 共用基礎版〉與 W2 作業指南。本頁不寫版本號、不拿介面截圖當唯一依據——它們改版很快。

  2. 貼給 AI，前面加一句情況。例如：「我在做 ___ 的時候出現這段，請先解釋這是什麼意思，再說你會怎麼查。」——先解釋，不是先修。

  4. 自己驗一次結果，記下四格。原文寫了什麼／它說是什麼／我做了什麼／結果如何。沒解掉也記——下一次問的時候，這四格就是你的問題描述。
