第二部分 14:45–15:25WiFi 真板（第 10 課）

2-1 連 ESP32 的基地台（不用 sudo）

ESP32OLED 有 maker-XXXX、pw makerXXXX（WiFi 模式）；板子先掃再連，兩個 XXXX 都換掉

nmcli device wifi list
nmcli device wifi connect maker-XXXX password makerXXXX

成功印 Device 'wlan0' successfully activated with '…'.。視窗 B 不會斷（走 USB）。連上之後板子沒有外網。說沒有權限 → 舉手。

2-2 跑 60 秒、抄統計

板子手握 DHT11、轉旋鈕、遮光；60 秒自己停 → 抄中位數、最快、最慢、95%

python3 brain.py --link wifi --esp 192.168.4.1 --seconds 60

感測值約每 2 秒更新一次，連續幾行一樣正常。手機別同時開 ESP32 網頁（會搶連線；要開就加 --period 2）。遮光數字反了 → rules.py 的 DARK_WHEN_LOW 改 False。

2-3 斷線長什麼樣子

板子跑起來後拔 ESP32 電 10 秒再插回，看完 Ctrl＋C

python3 brain.py --link wifi --esp 192.168.4.1

每輪 ESP32 沒回應（第 N 次）；ESP32 重開後 UNO Q 會自己連回去，第一輪燈號全部重送。還連著嗎：

nmcli -t dev status

換一塊 ESP32（輪流）

板子交出去：先 Ctrl＋C，再讓 UNO Q 忘掉這塊；接過來：XXXX 換成新那塊的 OLED，WiFi 掃、連，藍牙直接用名字

nmcli connection delete maker-XXXX
nmcli device wifi list
nmcli device wifi connect maker-XXXX password makerXXXX
python3 brain.py --link ble --name maker-XXXX

大腦第一行的 UNO Q 現在連的 WiFi 是 … 要跟 OLED 一樣。

🆘 三個最常見的卡關

① SSH 斷線：用了 WiFi 的位址。改 ssh arduino@192.168.7.2；說鑰匙變了 → 教室機 ssh-keygen -R 192.168.7.2。

② ESP32 沒回應／連不上 ESP32：…：ESP32 剛重開就等它，UNO Q 會自己連回；說沒連任何 WiFi → 照下一行打 nmcli device wifi connect；WiFi 名字跟 OLED 不一樣 → nmcli connection delete 那個名字。燈顏色怪：blue 是綠燈。

③ 藍牙 掃不到 maker-XXXX／No module named 'bleak'：OLED 要 BLE（按住 A 再按 EN）→ 名字 → 請上一位 Ctrl＋C（走了就重開 ESP32）；要在 w12-starter 裡跑，不行就重新解壓。
