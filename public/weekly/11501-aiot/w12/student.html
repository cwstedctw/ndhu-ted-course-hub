第二部分　14:45–15:25（40 分）WiFi 真板：UNO Q 連上 ESP32 的基地台

2　WiFi 真板（第 10 課 d10_wifi_web.py）

目標：UNO Q 連上 maker-XXXX，大腦讀真的溫度、光線、旋鈕，跑滿 60 秒拿到延遲統計。產出：log_wifi_*.csv＋統計那一行。

ESP32 現在自己當一台基地台（WiFi 名稱 maker-XXXX、密碼 makerXXXX、網址 http://192.168.4.1），不用校網、不用路由器。大腦每秒用網頁問答的規矩（HTTP）問一次 /api/status，板子回一段大括號的資料（JSON）；要開燈就再問一個網址，例如 /api/led?name=red&on=1。連上 ESP32 之後板子就沒有外網——起始檔你在第 0 部分已經抓好了。

  1. 做什麼確認 ESP32 是 WiFi 模式：OLED 上有 maker-XXXX、pw makerXXXX、192.168.4.1。不是的話，不要按任何鍵，按一下 ESP32 的重開鍵（EN／RST）或重新插電。多久：幾秒

    打什麼不用打，看 OLED。

    應該看到那三行字。ESP32 讀溫溼度（DHT11）每 2 秒才讀一次、一次只處理一個連線——所以一塊 ESP32 只給你們這組連。

  2. 做什麼讓 UNO Q 去連 ESP32 的基地台（視窗 B，不用 sudo）。先掃一次、再連（W6 踩過的雷：掃描結果太舊會連不上）。兩個 XXXX 都換成你紙上那四個字（名字 maker-XXXX、密碼 makerXXXX）。多久：幾秒；⚠️ 十組同時開沒測過

    nmcli device wifi list
nmcli device wifi connect maker-XXXX password makerXXXX
    Device 'wlan0' successfully activated with '…'.

    應該看到第一行列出附近的 WiFi，裡面有你的 maker-XXXX（也會看到別組的，別連錯）；第二行成功印上面那句。UNO Q 拿到 192.168.4.2，ESP32 是 192.168.4.1。視窗 B 不會斷——因為你是走 USB 的 192.168.7.2 進來的；這也是為什麼今天不准用 WiFi 的位址連板子。⚠️ 老師是用 USB 除錯線（adb）進板子跑的，用 SSH 進來會不會說沒有權限還沒試過；說沒有權限就舉手。

  3. 做什麼跑大腦，跑滿 60 秒自己停（視窗 B；--seconds 60＝60 秒後自動停）。跑的時候：① 手握住 DHT11（溫溼度那顆）讓溫度往上爬；② 轉旋鈕看 門檻 跟著變；③ 用手遮住光線感測器，看 光線 數字往哪邊走。多久：60 秒

    python3 brain.py --link wifi --esp 192.168.4.1 --seconds 60
    連線中…

4　改大腦（rules.py）、收尾、交作業

目標：三題挑一題，只改 rules.py，用假板子或真板試給自己看。產出：改了什麼＋為什麼。

rules.py 的 decide() 只管「想」、不管「怎麼傳」，所以同一份規則 WiFi、藍牙兩條線都能用。拿不到的值是 None（藍牙線的光線、旋鈕），規則要自己處理。brain.py 每次開跑才讀一次 rules.py：改完要 Ctrl＋C、重跑大腦才會生效。

題目一：濕度高 → 黃燈亮

目標：濕度超過你定的數字，黃燈亮；降回來就關。
提示：黃燈已經接好了——decide() 回傳的大括號裡有一行 "yellow": False（現在永遠不亮），brain.py 和兩條線都認得它。把 False 換成「這一輪的濕度 s.get("hum") 夠不夠高」的判斷就好；記得濕度可能是 None（沒讀到）。

目標：每按一次 A 鍵，彩色燈換一個顏色。

怎麼測：ble-sim＋網頁上的 A 鍵。

nmcli 說沒有權限舉手（用 SSH 進來的情況老師還沒試過）。今天不用 sudo。
第三部分 藍牙
藍牙起不來、連不上 ESP32：掃不到 maker-XXXX：ESP32 有在跑第 11 課嗎？ESP32 要真的重開（按 EN 或重插電），不能只停程式；有按住 A 再按 EN、看到 OLED 顯示 BLE 才放開嗎？名字打對了嗎？手機 App 有沒有先連著它（一次只能一個中心）？
連不上 ESP32：No module named 'bleak'你不在 w12-starter 資料夾裡跑（先 cd w12-starter），或 vendor/ 沒解出來（重新解壓）。
--link ble 要加 --name maker-XXXX（看 ESP32 的 OLED）少打 --name maker-XXXX。
藍牙線 光線、旋鈕 都是 --、門檻固定 28正常：第 11 課沒提供光線、旋鈕，沒旋鈕就用固定門檻 28。
括號寫 溫度沒讀到，維持上一輪正常：溫溼度感測器偶爾讀失敗（藍牙回 DHT11 read failed），大腦照上一輪判斷。一直出現就舉手。
藍牙斷線了，重新連線…大腦自己重新掃描、重連；ESP32 要還在藍牙模式（重開時按住 A）。
連按兩下 A 只嗶一次正常：大腦一秒看一次，同一秒裡按幾下都只算一次。
按 A 鍵 WiFi 線沒反應正常：第 10 課的回答裡沒有按鈕，WiFi 線讀不到 A 鍵。
AI 叫你 pip 安裝藍牙套件、加 sudo不用也不要：藍牙套件已經在起始檔裡。先給老師看。
第四部分 改大腦
改了 rules.py 沒變要 Ctrl＋C 再重跑大腦；確認存檔了。
IndentationError、SyntaxError縮排沒對齊或少了括號、冒號：看它指的那一行。
題目一：黃燈不亮decide() 回傳的 "yellow" 還是寫死的 False 嗎？濕度真的超過你定的數字了嗎（假板子用網址改 hum）？改完要重跑大腦。濕度沒讀到是 None，要先判斷。
題目二：藍牙線夜燈怎樣都不亮藍牙線讀不到光線，is_dark() 永遠「不暗」：讓 A 鍵自己決定彩色燈。

問 AI 可以，但照這三條

  1. 把事實給足：你打的完整指令、原本預期看到什麼、實際看到的完整錯誤原文、走的是哪條線（WiFi／藍牙／假的）。
  2. 板子密碼不給 AI。WiFi 密碼是 maker＋OLED 上的四個字，那是程式寫死的公開規則，沒關係。
  3. AI 叫你自己 pip 安裝套件、加 sudo、改 ESP32 的程式，先給老師看。今天都用不到；W6 的規矩照舊：不准 sudo pip install、不准 --break-system-packages。

WiFi 線：網頁問答的規矩（HTTP）

大腦像用瀏覽器開網頁一樣，對 ESP32 送一個網址，ESP32 回一段字——這套「問一個網址、回一段答案」的規矩叫 HTTP。第 10 課開了這幾個網址：GET /api/status 回一段大括號的資料（JSON），欄位有 red、yellow、blue、rgb、temp、hum、light、knob、last、requests；/api/led?name=red&on=1 開紅燈（name 可以是 red／yellow／blue）、/api/rgb?r=&g=&b= 彩色燈、/api/beep 嗶、/api/off 全關。192.168.4.1 是 ESP32 在它自己那個網路裡的門牌（IP）。重點：ESP32 只會回答、不會主動開口——A 鍵被按了它也不會說，所以 WiFi 線讀不到按鈕。

藍牙線：寫入與通知

藍牙低功耗（BLE）連上之後，資料擺在「服務＋特徵值」一層一層的架子上（GATT）。第 11 課開了兩組：文字指令服務——大腦往 RX（6E400002-…）寫入一行字，ESP32 從 TX（6E400003-…）通知（notify）回一行字；按鈕（00001524-…）——A 鍵按下／放開，ESP32 主動通知 1／0。指令：temp → temp 25 C, hum 61 %（讀失敗回 DHT11 read failed）；red on → OK red on；rgb 255 0 0 → OK rgb；beep → OK beep；off → OK all off。一行指令最多 128 個位元組、回話截到 100 個位元組。UNO Q 的 Linux 用 Python 的 bleak 套件（起始檔 vendor/ 已經帶好；UNO Q 的系統 Python 沒有 pip，所以不用也不要自己裝），做的事跟手機 App 一樣。

為什麼「只送有變的」

大腦每秒想一次，但只有決定跟「ESP32 上確定已經是這樣」不一樣時才送：紅燈本來就亮著就不再叫一次，嗶聲只在「剛變熱」那一輪叫。哪一輪失敗了（逾時、斷線），大腦就不確定 ESP32 現在是什麼樣子，下一輪成功時把燈號全部重送一次。理由三個：① 每送一次就多一次一問一答，WiFi 線一次只處理一個連線、ESP32 忙著回你就沒空讀感測器；② 藍牙一行一行排隊，送越多越慢；③ 紀錄檔的 sent 欄乾淨，一眼看得出「哪一輪發生了事」。所以第一部分你看到滿滿的 沒變——那是好事。

為什麼這週 SSH 走 USB（192.168.7.2）

UNO Q 只有一張 WiFi 網卡。第二部分它去連 ESP32 的基地台，就離開了原本的網路；你要是用原本那個 WiFi 位址 SSH 進來，連線當場就斷。USB 線上那張網卡（W6 做的）跟 WiFi 無關，192.168.7.2 永遠在，所以今天一律走它。也因為這樣，起始檔要在連 ESP32 之前抓好——連上之後板子就沒有外網（時鐘也會停住，所以畫面時間是 5 月）。回原本的網路：nmcli connection show 查名字，再 nmcli connection up 接那個名字（都不用 sudo）。

一問一答多久（RTT）、中位數、95%

「讀一次感測值來回」＝從大腦送出問題，到拿到答案的時間，叫來回時間（RTT）。每一輪量一次，停下來時排序：中位數是正中間那個（不怕偶爾一次特別慢），95% 在 … 內是「一百次裡九十五次都比這快」。假的 ESP32 的數字是電腦內部的，不代表 WiFi 或藍牙；真的數字今天你自己量（每塊板、每張桌子、每一次都不同）。紀錄檔是一行一筆的表格（CSV），read_ms 欄就是每一輪的來回時間、fail 欄 1＝那一輪沒回應、why 欄是理由。另外：WiFi 線問到的感測值是 ESP32 大約每 2 秒更新一次的那一筆，所以每秒問會連續拿到同一筆；量到的是「一問一答多久」，不是「感測器多快」。
