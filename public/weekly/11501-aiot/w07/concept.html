1核心與模組：對版才卡得上

核心（kernel）是作業系統的心臟；核心模組（kernel module）是可以插上去的零件，一個 .ko 檔。每個模組身上蓋了一個章，叫 vermagic，寫它只配哪一版核心。章的開頭跟 uname -r 對不上，insmod 就不收。

檔大小SHA256（前 8 碼）出處
u_audio.ko114,024 B6c90c70d…§〇 C·兩個模組檔
usb_f_uac2.ko207,120 B5c955ddd…§〇 C·兩個模組檔

兩個模組的章都是 7.0.0-g122c2c22d838 SMP preempt mod_unload aarch64 §〇 A／C·vermagic。所以 W12 的音效卡非 7.0.0 不可。

被拒的時候會印什麼？

成功的時候：老師板兩行 insmod 結束碼都是 0，dmesg | tail 多一行 u_audio: loading out-of-tree module taints kernel——意思是「載了一個不是跟核心一起編的模組」，正常 §〇 C·手動載入。

      如果 handler 寫壞了，會發生什麼？（只推演、不給碼）
      
    
      假設有人圖方便，把手機傳來的整句話直接交給 shell 執行：那麼教室裡任何一支手機——不用配對、不用密碼——打什麼，板子就以 arduino 的身分跑什麼；arduino 還在 docker 群組裡 v1 §〇 B·U 與 C。等於把板子的鑰匙貼在教室門口。
      
    
      所以回家挑戰替板子多教一個指令時，就算請 AI 幫忙，也要自己核對三件事：沒有把手機的原字交給 os.system／subprocess、help 有更新、手機實打有回 v1 §三·三件事。幾支手機能不能同時連同一塊板沒測過，今天改成同組輪流連 v1 §〇 C ⚠️。
