1　就位：接板子、開一條通道、SSH 進板子

目標：視窗 A 開好 2222 通道，視窗 B 的提示字元變成 arduino@ 開頭。

跟 W4、W5 一樣的四行。2222 讓你用 SSH 進板子打指令；網頁的通道今天換第 3 節開（三條）。都走 USB 線，不用知道板子的 IP。板子上週連過的 Wi-Fi 還在就不用動。

  1. 接線、等心跳：USB-C 資料線把板子直接插在電腦上（中間不要經過 hub）。點陣從旋轉的圖案變成心跳動畫，通常 30～60 秒。還在轉就先等，不要拔。
  2. USB 看得到：打開終端機（Ctrl＋Alt＋T），這就是視窗 A。打： 
    lsusb | grep -E '2341:0078|05c6:9008'
    正常要看到 2341:0078。看到 05c6:9008 是恢復模式：舉手叫老師，不要自己重刷。
  3. 找出 adb（App Lab 附的那個，不用另外裝）。前兩行是同一個指令（第一行最後的 \ 代表接到下一行），要一起貼： 
    ADB=$(find "$HOME/.arduino15/packages/arduino/tools/adb" \
    -type f -name adb -perm -u+x -print 2>/dev/null | sort -V | tail -n 1)
"$ADB" devices -l
    最後一行要列出剛好一塊板，狀態是 device。列出兩台以上，拔掉手機或別人的板子。$ADB 只在跑過這段的視窗裡有值，換視窗要重跑。
  4. 開 2222 通道：在跑過上面那段的同一個視窗打。成功時不印任何字： 
    "$ADB" forward tcp:2222 tcp:22
  5. 再開一個終端機視窗（視窗 B），SSH 進板子（ssh 不需要 $ADB，所以新視窗直接打）： 
    ssh -p 2222 arduino@127.0.0.1
    第一次會問 Are you sure you want to continue connecting，打完整的 yes、按 Enter；再打板子的密碼（打的時候畫面不會動，打完按 Enter）。要打 127.0.0.1，不要打成英文的本機名稱，會連不上。

視窗 B 的提示字元變成 arduino@… 開頭，就進到板子裡了。今天所有 arduino-app-cli、sudo 指令都在視窗 B 打；"$ADB" 開頭的都在視窗 A 打。

3　三條通道，開網頁，看臉框

目標：Chrome 開 http://127.0.0.1:17000，右下角「AI 人臉框選」框住你的臉。證據 1

畫面從電腦出發、經一條 USB 線、進板子、進容器，再回到網頁。三條通道各管一件事，缺一條畫面就不會出來：

電腦的埠 → 板子的埠走什麼
17000 → 7000操作的網頁本身
18080 → 8080影像：瀏覽器把一張張 JPEG 丟進去
14912 → 4912AI 框選：模型跑完的畫面，網頁用一個小視窗嵌回來
  1. 開三條通道（視窗 A；成功時不印字）。轉送（port forward）＝「電腦的這個埠，接到板子的那個埠」： 
    "$ADB" forward tcp:17000 tcp:7000
"$ADB" forward tcp:18080 tcp:8080
"$ADB" forward tcp:14912 tcp:4912
  2. 確認三條都在： 
    "$ADB" forward --list
    會列出每一條通道一行：行首是板子的序號（不用抄、不要截進作業），後面是 tcp:17000 tcp:7000 這種對應。加上第 1 節的 2222，共四行。
  3. 開網頁：Chrome 網址列打 http://127.0.0.1:17000。頁面標題是「人臉辨識測試」。一定要寫 127.0.0.1，為什麼 → 第 6 節會親眼看到。
  4. 選攝影機、允許：「1. 選擇攝影機」的下拉選單會列出教室機的攝影機；Chrome 第一次會在網址列旁邊問「要允許使用攝影機嗎」，按允許。
  5. 按「開始辨識」：下面狀態列變成「筆電攝影機：使用中」、「USB 影像傳送：已連接」、「送出畫面」開始數。左下「原始攝影機」是你的畫面，右下「AI 人臉框選」是板子算完回來的——臉上有框，就是板子看到你了。坐正、開燈、離鏡頭近一點（送過去的畫面只有 320×240）。
  6. 讀六格數字（「即時統計」那一排）：
格老師板 10/14 量到意思
送出速度8.0 FPS，下面小字「板子實際收到 8.0 FPS」瀏覽器每秒送幾張、板子每秒真的收到幾張（板子那邊自己數的）
USB 資料量35–52 KB/s每秒走過 USB 線的資料量，看畫面內容而定
送出影像320 × 240送給板子的畫面大小
已執行00:29這次按下開始辨識後經過的時間
跳過畫面0 張板子忙不過來或斷線時沒送出的張數
AI 看到有臉：臉數＋信心度；沒臉：「等待畫面」AI 這一秒的答案

回視窗 B 看 log，會多出 camera:connected、camera:streaming {}；有臉時每秒印幾行 faces=1。

✋ 先猜：8.0 是誰定的？想一想再點開。

揭曉

兩個地方各寫了一次 8：板子 python/main.py 的 fps=8，和網頁 assets/app.js 的 const TARGET_FPS = 8;。所以「板子實際收到」最高就是 8——網頁送再快，板子那邊也只收 8。第 7 節會把兩處都改成 20，看 AI 會不會跟著快 2.5 倍。

還有一件事在背後默默做：板子沒有電池時鐘，只收「時間戳在 ±10 秒內」的畫面。網頁按下開始辨識時會先讀板子回的時間、算出時差再打戳，所以你不用替板子對時；差超過 2 秒時「USB 影像傳送」那格會註明校正了多少。

4　一條線變網卡：裝進 adbd 的生命週期

目標：板子多一個「USB 網卡」的身分；電腦多一張 192.168.7.x 的網卡；不用 forward 就能 ssh arduino@192.168.7.2。證據 2

上半節每一條通道都靠 adb forward 開，而且它會自己掉（7/22 一個下午掉了 4 次）。USB 不是「一條線一種功能」：板子現在對電腦報的身分有兩個——adb 和序列埠；我們再加一個「USB 網卡（NCM）」，電腦就像插了一張網路卡，線本身就是網路。要不要改 kernel？不用：網卡的驅動是一個 kernel 模組（kernel module），早就編好放在板子上，載進去就行。

① 先看三樣：沒看過原本的樣子，就不知道改了什麼

  1. 板子現在有哪些身分（視窗 B）。configs/c.1/ 底下一個連結＝一個身分： 
    ls /sys/kernel/config/usb_gadget/g1/configs/c.1/
    出廠只有兩個：ffs.adb（adb）和 acm.GS0（序列埠）。旁邊幾個是這一組的設定檔，不用管。
  2. 驅動模組就在板子上： 
    ls /lib/modules/$(uname -r)/kernel/drivers/usb/gadget/function/

  4. 看你等一下要裝的那個檔。它是給 adbd 服務的「補充設定」（drop-in），有效的只有最後 [Service] 那一段： 
    cat ~/w06-usbnet/10-extra-functions.conf

ExecStop=-/home/arduino/usbnet/ncm-hook.sh remove

③ 七行 sudo，一行 restart

  1. 把三個檔放到該去的位置，再讓發 IP 的服務跟著網卡自動起來（視窗 B；sudo 要打板子的密碼，打一次後面幾行不會再問）。install＝複製檔案並順手設好權限（-d 建資料夾、-m 權限）；daemon-reload 讓 systemd 重讀設定；最後的 enable 把發 IP 的服務設成「usb0 一出現就起來」： 
    cd ~/w06-usbnet

sudo install -m 755 ncm-hook.sh /home/arduino/usbnet/ncm-hook.sh

sudo install -m 644 10-extra-functions.conf /etc/systemd/system/adbd.service.d/
sudo install -m 644 usbnet-dhcp.service /etc/systemd/system/

    除了最後一行，其他都不印字；enable 會印這一句： 
    Unit /etc/systemd/system/usbnet-dhcp.service is added as a dependency to a non-existent unit sys-subsystem-net-devices-usb0.device.
    看起來像錯誤，其實是正常的：它說「你綁的那個 usb0 裝置現在還不存在」——當然，網卡還沒掛上。三個檔分別去了哪：ncm-hook.sh（做 add／remove／sweep 的腳本）→ /home/arduino/usbnet/；drop-in → /etc/systemd/system/adbd.service.d/；usbnet-dhcp.service（網卡一出現就給它 192.168.7.2、再替電腦發 IP）→ /etc/systemd/system/。

    打完這一行，視窗 B 的 SSH 會斷掉——正常。因為 2222 那條通道是 adb 開的，adbd 一重啟它就沒了。不要拔線、不要重打；數 15 秒，然後做第 ④ 步。

為什麼是「掛進 adbd」，不是「執行中硬改」

板子上這一束 USB 身分（gadget）的主人是 adbd：開機時它建好（setup）、插上插頭（activate），停止時它拆光（reset）。如果我們趁它在跑的時候硬去拔插頭、塞一個新身分，adbd 會當場死掉、1 秒後自動重啟；重啟時 reset 看到一個它不認識的連結就卡住——adb 從此起不來。7 月 28 日老師的板子就是這樣壞的：第二次重開機只剩音效卡，adb、序列埠、網卡全斷，最後整塊重刷才救回來。

正解是把我們的動作掛進 adbd 自己的生命週期：它 setup 完我們就 add（這時插頭還沒插，所以零斷線）；它要停我們先 remove；它 reset 之後我們再 sweep，不論前一步成功或失敗都把殘骸清乾淨，下一輪 setup 永遠從零開始。而且每一步都容忍失敗：最壞的情況＝網卡沒掛上，adb 照常活著。

這張網卡是持久的：以後每次開機、插上電腦就有，不用再做一次——這是刻意的，之後傳模型、傳資料走它（第 5 節會量到 100 MB/s 以上）。因為 MAC 位址是固定的，一台電腦一次只接一塊板（兩塊板會撞同一個 IP）。想拿掉 → 第 8 節。

7　有餘力：怎麼變快？三個數字三件事

目標：把送幀速率從 8 改成 20，親眼看 AI 有沒有跟著快；說得出瓶頸在哪一層。

「送出速度」是攝影機供幀、「板子實際收到」是走過 USB 線的、AI 每秒回幾次結果是模型算的——三個數字三件事。改之前先猜。

✋ 先猜：把 8 改成 20，AI 每秒回的結果會不會變成 2.5 倍？

  1. 改兩處（視窗 B）。只改板子那邊沒用，網頁 app.js 也寫死了 8，兩邊都改： 
    cd ~/ArduinoApps/face-usb-classroom
sed -i "s/^    fps=8,/    fps=20,/" python/main.py
sed -i "s/^const TARGET_FPS = 8;/const TARGET_FPS = 20;/; s/max: 12 }/max: 30 }/" assets/app.js
grep -n -E "fps=|TARGET_FPS = |max: " python/main.py assets/app.js
    最後一行是確認：要看到 fps=20,、const TARGET_FPS = 20;、max: 30 } 三處都換了（main.py 註解裡另一個 fps=8 不用管）。
  2. 重啟 App（視窗 B；停、再起）： 
    arduino-app-cli app stop ~/ArduinoApps/face-usb-classroom
arduino-app-cli app start ~/ArduinoApps/face-usb-classroom
  3. 回 Chrome 重新整理（走轉接程式或 forward 都可以），按「開始辨識」：送出速度 20.0 FPS、板子實際收到 20.0、USB 資料量升到 89–137 KB/s、跳過 0。
  4. 數 AI 每秒回幾次：按 F12 打開開發人員工具，切到「主控台（Console）」——每一行 classification 就是一次推論（inference，模型算一張畫面），行尾的數字是這一張花了幾毫秒。數 10 秒有幾行，除以 10。
  5. 看容器有多忙（視窗 B）： 
    docker stats --no-stream
    看 face-usb-classroom-ei-video-obj-detection-runner-1 那列的 CPU %。
送幀AI 每秒回幾次每張推論AI 容器 CPU
8 FPS5.5 次/秒86–102 ms（中位 90）76%
20 FPS6.3 次/秒87–100 ms（中位 93）113%

揭曉：送更多為什麼不更快

送 2.5 倍的畫面，AI 只多回了 15%。每張推論都要 90 毫秒左右，而且官方的管線一次只處理一張、三個行程擠在一顆核心上——四核的板子，AI 容器只用到「一核多一點」（113%）。所以瓶頸不在攝影機、不在 USB 線，在AI 怎麼跑那一層。多送的畫面只是在排隊、被丟掉。

老師示範：快速版，同一顆模型跑 20 FPS

做法：繞過官方的 AI 容器，Python 直接把模型當程式跑，開 3 個 worker 平行算，一支 App 只剩一個容器（app start 1.7 秒就起來）。7/22 的階梯：1 個 worker 7.6 FPS → 2 個 15.2 → 3 個 22.8；教室版卡在 8.0。同一顆模型、同一塊板，快約 3 倍。

換 kernel 能不能變快？

不能，今天的瓶頸不在 kernel。板子的 CPU 有 4 核、9 檔速度（300 MHz 到 2.016 GHz），調速器是 schedutil，量的時候四核都在 1.8 GHz；7/20 的速度調查也排除了過熱——晶片 50–57 °C、長時間跑不劣化。kernel 管的是「有沒有驅動、怎麼排程」：下半節那顆 NCM 模組就是 kernel 的事，而且它早就編好放在板上，modprobe 一行就載，根本不用重新編譯。真的要動 kernel 的時候是：模組根本沒編、或要寫新驅動——那是 W15「自編核心模組」那週的事。今天要快，改的是「AI 怎麼跑」那一層。

⚠️ 快速版開 3 個 worker 時別只靠電腦的 USB-C 供電（尖峰約 1.2 A，會掉電硬重開），要接 3 A 的 USB-C 電源或有供電的 hub——這是老師示範時的事，學生板今天不會碰到。
