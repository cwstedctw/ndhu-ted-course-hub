    COMPONENTS回目錄 ↑

    一句話：每個元件只做一件事；「不負責」那一欄跟「負責」一樣重要——它告訴你出問題時不用去哪裡找。

    元件跑在哪用什麼寫負責不負責
    python/main.pyLinux Docker 容器Python 3.13＋arduino.app_utils上網、解析 JSON、快取、組一行英文字、印 log不碰燈、不碰點陣、不管 MCU 多久問一次

    sketch/sketch.inoMCU Zephyr 上的 llextC++（Arduino）決定什麼時候發問、等回覆、畫字、捲動不上網、不知道金鑰

    App 的檔案與生命週期

    FILES & LIFECYCLE回目錄 ↑

    一句話：一支 App 就是一個資料夾；app start 會把 sketch 編好燒進 MCU、再把 Python 放進容器跑起來。

    ~/ArduinoApps/my-aqi/
├── app.yaml            App 的名字、用了哪些積木（bricks）；空白 App 是 bricks: []
├── python/
│   ├── main.py         Linux 這半（換成課程網的版本）
│   └── moenv_key.txt   金鑰（自己用 read -rsp 存；不截圖、不上傳）
└── sketch/
    ├── sketch.ino      MCU 這半（換成課程網的版本）
    └── sketch.yaml     平台＋函式庫清單（多了 ArduinoGraphics (1.1.4)）

    從建立到停止

    1. arduino-app-cli app new my-aqi：建出上面的資料夾（空白內容）。
    2. 換三個檔（curl 從課程網抓）＋存金鑰檔。到這裡都只是檔案，板子還沒有任何改變。
    3. arduino-app-cli app start ~/ArduinoApps/my-aqi：讀 sketch.yaml、第一次會下載函式庫 → 在板上編譯 sketch → 燒進 MCU → 起 Docker 容器跑 main.py。最後一行 ✓ App "my-aqi" started successfully。第一次 96–108 秒、同一支第二次約 23 秒 〔實板 10-02〕
    4. arduino-app-cli app logs ~/ArduinoApps/my-aqi --tail 60：看 main.py 印出來的每一行（每行開頭 [main]）。
    5. arduino-app-cli app stop ~/ArduinoApps/my-aqi：停掉這支 App。一次只能跑一支，換下一支之前先停；不要用 app restart。

    改了檔案之後：改 main.py → app stop、等 3 秒、app start（約 23 秒）；改 sketch.ino／sketch.yaml → 一樣停再起，但要重新編譯、比較久。只有金鑰檔例外：補好或換掉金鑰檔，不必重開 App，程式 1 分鐘內會自己再試 〔實板 10-02〕。

    兩顆腦的約定：get_aqi_text 介面

    INTERFACE CONTRACT回目錄 ↑

    一句話：兩邊只約定「一個名字＋一個字串」。約定寫清楚，兩邊就能各自改程式而不打架——這就是 W15 期末要寫的 contract。

    項目約定內容
    方法名get_aqi_text
    誰登記（提供）Linux main.py 第 64 行 Bridge.provide("get_aqi_text", get_aqi_text)。底層是向總機送 $/register 〔原始碼〕
    誰呼叫MCU sketch.ino 第 16 行 Bridge.call("get_aqi_text").result(text)
    參數沒有（空陣列 []）
    回傳一個字串，只用英文字母、數字、空白和少數符號（.、?、-）。點陣的字型只有這些字，中文會變亂碼（§10 D7）
    正常值HUALIEN AQI <aqi> PM2.5 <pm2.5>；環境部沒給值時用 --。判斷規則：以 LABEL 開頭＝真資料（main.py 第 59 行就是這樣判斷）
    狀態值（不是資料）NO KEY、KEY?、NO SITE、NO DATA（Python 回的）；WAIT（MCU 自己補的：沒拿到回覆時）
    新鮮度真資料最多舊 10 分鐘（快取）；狀態值最多 1 分鐘後會重試
    呼叫頻率MCU 捲完一輪就問一次，實板 log 約 12 秒一行 〔實板 10-02〕
    等待MCU 端（Arduino_RouterBridge）的 result() 在原始碼裡是迴圈等到收到回覆為止，沒有逾時參數 〔原始碼 10-08 main〕；總機會不會替它逾時，原始碼沒讀到、也沒實測。Python 端的 Bridge.call 預設最多等 10 秒 〔原始碼 bridge.py〕——以前 nightlight 實驗第一發冷啟動「逾時 10 秒」就是這一側 〔實板 07-27〕。本週是 MCU 呼叫 Python；Python 上網那一次最多等 15 秒（urlopen(timeout=15)）
    線上格式MessagePack-RPC。請求 [0, msgid, "get_aqi_text", []]；回覆 [1, msgid, nil, "<字串>"]。大小約 17／27 位元組 〔估算〕（自己算：概念頁 §4 位元組計算器）

    同一座 Bridge，方向可以反過來：〈Color your LEDs〉是 MCU 登記 set_led3_color、Python 呼叫；天氣範例和 AQI 版是 Python 登記、MCU 呼叫。總機只認名字，不管誰在哪一顆腦。

    main.py 的結構

    PYTHON SIDE回目錄 ↑

    一句話：66 行分成七塊；真正的邏輯只有兩個函式——fetch_aqi() 負責「問一次」，get_aqi_text() 負責「要不要問」。

    結構地圖（照行號）

    1–9
    匯入：只用 Python 標準函式庫（json、pathlib、ssl、time、urllib）＋官方的 arduino.app_utils（提供 Bridge、App）
    11–15
    設定：SITE（查詢用的中文站名）、LABEL（顯示用的英文）、CACHE_SECONDS、RETRY_SECONDS、KEY_FILE（金鑰檔路徑，跟 main.py 同一層）
    17–19
    連線安全：建一個 TLS 設定 SSL_CTX，只放寬一項檢查（§10 D5）
    21–22
    狀態：last_text（要顯示的字，開機是 WAIT）、last_fetch（上次上網的時間，開機是 0）
    25–41
    fetch_aqi()：讀金鑰 → 組網址 → HTTPS GET → 解 JSON → 組成一行字
    44–61
    get_aqi_text()：快取判斷、呼叫 fetch_aqi()、接住所有例外、決定下次多久後再試
    64–66
    啟動：向總機登記 get_aqi_text，然後 App.run() 讓程式一直活著等人來問

    兩個函式的規格

    fetch_aqi() -> str

    被誰呼叫：只有 get_aqi_text()

    • 讀：KEY_FILE（金鑰）、SITE
    • 做：urlencode 組查詢字串（中文站名會被正確編碼）→ urlopen(..., timeout=15, context=SSL_CTX) → json.loads
    • 回：HUALIEN AQI …；回來的不是 JSON → KEY?；空陣列 → NO SITE
    • 往外丟：FileNotFoundError（沒有金鑰檔）、連線錯誤、KeyError（欄位改名）——交給呼叫它的人處理
    • 印：moenv:／moenv says:／no such site: 其中一行；絕不印金鑰或完整網址

    get_aqi_text() -> str

    被誰呼叫：總機（MCU 每問一次就呼叫一次）

    • 狀態：last_text、last_fetch（全域變數，記在容器的記憶體裡；App 重開就歸零）
    • 規則：距上次上網不到 600 秒 → 印 cache:、回上次的字；否則上網
    • 保證：永遠回一個字串，不會把例外丟回 Bridge（第 56 行 except Exception 全部接住）
    • 小技巧（第 59–60 行）：沒拿到真資料時，把 last_fetch 往回撥成「現在 − 600 + 60」——效果是 60 秒後快取就「過期」，不用等滿 10 分鐘

    快取的狀態機

    把 get_aqi_text() 畫成狀態圖，就是四個狀態。想按按鈕模擬，用概念頁 §5〈額度計算機與快取〉。

    A 開機

    last_text = "WAIT"、last_fetch = 0。第一次被問時，距 0 一定超過 600 秒 → 去 B。

    B 上網

    呼叫 fetch_aqi()。拿到以 LABEL 開頭的字 → 去 C；拿到狀態值（NO KEY 等）→ 去 D。

    C 快取有效（600 秒）

    這段時間每次被問都印 cache:、回同一行字。滿 600 秒後再被問 → 回 B。

    D 失敗冷卻（60 秒）

    每次被問也印 cache:，回的是狀態值（例如 cache: NO KEY）。滿 60 秒後再被問 → 回 B。

    想一想：在 C 狀態時把金鑰檔刪掉，點陣會馬上變 NO KEY 嗎？（不會。要等快取過期、真的再上網時才發現——快取讓錯誤「晚一點才看得到」。§12 的故障演練就是利用這一點。）

    sketch.ino 的結構

    MCU SIDE回目錄 ↑

    一句話：setup() 只做一次準備；loop() 每一輪做三件事——問、補、畫。畫字的那一行（捲動）會花掉一輪絕大部分的時間。

    setup()：開機做一次（第 8–12 行）

    1. matrix.begin()、matrix.clear()：啟動點陣、清空畫面。
    2. Bridge.begin()：接上總機。之後才能 call。

    loop()：一直重複（第 14–28 行）

    1. 問（第 16 行）：Bridge.call("get_aqi_text").result(text)。送出請求，停在這裡等回覆；回覆成功 → ok 是 true、text 拿到字串。
    2. 補（第 17–19 行）：ok 是 false（例如 Python 還沒登記）→ 自己把 text 設成 WAIT。
    3. 畫（第 20–27 行）：beginDraw() → stroke(0xFFFFFFFF) 筆畫顏色 → textScrollSpeed(60) 每移一格停 60 毫秒 → textFont(Font_5x7) 5×7 字型 → beginText(0, 1, 0xFFFFFF) 從第 0 欄、第 1 列開始 → println(" " + text + " ") 把字放進緩衝區 → endText(SCROLL_LEFT) 一格一格往左捲到完 → endDraw()。
    4. 回到第 1 步，再問一次。

    兩個容易漏的細節：① 第 2 行 #include <ArduinoGraphics.h> 要放在 Arduino_LED_Matrix.h 前面，點陣函式庫才會接上畫字功能 〔原始碼〕；② 前後各補三個空白，是讓字從右邊外面滑進來、再完整滑出去，不會一開始就擠在左邊 〔依原始碼推論〕。

    為什麼這樣設計

    DESIGN DECISIONS回目錄 ↑

    一句話：每個設計都有「選了什麼、沒選什麼、付出什麼代價」。寫期末設計文件時，這一節的格式最值得照抄。

    D1　MCU 發問（pull），不是 Python 推（push）

    理由：MCU 捲完一輪才需要下一筆，自己決定節奏最自然；Python 不必知道 MCU 忙不忙。官方天氣範例也是這個模式。

    代價：每一輪都要過一次橋（毫秒級，跟 9–12 秒的捲動比可以忽略）；MCU 在 result() 等待時不能做別的事。

    另一個選擇：Python 有新資料才用 notify 推給 MCU（單向、不等回覆），適合「一變就要通知」的情境（擴充題 ★★★）。

    D2　快取 600 秒

    理由：測站每小時才更新，問再快也是同一筆；金鑰每把每天 5,000 次。成功時一個人一小時最多打 6 次。

    代價：畫面上的資料最多晚 10 分鐘——對每小時更新的資料感覺不出來。

    D3　失敗後 60 秒重試

    理由：沒網路時，如果每 12 秒打一次，會白白消耗額度；如果等滿 10 分鐘，補好金鑰的人要等太久。60 秒是中間值。

    代價：一直失敗時一小時最多 60 次，仍遠低於每天 5,000 次。

    D4　金鑰放檔案，不寫進程式

    理由：程式可以分享、上傳 GitHub、貼給同學，金鑰不跟著走。存金鑰用 read -rsp：畫面不顯示，指令歷史也只記得 $K。

    代價：多一個檔要管理；放錯資料夾就是 NO KEY。

    D5　只放寬一項憑證檢查，不是關掉驗證

    理由：板上 Python 3.13 預設開嚴格檢查（VERIFY_X509_STRICT），環境部網站的憑證少一個欄位（Subject Key Identifier）會被擋。第 19 行只拿掉這一項，主機名稱與信任鏈照樣驗：過期憑證、主機名稱不符的網站實測仍被擋 〔實板 10-02〕。

    代價：要多寫兩行並解釋清楚，否則看起來像在「關安全」。

    D6　只用標準函式庫

    理由：空白 App 的容器不必另外安裝套件（app.yaml 是 bricks: []），學生少一個會壞的步驟。

    代價：urllib 寫起來比第三方套件囉嗦一點。

    D7　查詢用中文、顯示用英文

    理由：環境部的測站名是中文，所以 SITE 用中文查；點陣的 Font_5x7 只有英文字母、數字與符號，中文的 UTF-8 位元組會被拆開查字形、變成亂碼，所以 LABEL 用英文 〔原始碼 ArduinoGraphics〕（想看亂碼長怎樣：概念頁 §6）。

    代價：兩個值要一起改（§9）。

    D8　空白 App＋換三個檔

    理由：不需要天氣積木，也避開出廠舊版工具 --from-app 還沒驗過的風險；空白 App 換三個檔已實板跑通 〔實板 10-02〕。

    代價：要從課程網抓檔，課程網沒上站就抓不到（學生頁有備援貼法）。

    D9　用字串回報狀態

    理由：點陣直接顯示，人眼一看就知道哪裡壞。

    代價：資料和狀態擠在同一個字串，要靠「是不是 LABEL 開頭」分辨——LABEL 一改錯，真資料也會被當成失敗。擴充題 ★★ 讓你把它拆開。

    一句話：瓶頸不在 Bridge（毫秒），而在捲動和上網（秒）——所以毫秒級的控制留在 MCU、秒級的上網放 Linux，這就是雙腦分工的理由。

    項目數字等級
    Bridge 往返（Python 呼叫 MCU 的 echo，n=200）中位數 4.99 ms、p95 5.08 ms；冷啟動第一發 7.7 ms〔實板 07-27〕
    get_aqi_text 一次往返約 7–8 ms（封包比 echo 大，不能直接拿 4.99 ms 套）〔估算〕
    Python 上網一次沒量過；上限 15 秒（逾時設定）〔原始碼〕
    捲一輪（HUALIEN AQI 32 PM2.5 7，速度 60）151 步 × 60 ms ≈ 9.1 秒（純 delay）；實板 log 約 12 秒一行〔估算〕〔實板 10-02〕

    EXTENSIONS回目錄 ↑
