一條線，點亮一整串燈

單線 RGB 燈為什麼只要一支腳：從「燈多腳少」到排隊送、接力傳、真的拿來用

燈很多、腳很少，所以不讓每顆燈各占一支腳，而是把所有顏色排成一長串，從同一條線依序送出去。每顆燈收下排在最前面的 24 位元，剩下的整理好往下一顆傳；線停在低電位夠久，全部一起換色。這種每顆都能單獨指定顏色的燈，叫可定址 RGB 燈（WS2812／NeoPixel）。

① 燈多腳少② 0 和 1 怎麼說③ 接力傳話④ 算算看⑤ 跟 I2C 比⑥ 排成矩陣⑦ Wokwi 動手

套件上就是這種燈：三顆串在一起，只接 GPIO26（板面印 IO16）（K2）。這一頁的 16 顆環形燈、8×8 矩陣、300 顆燈條，套件都沒有，只在 Wokwi 和計算機裡看。姊妹頁：〈腳位怎麼講話實驗台・② 一條線〉、〈讀旋鈕、調亮度實驗台〉。

1

問題：燈很多，腳很少

一顆 RGB 燈裡面其實是紅、綠、藍三顆小燈。上週學過：一支腳用 PWM 可以調一顆燈的亮度。所以最直接的接法是一顆 RGB 燈占三支腳（R、G、B 各一支）。燈一多，腳就不夠了。

（拉桿六格：1、3、8、16、64、300 顆）

每顆燈直接接：一顆三支腳

9 支腳

排隊送：所有燈共用一條資料線

1 支腳（另外接電源、接地）

解法：不讓每顆燈各占一支腳，改成「排隊送」（serial，一個接一個送）。ESP32 把所有燈的顏色排成一長串 1 和 0，從同一支腳依序送出去；燈自己知道「最前面那一份是我的」。下面四段，一段回答一個問題：一條線怎麼說 0 和 1？一長串怎麼分給每一顆？送一次要多久、要多少電？排成方陣時誰是第幾顆？

2

一條線怎麼說 0 和 1：看高電位多長

I2C 有一條專門打拍子的線（SCL）。單線燈沒有拍子線，所以大家事先約好時間：每一位元約 1.25 µs（微秒，百萬分之一秒）；高電位「短」是 0、「長」是 1。資料表寫的是：0＝高 0.40 µs、1＝高 0.80 µs，每段可以差 ±0.15 µs（P11）。燈裡的小晶片就靠量「高了多久」分辨 0 和 1。

資料表的數字（WS2812B，P11）與 MicroPython 實際送的（M10）

這一段資料表MicroPython 送
0 的高電位0.40 µs ±0.150.40 µs
0 的低電位0.85 µs ±0.150.85 µs
1 的高電位0.80 µs ±0.150.80 µs
1 的低電位0.45 µs ±0.150.45 µs
一位元合計1.25 µs ±0.61.25 µs
停多久才換色舊版 ≥ 50 µs；新版 V5 > 280 µs送完就停在低電位

上表「資料表」那欄是舊版 WS2812B。新版（V5）的數字不同：0 的高電位 0.22–0.38 µs、1 的高電位 0.58–1 µs、送完要停在低電位 > 280 µs（P11b）。本頁一律保守抓：送完後維持低電位至少約 300 µs，燈才換色。投影片寫的 50 µs 是舊版資料表；新版要更久，保守抓 300。

⚠️ 依 V5 資料表，MicroPython 送的「0 的高電位」0.40 µs 已經超過上限 0.38 µs。Wokwi 能跑，不代表真板保證成功；套件那三顆是哪一版沒查到，W10 拿到真板再確認料號或量測（P11b）。

動手：挑一個顏色，看它變成哪 24 位元

R 紅128 G 綠0 B 藍0

送出去的順序是綠先、紅、藍（G、R、B），每個顏色 8 位元、高位先送（P10）。你寫 (r, g, b)，neopixel 模組幫你排成 G、R、B（M10）：

程式不用自己數這些微秒。neopixel 是 ESP32 的 MicroPython 韌體內建的模組（今天在 Wokwi 列出的模組清單裡就有它，M12）。你寫 np[0] = (r, g, b)，它把顏色存進記憶體（MicroPython 的 neopixel 模組、三色燈：緩衝區照 G、R、B 排）；np.write() 再把整串交給 ESP32 裡一塊專門發精準脈衝的硬體去送，一位元只有 1.25 µs，靠程式一行一行開關腳位來不及（M11）。

3

接力傳話：第一顆留下前 24 位元，其餘往下傳

燈一顆接一顆串起來：ESP32 → 第 1 顆的 DIN（資料進）→ 第 1 顆的 DOUT（資料出）→ 第 2 顆的 DIN……。第 1 顆收下最前面 24 位元，後面的整理好（重新整形）從 DOUT 送給第 2 顆；第 2 顆再收下它看到的最前面 24 位元……（P12）。所以燈不需要名字：排第幾個，就拿第幾份。收到的顏色先放著，等線停在低電位夠久（保守抓至少約 300 µs），所有燈才一起換色（P11、P11b）。

改記憶體（np[i] = …）：

燈現在的顏色（上排）・每顆收下、還沒顯示的 24 位元（下面小條）

np[i] = (r, g, b) 只改 ESP32 記憶體裡的數字（下面那行 np.buf）；np.write() 才把整串送上線。試試看：先按上面任一組顏色、不要按 np.write()——燈不會變，因為根本沒送。跟 OLED 的 show() 是同一個道理。實驗台也有同一件事：〈只改不 write()〉。

4

算算看：串 3 顆跟串 300 顆，差在哪

一條線很省腳，但代價有三個：串愈多，送一次愈久（資料每顆 24 位元 × 1.25 µs＝30 µs，送完還要停在低電位約 300 µs 才換色）；記憶體每顆要 3 個位元組；電流估電源時每顆全白抓 60 mA（A1）。改數字看看。

每顆的顏色：

這些數字怎麼算的

資料脈衝時間＝顆數 × 24 位元 × 1.25 µs。一個完整畫面＝資料時間＋停在低電位的時間，本頁保守抓 300 µs（新版 V5 要 > 280 µs；舊版資料表寫 ≥ 50 µs，投影片寫的就是這個，P11、P11b）。每秒最多換幾次＝1 秒 ÷ 一個完整畫面——只看傳輸時間的理論上限；Python 程式本身（算顏色、呼叫 write()）也要時間，實際會更少。資料表自己寫：每秒 30 張畫面時，可以串到 1024 顆以上（P19），跟 1024 × 30 µs ≈ 31 ms 對得起來。

記憶體＝顆數 × 3 個位元組：neopixel 模組開一塊 bytearray(n * 3) 存顏色（M10）。

電流（保守估）＝顆數 × 60 mA × 亮度 ÷ 255。每顆 60 mA 是保守的估電源算法（Adafruit：全白最亮時每顆最多），不是每顆燈都會量到這麼多；日常混色他們用每顆 20 mA 粗估（A1）。⚠️ 亮度和電流當成近似直線估算（燈用開關快慢調亮度，平均電流大致跟著亮度走），不是量測值，真板沒量過。

5

跟 I2C 比：一個喊名字，一個看排隊位置

I2C 用兩條線，每顆裝置有自己的位址，開頭先喊名字、被喊到的回「收到」。單線燈只有一條資料線（另接電源、接地），沒有名字、也不回話，靠的是「你排第幾個」。跟投影片第 11 頁那張對照表同一件事，多加幾列：

I2C（套件的小螢幕）單線燈（套件的三顆 RGB 燈）SPI（Wokwi 點陣）
幾條線2：SDA 資料、SCL 時脈1：資料線（另接電源、接地）4：SCK、MOSI、MISO、CS
怎麼挑對象喊位址（螢幕是 0x3C）排隊：第幾個就拿第幾份 24 位元（P12）CS 拉低的那顆才聽
誰打拍子ESP32 在 SCL 上打沒有拍子線：看高電位多長（P11）ESP32 在 SCK 上打
對方回不回話回：第 9 拍拉低＝收到不回：送了就算MAX7219 不回
多掛一顆要付什麼那一顆要有不同的位址多 24 位元、多 30 µs；中間一顆壞了，後面全收不到（資料要經過每一顆）多一條 CS 線

11 三顆燈，印出真的送出去的位元組

要做什麼：一步一步改三顆的顏色，每一步印出你寫的 (r, g, b)，和 np.buf——MicroPython 的 neopixel 模組放顏色的緩衝區（三色燈照 G R B 排），write() 送上線的就是這 9 個位元組。

跑起來會看到（實跑原文，W11）：

要做什麼：16 顆排成一圈，彩虹每 0.1 秒轉一格。程式跟套件的三顆幾乎一樣，只有 NUM = 16。每色最大只給 80（不給到 255），16 顆一起亮比較省電（第④段）。

# 10 環形燈彩虹：16 顆單線 RGB 燈排成一圈，還是只接一支腳（GPIO26）
# 套件只有 3 顆燈；16 顆的環形燈只在 Wokwi 上有，程式寫法完全一樣，只是 NUM 從 3 變 16。
# 16 顆 × 24 位元 = 384 位元，一次 write() 全部排隊送出去；第 1 顆留前 24 位元，其餘往下傳。
from machine import Pin
import neopixel
import time

NUM = 16                                  # 環上有幾顆
BRIGHT = 80                               # 每色最大給 80（0–255）：16 顆一起亮，別給到 255
ring = neopixel.NeoPixel(Pin(26), NUM)    # 跟套件同一支腳：GPIO26（板面 IO16）


def wheel(h):
    """色相 0–359 → (r, g, b)：紅 → 綠 → 藍 → 紅 繞一圈，每色最大 BRIGHT"""
    h = h % 360
    up = BRIGHT * (h % 120) // 120        # 這一段要變亮的那個顏色
    down = BRIGHT - up                    # 這一段要變暗的那個顏色
    if h < 120:
        return (down, up, 0)              # 紅 → 綠
    if h < 240:
        return (0, down, up)              # 綠 → 藍
    return (up, 0, down)                  # 藍 → 紅


print('環形燈彩虹：', NUM, '顆，一支腳 GPIO26，每 0.1 秒轉一格')
step = 0
while True:
    for i in range(NUM):
        ring[i] = wheel((i + step) * 360 // NUM)   # 第 i 顆的顏色：彩虹排一圈，再往前推 step 格
    ring.write()                                    # 到這一刻才把 384 位元送出去
    if step % NUM == 0:                             # 每轉完一圈印一次：環上四個方位的燈（16 顆時是第 0、4、8、12 顆）
        print('第', step // NUM + 1, '圈', ring[0], ring[NUM // 4], ring[NUM // 2], ring[3 * NUM // 4])
    step += 1
    time.sleep(0.1)

from machine import Pin, ADC

import time

NUM = 16
knob = ADC(Pin(34), atten=ADC.ATTN_11DB)   # 套件可變電阻 GPIO34（板面 IO2）；11 dB 才量得到整段 0–3.3 V
ring = neopixel.NeoPixel(Pin(26), NUM)     # 跟套件同一支腳：GPIO26（板面 IO16）

GREEN = (0, 80, 0)
YELLOW = (80, 60, 0)
RED = (80, 0, 0)
OFF = (0, 0, 0)


def color_of(i):
    """第 i 顆亮的時候是什麼顏色：0–9 綠、10–12 黃、13–15 紅"""
    if i < 10:
        return GREEN
    if i < 13:
        return YELLOW
    return RED


print('旋鈕決定亮幾顆：raw 0 到 4095 → 0 到 16 顆')
last = -1
while True:
    raw = knob.read()                      # 0–4095
    n = raw * NUM // 4095                  # 換算：轉到底 4095 → 16 顆
    # Wokwi 的旋鈕轉得到 4095；真旋鈕常到不了端點，W10 真板要校正上限（把 4095 換成實際量到的最大值）
    for i in range(NUM):
        ring[i] = color_of(i) if i < n else OFF
    ring.write()                           # 16 顆的顏色一次送出去
    if n != last:                          # 顆數變了才印，不然會洗版
        print('raw', raw, '→ 亮', n, '顆')
        last = n
    time.sleep(0.1)

13 8×8 矩陣畫愛心

要做什麼：64 顆燈的蛇形燈板，用 index(x, y) 把「第 x 欄、第 y 列（橫的一排）」換成隊伍裡的第幾顆，畫一顆愛心。

跑起來會看到（實跑原文，W13）：

(x, y) → index：(0, 0) → 0  (7, 0) → 7  (0, 1) → 15  (7, 1) → 8
愛心畫好了：亮 27 顆

試著改：SERPENTINE = False：電路還是蛇形，所以奇數列會左右翻，愛心的第 1、3、5 列歪掉——這是故意讓你看錯的樣子（第⑥段把兩個選單弄成不一樣，就是這個畫面）。

看一眼 main.py／diagram.json
# 13 8×8 單線燈矩陣畫愛心：64 顆燈還是排成「一條隊伍」，只是隊伍折成 8 列
# 位置用「第 x 欄、第 y 列（橫的一排）」來說；大部分買得到的燈板是蛇形接法（serpentine）：
# 第 0 列由左往右，第 1 列折回來由右往左，再折回來……
# 所以第 x 欄、第 y 列不是直接 y*8+x，要用 index(x, y) 換算成隊伍裡的第幾顆。
from machine import Pin
import neopixel
import time

W, H = 8, 8
SERPENTINE = True                          # 試著改成 False：電路還是蛇形，所以奇數列會左右翻——這是故意讓你看錯的樣子
mat = neopixel.NeoPixel(Pin(26), W * H)    # 跟套件同一支腳：GPIO26；64 顆 × 24 位元 = 1536 位元
RED = (80, 0, 16)                          # 亮度給小一點：64 顆一起亮很耗電

HEART = [                                  # 7 格寬、靠左放：左右不對稱，排錯了一眼看得出來
    '........',
    '.##.##..',
    '#######.',
    '#######.',
    '.#####..',
    '..###...',
    '...#....',
    '........',
]


def index(x, y):
    """第 x 欄（0–7，左到右）、第 y 列（0–7，上到下）→ 隊伍裡的第幾顆"""
    if SERPENTINE and y % 2 == 1:
        return y * W + (W - 1 - x)         # 奇數列折回來：由右往左
    return y * W + x                       # 偶數列：由左往右


print('8×8 矩陣愛心：蛇形接法', SERPENTINE)
print('(x, y) → index：(0, 0) →', index(0, 0), ' (7, 0) →', index(7, 0),
      ' (0, 1) →', index(0, 1), ' (7, 1) →', index(7, 1))
for y in range(H):
    for x in range(W):
        mat[index(x, y)] = RED if HEART[y][x] == '#' else (0, 0, 0)
mat.write()                                # 64 顆的顏色一次送出去
lit = sum(row.count('#') for row in HEART)
print('愛心畫好了：亮', lit, '顆')
while True:
    time.sleep(1)

四個專案都在 Wokwi 實跑過（無頭瀏覽器、沒登入、沒存檔）：開機、序列埠沒有錯誤訊息，燈色用兩條路讀回來跟程式算的一樣（W10–W13）。沒在真板跑過。

想看更深：三個真的拿來用會遇到的事

燈多了，電源要另外接、地要接在一起

幾十顆以上，別靠開發板供電：另外接 5 V 電源供應器（大小照第④段算出來的電流挑），而且電源的 GND、燈的 GND、ESP32 的 GND 要接在一起，不然資料線的 0 和 1 沒有共同的基準。接線時先接地、再接 5 V、最後接資料線（A2）。

3.3 V 的腳，叫得動 5 V 的燈嗎？

舊版資料表要求資料線的「1」至少是燈電源的 0.7 倍（P17）：燈接 5 V 時要 3.5 V，ESP32 的腳只有 3.3 V，差一點點。很多人照接也能用，但不保證；常見做法是加一顆電位轉換晶片。⚠️ 套件上那三顆怎麼供電，本頁沒查；套件程式上學期在真板跑過（K2）。

接力只慢一點點

每顆把資料從 DIN 傳到 DOUT，最多慢 0.3 µs（P18），而且每顆都會把波形重新整形（P12），所以串很長也不會愈傳愈糊。真正花時間的是「每顆 24 位元」本身：第④段算的就是這個。

數字從哪裡來

頁面上每個數字都有出處，編號跟頁面裡的小標籤一樣（點小標籤會跳到這裡）。官方英文照原文引，旁邊是白話。標 ⚠️ 的是版本會變、或本頁沒驗證的。編號跟〈腳位怎麼講話實驗台〉同一件事用同一個號碼。

這一頁的簡化

  • 簡化：波形只畫 0 和 1 兩種電壓、直角轉換。
  • 簡化：接力圖把「每顆轉傳慢 0.3 µs」省略，每一排的同一格畫在同一個時間（P18）。
  • 簡化：畫面上的燈色放大到看得清楚，不代表真的亮度；例如 (10, 20, 30) 真的燈很暗。
  • 簡化：電流照「亮度幾成、電流幾成」直線估算，每顆全白抓 60 mA 是保守的估電源算法（⚠️ 不是量測值）。
  • 簡化：送完後停在低電位的時間一律保守抓 300 µs（新版 V5 要 > 280 µs；舊版資料表 ≥ 50 µs，投影片寫的是這個，P11、P11b）。
