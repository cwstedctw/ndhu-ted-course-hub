腳位怎麼講話實驗台

把一個字、一個顏色拆成一串 1 和 0——三種約定：I2C、單線燈、SPI

一支腳位一次只能說 1 或 0。要把「A」送進螢幕，就把它拆成一串 1 和 0，再約好：誰先講、在哪一刻看、一次幾個位元、聽的人怎麼回「收到」。8 個位元排成一組，叫位元組（byte）。I2C 用兩條線：一條送資料，一條打拍子——打拍子的那條叫時脈（clock）；開頭先喊對方的位址（address），像喊門牌。SPI 用四條線，不喊門牌，改用一條晶片選擇（CS，chip select）線點名。單線燈只有一條線，靠高電位多長分 0 和 1，排隊的燈一顆吃掉一份、剩下的往下傳。

這一頁在做什麼

上週學了一支腳位怎麼表達「多少」；這一頁學幾支腳位怎麼「說一句話」給另一顆晶片聽。三個分頁並排三種講法：① 兩條線的 I2C（套件的 OLED 小螢幕）、② 一條線的單線燈（套件的三顆 RGB 燈）、③ 四條線的 SPI（套件沒有，用 Wokwi 的 8×8 點陣對照）。左邊可以動、看慢動作波形，右邊是那一步對應的程式（亮的那一行）和序列埠印出來的字；每個分頁都配一支 Wokwi 程式，在下面的動手卡複製、貼上就能自己跑。

姊妹頁：〈讀旋鈕、調亮度實驗台〉（第三頁「接起來」的旋鈕讀數，這週把它放上螢幕）、〈ESP32 腳位透視鏡〉（腳位當輸出、輸入；I2C 兩條線「只拉低、一放手就靠上拉電阻回到 1」，在它的開汲極情境看過）

先喊位址，對方在第 9 拍回「收到」，才接著送。

SDA 送資料、SCL 打拍子：SDA 只在 SCL 是 0 的時候換，SCL 變成 1 的那一刻，聽的人看一次。每送完一個位元組，被喊到的那顆在第 9 拍把 SDA 拉低，回一聲「收到」，叫確認（ACK）。

送一個字：A–Z、0–9（小寫會換成大寫；這一頁只放了這些字的字型）。

「A」在 ESP32 記憶體裡

左邊＝第幾個位元（bit 0 在最上面，M7）；上面＝第幾欄。

OLED 小螢幕 128×64：收到一欄，亮一欄

虛線框＝左上角那 8 欄（第 0 頁、第 0–7 欄），這一頁把字放在這裡；一個位元組填一整欄 8 個點（P9）。

掃描：從 0x08 喊到 0x77，每個位址喊一次（M2）

oled.text() 只是在 ESP32 自己的記憶體裡畫；oled.show() 才把整個畫面送過去（M4）。所以程式先畫完、再 show() 一次就好。

套件那三顆 RGB 燈（K2），每顆都能單獨指定顏色，叫可定址 RGB 燈（WS2812／NeoPixel）。只有一條資料線、沒有拍子：每位元 1.25 µs，高電位短是 0、長是 1。第一顆留下最前面 24 位元，其餘往下一顆傳。

快選

72 位元：每顆 24 位元，G、R、B 各 8 位元，高位先送（P10）

你寫 (r, g, b)，驅動幫你排成 G、R、B 再送（M10）。黃色＝正在送的那一位；淡的＝還沒送到。

np[i] = (r, g, b) 只改 ESP32 記憶體裡的數字；np.write() 才把 72 位元送上線（M9）。跟螢幕的 show() 是同一個道理。

SPI 不喊位址：要跟誰講，就把它的 CS 拉低；SCK 打拍子、MOSI 一拍送一個位元。MAX7219 一次聽 16 位元：前 8 位元說「寫到哪一列」（其實只看後 4 位，最前面 4 位不用）、後 8 位元是那一列的 8 個點。套件沒有 SPI 零件，這一頁在 Wokwi 做（K3）。

送一張圖

8×8 點陣：點格子開或關

虛線圈＝改了、還沒送到。右邊：那一列的 8 個點 → 封包（列號 << 8 | 資料）。

三種講法怎麼挑對象：I2C 靠位址挑人、SPI 靠 CS 那條線挑人、單線燈靠排隊的位置。

這個分頁在講這個

先喊位址，對方回「收到」

兩條線上可以掛好幾顆裝置，每顆有自己的 7 位元位址（套件的螢幕是 0x3C，P7）。開頭先送「位址＋寫」這一個位元組：0x3C 往左移一位、最後補一個 0（寫）＝0x78（P4）。

每個位元組 8 位元、最高位先送（P5b），後面第 9 拍是確認：被喊到的那顆把 SDA 拉低（P5）。沒人拉低，ESP32 就知道沒人在，發「結束」、後面不送了。

想看原理

i2c.scan() 就是把 0x08 到 0x77 每個位址都喊一次：誰在位址後面把 SDA 拉低，就記進清單（M2）。開始是「SCL 是 1 時 SDA 從 1 掉到 0」、結束是「SCL 是 1 時 SDA 從 0 升回 1」（P3）；兩條線閒著的時候都是 1（P2）。

送畫面時，位址後面先跟一個控制位元組 0x40，告訴螢幕「後面是畫面資料」（0x00 則是「後面是指令」，P8）。

這個分頁在講這個

高電位多長就是 0 或 1；排隊吃位元組

沒有拍子線，就約好時間：800 Kbps，每位元約 1.25 µs（P11）。驅動送 0＝高 0.40 µs＋低 0.85 µs、送 1＝高 0.80 µs＋低 0.45 µs（M10）。

一顆燈 24 位元，順序 G、R、B，高位先（P10）。三顆串著：第一顆留下最前面 24 位元，其餘整理好從 DOUT 送給下一顆（P12）。所以你寫的順序，就是燈排隊的順序。

想看原理

72 位元送完，線上保持低電位 ≥ 50 µs，三顆才一起換成新顏色（P11）。在那之前，燈維持上一次的顏色。

np[0] = (255, 0, 0) 只改記憶體；np.write() 才送（M9）。你寫 R G B，驅動用 ORDER = (1, 0, 2, 3) 排成 G R B（M10）。

這個分頁在講這個

CS 拉低才聽，拉高才算

SPI 沒有位址：每顆一條 CS，要跟哪一顆講，就把它的 CS 拉低、其他顆放高（P13）。

MAX7219 一次收 16 位元、D15 先送：D8–D11 是暫存器位址、D0–D7 是資料；CS 拉高那一刻才把這 16 位元鎖進去（P14）。第 1–8 列的位址就是 0x1–0x8（P15）。

想看原理

一上電，MAX7219 是關機、全暗的（P15），所以 05 開機先寫五個設定：關機暫存器寫 1、不解碼、八列都掃、亮度、關掉顯示測試。按實驗台③的「開機先送五個設定」看這五個封包。

# 01 I2C 掃描：兩條線上有誰？
# I2C 只用兩條線（SCL 時脈、SDA 資料），一條線上可以掛很多顆裝置，
# 每顆裝置有自己的位址（7 位元，像門牌號碼）。ESP32 講話時先喊門牌，被喊到的那顆才回應。
# scan() 就是把 0x08 到 0x77 每個門牌都喊一遍，有人回「在」就記下來——螢幕都還沒畫，先確認它聽得到。
from machine import Pin, I2C
import time

# ESP32 的 I2C 可以指定任何一對腳位；套件 OLED 接 SCL=GPIO22（板面 IO17）、SDA=GPIO21（板面 IO18）
i2c = I2C(0, scl=Pin(22), sda=Pin(21), freq=400000)   # 400 kHz＝「快速模式」，OLED 吃得下

n = 0
print('I2C 掃描：SCL=GPIO22／SDA=GPIO21，每 2 秒掃一次')
while True:
    n = n + 1
    found = i2c.scan()                 # 回一串整數位址，沒人回應就是空的
    print('第', n, '次掃描，找到', len(found), '顆裝置')
    for addr in found:
        # 同一個位址印兩種寫法：資料手冊都寫十六進位 hex（0x3c），程式裡比大小用十進位 dec（60）
        # ⚠️ print 字串故意用英文 hex／dec：Wokwi 序列埠會把「進」「值」「、」這些字靜靜吃掉
        print('  位址 hex', hex(addr), '= dec', addr)
    time.sleep(2)

# MicroPython SSD1306 OLED driver, I2C and SPI interfaces

from micropython import const
import framebuf


# register definitions
SET_CONTRAST = const(0x81)
SET_ENTIRE_ON = const(0xA4)
SET_NORM_INV = const(0xA6)
SET_DISP = const(0xAE)
SET_MEM_ADDR = const(0x20)
SET_COL_ADDR = const(0x21)
SET_PAGE_ADDR = const(0x22)
SET_DISP_START_LINE = const(0x40)
SET_SEG_REMAP = const(0xA0)
SET_MUX_RATIO = const(0xA8)
SET_IREF_SELECT = const(0xAD)
SET_COM_OUT_DIR = const(0xC0)
SET_DISP_OFFSET = const(0xD3)
SET_COM_PIN_CFG = const(0xDA)
SET_DISP_CLK_DIV = const(0xD5)
SET_PRECHARGE = const(0xD9)
SET_VCOM_DESEL = const(0xDB)
SET_CHARGE_PUMP = const(0x8D)


# Subclassing FrameBuffer provides support for graphics primitives
# http://docs.micropython.org/en/latest/pyboard/library/framebuf.html
class SSD1306(framebuf.FrameBuffer):
    def __init__(self, width, height, external_vcc):
        self.width = width
        self.height = height
        self.external_vcc = external_vcc
        self.pages = self.height // 8
        self.buffer = bytearray(self.pages * self.width)
        super().__init__(self.buffer, self.width, self.height, framebuf.MONO_VLSB)
        self.init_display()

    def init_display(self):
        for cmd in (
            SET_DISP,  # display off
            # address setting
            SET_MEM_ADDR,
            0x00,  # horizontal
            # resolution and layout
            SET_DISP_START_LINE,  # start at line 0
            SET_SEG_REMAP | 0x01,  # column addr 127 mapped to SEG0
            SET_MUX_RATIO,
            self.height - 1,
            SET_COM_OUT_DIR | 0x08,  # scan from COM[N] to COM0
            SET_DISP_OFFSET,
            0x00,
            SET_COM_PIN_CFG,
            0x02 if self.width > 2 * self.height else 0x12,
            # timing and driving scheme
            SET_DISP_CLK_DIV,
            0x80,
            SET_PRECHARGE,
            0x22 if self.external_vcc else 0xF1,
            SET_VCOM_DESEL,
            0x30,  # 0.83*Vcc
            # display
            SET_CONTRAST,
            0xFF,  # maximum
            SET_ENTIRE_ON,  # output follows RAM contents
            SET_NORM_INV,  # not inverted
            SET_IREF_SELECT,
            0x30,  # enable internal IREF during display on
            # charge pump
            SET_CHARGE_PUMP,
            0x10 if self.external_vcc else 0x14,
            SET_DISP | 0x01,  # display on
        ):  # on

試試看：五個問題

① 螢幕的位址改成 0x3D，會怎樣？

螢幕什麼都收不到。程式還在喊 0x3C：位址位元組送完，第 9 拍沒人把 SDA 拉低（P5），ESP32 就發「結束」、後面不送了。改法有兩個：程式寫 SSD1306_I2C(128, 64, i2c, addr=0x3D)，或把螢幕改回 0x3C（P7）。

② 「B」這個字，第二欄是哪個位元組？

0x7F＝127。字型裡的「B」是 0x00、0x7F、0x7F、0x49、0x49、0x7F、0x36、0x00；第二欄 0x7F＝0111 1111，bit 0 在最上面（M7），所以那一欄上面 7 個點都亮、最下面一個暗。

③ 三顆燈只寫 np[0]、不寫 write()，燈會變嗎？

不會。np[0] = … 只改 ESP32 記憶體裡那 3 個數字；np.write() 才把 72 位元送上線（M9）。跟 oled.show() 同一個道理：先改記憶體，再一次送出去。

④ 想讓第三顆亮紅，72 位元裡哪 8 格要是 1？

第 57–64 格。第三顆吃最後 24 位元，也就是第 49–72 格（P12）；順序 G、R、B（P10）：G 在 49–56、R 在 57–64、B 在 65–72。紅＝(255, 0, 0)，所以 R 那 8 格全是 1，其餘都是 0。

⑤ 點陣只想亮最上面一列，要送哪一個 16 位元封包？

0x01FF。前 8 位元 0x01＝第 1 列（後 4 位 0001 是列號；P15），後 8 位元 0xFF＝8 個點全亮：0000 0001 1111 1111，CS 拉高那一刻才算（P14）。其他七列要是原本有亮，也得各送一個資料是 0x00 的封包。

想看更深：五個小問題

兩條線，怎麼讓很多顆共用？

I2C 上的每一顆都只會做兩件事：把線拉到 0，或放手。放手的時候，上拉電阻把線拉回 1，所以 SDA、SCL 兩條都要接上拉電阻，模組板上常常已經有了（M3）。沒人講話時兩條線都是 1（P2）；誰拉低，大家都看得到——第 9 拍回「收到」，就是被喊到的那顆把 SDA 拉低。這種「只拉低、不推高」的接法，在〈ESP32 腳位透視鏡〉的開汲極情境看過。

老師選用：用邏輯分析儀看真的波形

Wokwi 有一個 8 通道的邏輯分析儀零件 wokwi-logic-analyzer（D0–D7、1 GHz）。把 SDA、SCL（或單線燈的資料線）接到它的通道，跑一下再停止模擬，瀏覽器會下載一個 wokwi-logic.vcd；用 PulseView 打開，能直接把 I2C、WS2812 的位元解出來（W4）。這一頁的慢動作波形，就是它看到的東西放慢。

SPI 還要約好什麼？

除了 CS，SPI 還要約好兩件事：時脈閒著的時候是 0 還是 1、在時脈的哪一個邊看資料——就是 05 裡的 polarity=0, phase=0，有些文件叫 CPOL／CPHA。兩邊約定不一樣，收到的位元就會錯開一格。

MOSI、MISO 的新名字

有些新的文件把 MOSI 改叫 PICO、MISO 改叫 POCI（P13）；MicroPython 的 SPI 參數還是寫 mosi=、miso=，05 就是這樣寫。MAX7219 不回話，所以 05 的 MISO 隨便接一支空腳 32。

ESP32 有幾組 I2C、SPI？

硬體 I2C 有兩組，編號 0 和 1，能輸出的腳都能當 SCL、SDA（M1）。能用的硬體 SPI 也是兩組：HSPI＝1、VSPI＝2（P16）；也能改接別的腳，只是不在預設腳時最高 40 MHz（M8）。單線燈一位元只有 1.25 µs，程式一行一行開關腳位來不及，所以 neopixel 模組交給 ESP32 裡專門發脈衝的硬體去送（M9）。

這一頁的簡化

  • 簡化：波形畫成慢動作。真實速度下，I2C 一拍 2.5 µs（400 kbit/s）、單線燈一位元 1.25 µs、05 的 SPI 一拍 1 µs（1 MHz），眼睛看不到；這一頁一拍放慢到零點幾秒（拉桿可以調）。
  • 簡化：I2C 一次只示範送一個字：位址、控制各 1 個位元組，加上 8 欄，共 10 個位元組。真的 oled.show() 會先送幾個設定指令，再一口氣送整個畫面 1024 個位元組（M4）。
  • 簡化：字畫在螢幕左上角第 0–7 欄；真的 oled.text() 可以畫在任何位置、一次畫好幾個字。
  • 簡化：單線燈的脈衝寬度用驅動實際送的數字 0.40／0.85／0.80／0.45 µs（M10）；資料表允許每一段差 ±150 ns。
  • 簡化：SPI 點陣在套件上沒有，只在 Wokwi 做（K3）。這一頁照 05 的畫布畫：第 1 列在最上面、最高位元在最左；Wokwi 實跑畫出來跟程式裡的圖逐點相同、不旋轉（W6）。
  • 簡化：「別的裝置 0x68」是示意，套件上沒有。
  • 簡化：波形只畫 0 和 1 兩種電壓、直角轉換；真的線有上升時間，上拉電阻愈大、升得愈慢。I2C 的 SDA 也只畫一條線，不分是誰在拉低。
  • 簡化：程式每一行都當成一瞬間做完；序列埠只印程式 print() 的那幾行，而且只在按了對應的鈕才印（自己拉的顏色、自己點的格子，程式裡沒有那一行 print，就不印）。
  • 簡化：MAX7219 的亮度（05 設 3）這一頁不畫明暗；關機、顯示測試、掃描列數有畫。
