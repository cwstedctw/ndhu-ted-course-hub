讀旋鈕、調亮度實驗台

旋鈕、光感測器怎麼變成數字（ADC）；數字怎麼控制燈、蜂鳴器、馬達（PWM）

ESP32 的腳位平常只認 1 和 0。要讀「中間值」，得把電壓切成 4096 格、看它落在第幾格；要送「中間值」，得用很快的開、關比例騙過燈和耳朵。只有 1 和 0 兩種值，叫數位（digital）；可以停在中間任何一點，叫類比（analog）。把電壓換成格子上的數字，叫類比數位轉換（ADC）；用開、關的時間比例假裝中間值，叫脈衝寬度調變（PWM）。旋鈕從頭轉到底＝電壓 0 到 3.3 V＝數字 0 到 4095；燈的平均光量＝開的時間佔幾成（眼睛覺得多亮不是一直線，第二頁有）。

這一頁在做什麼

前幾週的燈只有開和關、按鈕只有 1 和 0；這一頁第一次碰「中間值」：旋鈕轉到一半，程式讀到多少？燈要半亮，程式送出去的又是什麼？三個分頁依序是①讀進來、②送出去、③接起來做旋鈕調亮度，左邊可以動，右邊是正在跑的程式（亮的那一行）和序列埠印出來的字。每個觀念都配一支在 Wokwi 實跑過的程式，在下面的動手卡複製、貼上就能自己跑。

輸入範圍檔位（真板才會遇到）

程式裡的 pot.atten(ADC.ATTN_11DB) 選的是「輸入範圍檔位」。真板的 ADC 有四個檔位，各自量得準的電壓範圍不一樣（A9）。選一個檔位，上面的電壓尺會畫出真板量得準的那一段，範圍外塗灰。

頭尾都不準：100 mV 以下都讀成 0；11 dB 這一檔讀數超過 3000（大約 2.45 V）以上，就沒有官方表上那麼準（A10）。每顆晶片也不太一樣（A12）。不管哪一檔，輸入腳都別超過 3.6 V，靠近它就可能燒壞晶片（A13）。

Wokwi 不管哪一檔，都是 0–3.3 V 一直線對 0–4095（W2），所以模擬器裡看不到這件事；真板才會遇到。沒寫檔位的時候，MicroPython 原始碼用的是 11 dB，但文件沒寫（A8）；程式裡寫清楚最保險。

為什麼套件把旋鈕和光感測器放在 34 和 39？那幾支腳屬於 ADC1。另一組 ADC2（GPIO0、2、4、12–15、25–27）Wi-Fi 也要用，Wi-Fi 開著的時候讀它會出錯（A2、A3）。34–39 只能當輸入、沒有內建上下拉（K1）。前一步：〈ESP32 腳位透視鏡〉切到輸入、接法選「可變電阻分壓」，看同一個電壓被讀成 1 或 0。

「程式多久讀一次」跟 W4〈計時器與中斷實驗台〉的「看一眼按鈕」是同一件事：程式讀的那一刻才知道現在是多少；讀完去睡，這中間旋鈕怎麼轉，它都不知道。所以右邊的序列埠一行一行跳，不會跟著你的手連續走。

腳位還是只能開或關，只是開關得很快。一秒開關幾次，叫頻率（frequency）；每一次開的時間佔一個週期的幾成，叫工作週期（duty cycle）。同一招控制三種零件：燈看工作週期（亮度）、蜂鳴器看頻率（音高）、伺服馬達看脈衝寬度（角度）。選一個零件，拉下面的拉桿。

解析度跟頻率打架

頻率愈高，一個週期能分的格數愈少（P2）。ESP32 用 80 MHz 的時脈數格子：80 MHz ÷ 頻率＝一個週期能數幾格，取 log₂ 就是位元數，上限 20（P6）。

現在：1000 Hz → 80,000 格 → 16 位元

頻率也不一定剛好：要 1000 Hz 實際 998、要 30000 Hz 實際 30030；改了參數，下一個週期才生效（P7）。

什麼時候用：腳位只會開、關，你又想要燈有亮暗、蜂鳴器有音高、伺服馬達轉到某個角度的時候。燈用幾 Hz 沒有權威規定，官方範例用 1、4、5 kHz，本課用 1 kHz（P9）；程式沒寫頻率就是 5 kHz、工作週期 50%（P4）。

類比和數位：連續的電壓、一格一格的晶片

外面的世界是連續的：旋鈕可以停在任何角度，電壓可以是 0 到 3.3 V 之間任何一點。晶片只認格子：類比數位轉換做的事，就是把這個電壓放到最近的那一格，回傳格子的號碼。

pot.read() 回傳 0–4095（A4）；pot.read_u16() 把同一個讀數換到 0–65535 這把各家板子共用的尺（A5）。

想看原理

ESP32 裡有兩個 12 位元的類比數位轉換器，可以量 18 支腳（A1）。read_u16() 在 12 位元時的換算，是把讀數往左移 4 位、再把最高的 4 位補到最右邊：raw << 4 | raw >> 8。Wokwi 實跑 raw 2050 → 32808（A5）。

01 印的電壓用 3.3 * raw / 4095 算，這是簡化：Wokwi 這樣算剛好對，真板每顆晶片不一樣，要準就用 read_uv()（見下面「想看更深」）。

這個分頁在講這個

解析度：把 3.3 V 切成幾格

12 位元＝4096 格＝一格約 0.8 mV；10 位元是 1024 格、一格約 3.2 mV。格子愈多愈細，但真板有雜訊，最後幾格會抖（A11），多量幾次取平均比較穩。

③ 的「乘 16」就是換尺：讀進來是 0–4095 的尺，duty_u16() 要的是 0–65535 的尺。4095 × 16 ＝ 65520，差一點點到不了頂。

想看原理

PWM 也有解析度：一個週期能分成幾格。頻率愈高，格子愈少：1 kHz 最多 16 位元、5 kHz 13 位元、10 kHz 12 位元（P6）。所以「解析度」在讀進來、送出去兩邊都會碰到，意思一樣：能分成幾格。

這個分頁在講這個

PWM 不是真的中間電壓

腳位仍然只有開、關兩種電壓，只是開關得很快；燈和眼睛、蜂鳴器和耳朵、伺服馬達裡的電路，把它「平均」掉。官方的說法是在數位腳位上做出「假的類比輸出」（P1）。示波器上那條虛線是平均電壓＝工作週期 × 3.3 V。要真的中間電壓，得靠數位類比轉換，或接電阻＋電容把它磨平。

想看原理
  • 燈看工作週期（亮度）；頻率只要夠快、眼睛看不出閃就好（大約 48–60 Hz 以上，E1）。
  • 蜂鳴器看頻率（音高，W6）；工作週期影響音色。
  • 伺服馬達看脈衝有多寬：Wokwi 實跑 544 µs＝0°、1500 µs＝93°、2400 µs＝180°；頻率在 40–400 Hz 內，角度只看脈衝寬度（W5）。

01 讀可變電阻

要做什麼：ADC(Pin(34)) 讀旋鈕，每 0.5 秒印一行：raw（0–4095）、read_u16()（0–65535）、電壓、百分比。

跑起來會看到：電路預設旋鈕在中間（位置 512；Wokwi 的位置是 0–1023，不是電壓，W1），實跑印 raw 2050 u16 32808 電壓 1.65 V 50%。實跑五個位置 0／256／512／768／1023 讀到 0／1025／2050／3074／4095，一直線到底；用滑鼠拖旋鈕，讀數跟著變。

試著改：最後一行 time.sleep(0.5) 改成 time.sleep(2)，快速轉旋鈕，序列埠還跟得上你的手嗎？

看一眼 main.py
# 01 讀可變電阻：ADC 把 0–3.3 V 的電壓變成 0–4095 的整數。
# 4095 = 2 的 12 次方減 1，所以叫「12 位元」：電壓被切成 4096 格。
# 旋鈕轉到底就是 4095、轉到頭就是 0，中間照比例。
from machine import ADC, Pin
import time

pot = ADC(Pin(34))              # 套件可變電阻 GPIO34（板面 IO2）：只能輸入、沒有內建上下拉
pot.atten(ADC.ATTN_11DB)        # 輸入範圍檔位 11 dB：把量測範圍拉到最寬（官方文件寫 150 mV–2450 mV；Wokwi 實跑是 0–3.3 V 線性對 0–4095，見 README）
pot.width(ADC.WIDTH_12BIT)      # 12 位元 0–4095（ESP32 預設就是 12 位元，寫出來是讓「4095 從哪來」有跡可循）

print('旋鈕讀數：raw / read_u16 / 電壓 / 百分比')
while True:
    raw = pot.read()            # 0–4095，ADC 直接給的數字
    u16 = pot.read_u16()        # 同一個位置換成 0–65535 的尺（MicroPython 各家板子共用的尺）
    volt = 3.3 * raw / 4095     # 簡化換算：滿刻度當 3.3 V，兩位小數
    pct = 100 * raw // 4095
    print('raw', raw, ' u16', u16, ' 電壓 %.2f V' % volt, ' %d%%' % pct)
    time.sleep(0.5)

02 光感測器小夜燈

要做什麼：ADC(Pin(39)) 讀光感測器，讀數大於 1500 就算暗、開紅燈。

跑起來會看到：電路預設 400 lux，實跑印 亮 raw 1123、紅燈不亮。實跑五種亮度：1 lux 讀 3938、10 lux 3413、100 lux 2045（這三個都算暗、紅燈亮），400 lux 1123、10000 lux 156（算亮）：愈暗，讀數愈大。

試著改：diagram.json 裡光感測器的 "lux": "400" 改成 "100" 再跑，印出來變成什麼？紅燈呢？

看一眼 main.py
# 02 光感測器小夜燈：模組的 AO 腳是「LDR 串 10 kΩ」的分壓，電壓隨亮暗變。
# 暗 → LDR 電阻大 → AO 電壓高 → 讀數大；亮 → 讀數小（Wokwi 文件的表是 5 V 供電：0.1 lux 4.96 V、10000 lux 0.19 V；接 3.3 V 照比例縮小）。
# 讀數超過門檻就開紅燈；門檻是實跑三種亮度後挑的（見 README）。
from machine import ADC, Pin
import time

ldr = ADC(Pin(39))              # 套件光感測器 GPIO39（板面 IO1）：只能輸入
ldr.atten(ADC.ATTN_11DB)        # 範圍拉到最寬，跟 01 一樣
red = Pin(16, Pin.OUT)          # 套件紅燈 GPIO16（板面 IO4）

DARK = 1500                     # 門檻：讀數比它大就當「暗」。Wokwi 實跑：100 lux 讀 2045、400 lux 讀 1123，門檻放中間（見 README）

print('小夜燈：讀數超過', DARK, '算暗，紅燈亮')
while True:
    raw = ldr.read()
    if raw > DARK:
        red.value(1)
        state = '暗'
    else:
        red.value(0)
        state = '亮'
    print(state, ' raw', raw)
    time.sleep(0.5)

03 呼吸燈

要做什麼：PWM(Pin(16), freq=1000)，duty_u16 從 0 加到 65535 再減回 0，每步停 15 ms。

跑起來會看到：紅燈慢慢亮、慢慢暗。實跑每 250 ms 拍一張、連拍 10 張：Wokwi 的燈亮度在 0.46 到 0.97 之間來回，3.5 秒內兩個來回；序列埠一趟只印一行「第 N 次呼吸完成」。

試著改：WAIT = 15 改成 5，呼吸變快還是變慢？

看一眼 main.py
# 03 呼吸燈：PWM 用「開多久、關多久」的比例騙眼睛，看起來像亮度在變。
# freq=1000：每秒開關 1000 次，眼睛看不到閃、只看到平均亮度。
# duty_u16 0–65535：0 全關、65535 全開、32768 一半時間開。
from machine import Pin, PWM
import time

led = PWM(Pin(16), freq=1000)   # 套件紅燈 GPIO16（板面 IO4）
led.duty_u16(0)

STEP = 1024                     # 每步加多少：65536 / 1024 = 64 步到最亮
WAIT = 15                       # 每步停幾 ms：64 步 × 15 ms ≈ 1 秒漸亮、1 秒漸暗

print('呼吸燈：duty_u16 從 0 到 65535 再回 0')
n = 0
while True:
    for d in range(0, 65536, STEP):     # 漸亮
        led.duty_u16(d)
        time.sleep_ms(WAIT)
    led.duty_u16(65535)
    for d in range(65535, -1, -STEP):   # 漸暗
        led.duty_u16(d)
        time.sleep_ms(WAIT)
    led.duty_u16(0)
    n = n + 1
    print('第', n, '次呼吸完成')       # 一趟來回只印一行，別每步印（序列埠會被洗版）

04 旋鈕調亮度

要做什麼：讀旋鈕（0–4095），乘 16 交給 duty_u16()，每 0.2 秒印一行。

跑起來會看到：預設旋鈕在中間，實跑印 raw 2050 → duty_u16 32800，燈的亮度 0.78（不是 0.50：Wokwi 的燈照「眼睛看到的」曲線畫，W4）；轉到頭 raw 0 → duty_u16 0 燈滅，轉到底 raw 4095 → duty_u16 65520、亮度 1.00。

試著改：duty = raw * 16 改成 duty = raw * 65535 // 4095，轉到底印多少？

看一眼 main.py
# 04 旋鈕調亮度：ADC 讀進來的 0–4095，乘 16 就是 PWM 要的 0–65520。
# 輸入端（ADC）和輸出端（PWM）用的尺不同，中間只差一個換算。
from machine import ADC, Pin, PWM
import time

pot = ADC(Pin(34))              # 套件可變電阻 GPIO34（板面 IO2）
pot.atten(ADC.ATTN_11DB)
led = PWM(Pin(16), freq=1000)   # 套件紅燈 GPIO16（板面 IO4）

print('旋鈕調亮度：raw x 16 = duty_u16')

    raw = pot.read()            # 0–4095
    duty = raw * 16             # 0–65520（差 15 到不了 65535，眼睛看不出來）
    led.duty_u16(duty)
    print('raw', raw, ' → duty_u16', duty)

05 蜂鳴器吹音階

要做什麼：無源蜂鳴器（GPIO14）吹 Do 到高音 Do 八個音（262–523 Hz），每個音 0.3 秒、中間用 duty_u16(0) 休止，一輪吹完 deinit()、兩秒後再來。

跑起來會看到：序列埠依序印 Do 262 Hz、Re 294 Hz……Do 523 Hz，實跑 14 秒內完整三輪。實跑是程式自動檢查的、聽不到聲音：26 次裡有 17 次蜂鳴器有收到方波，休止的時候沒有。請自己開聲音聽一次；Wokwi 的 ESP32 第一個音可能不響（W6）。

試著改：把 NOTES 改成從高音 Do 往下排，吹出來是什麼？

看一眼 main.py
# 05 蜂鳴器吹音階：無源蜂鳴器自己不會響，要餵它一個方波；方波的頻率就是音高。
# 同一支 PWM，換 freq 就換音、duty_u16 給 50%（開一半關一半，方波最響）、duty_u16(0) 就是休止。
from machine import Pin, PWM
import time

NOTES = [('Do', 262), ('Re', 294), ('Mi', 330), ('Fa', 349),
         ('So', 392), ('La', 440), ('Si', 494), ('Do', 523)]   # Hz，中央 C 起的一個八度

round_no = 0
while True:
    buzzer = PWM(Pin(14), freq=262, duty_u16=0)   # 套件無源蜂鳴器 GPIO14（板面 IO0）；先靜音
    round_no = round_no + 1
    print('第', round_no, '輪音階')
    for name, freq in NOTES:
        buzzer.freq(freq)           # 換音高
        buzzer.duty_u16(32768)      # 50%：開始響
        print(name, freq, 'Hz')
        time.sleep(0.3)             # 每音 0.3 秒
        buzzer.duty_u16(0)          # 休止：音與音之間斷開，聽得出是八個音
        time.sleep_ms(60)
    buzzer.deinit()                 # 收掉 PWM，腳位還回去；下一輪重新建
    print('一輪吹完，deinit；兩秒後再來')
    time.sleep(2)

06 旋鈕轉伺服

要做什麼：PWM(Pin(27), freq=50)，旋鈕讀數換成角度，再換成 544–2400 µs 的脈衝寬度，用 duty_ns() 送出去。伺服馬達的 V+ 接 5 V。

跑起來會看到：預設旋鈕在中間，實跑印 raw 2050 → 角度 90，伺服轉到 90 度；轉到頭 0 度、轉到底 180 度。

試著改：把 raw * 180 的 180 改成 90，轉到底停在幾度？序列埠和擺臂會一致。進階：MAX_US = 2400 改成 2000——序列埠照樣印 180，擺臂卻只到約 141 度（W5）：程式「要」的角度跟馬達「做到」的角度不一定一樣，這就是伺服要校正的原因。

看一眼 main.py
# 06 旋鈕轉伺服：伺服馬達看的是「脈衝多寬」，脈衝多寬就轉到多少度。
# 本例用 50 Hz（每 20 ms 一個脈衝；常見 40–400 Hz 都行，角度只看脈衝寬）；脈衝寬度用 duty_ns 給（奈秒），比 duty_u16 好算。
# 0 度與 180 度對應的脈衝寬度是實跑量出來的（見 README），不同伺服會差一點。
from machine import ADC, Pin, PWM
import time

pot = ADC(Pin(34))              # 套件可變電阻 GPIO34（板面 IO2）
pot.atten(ADC.ATTN_11DB)
servo = PWM(Pin(27), freq=50)   # 套件空腳 GPIO27（板面 IO14）；套件沒附伺服，外接才有

MIN_US = 544                    # 0 度的脈衝寬度（微秒）：Wokwi 伺服實跑 544 µs → 0 度（跟 Arduino Servo 程式庫預設一樣）
MAX_US = 2400                   # 180 度的脈衝寬度（微秒）：實跑 2400 µs → 180 度；再寬也停在 180


def angle_to_ns(angle):
    us = MIN_US + (MAX_US - MIN_US) * angle / 180
    return int(us * 1000)       # 微秒 → 奈秒


print('旋鈕轉伺服：raw → 角度')
while True:
    raw = pot.read()                    # 0–4095
    angle = raw * 180 // 4095           # 0–180 度
    servo.duty_ns(angle_to_ns(angle))
    print('raw', raw, ' → 角度', angle)
    time.sleep(0.3)

Wokwi 的旋鈕讀數不抖、0–3.3 V 一直線到底（W2）；真板會抖、頭尾不準（A10、A11）。別拿 Wokwi 的數字當真板的證據。

試試看：五個問題

① 解析度切到 8 位元、旋鈕轉一半，數字是多少？

127 或 128。8 位元只有 256 格（0–255），轉一半剛好落在 127.5，兩格中間，這一頁放到 128。同一個電壓在 12 位元是 2048：格子粗了 16 倍，數字也小了 16 倍。

② PWM 頻率調到 5 Hz，燈會怎樣？

一閃一閃，看得很清楚。一秒只開關 5 次，工作週期 50% 時每次開 0.1 秒、關 0.1 秒，眼睛跟得上。頻率要到大約 48–60 Hz 以上，燈才會看起來「一直亮、只是比較暗」（E1）。

③ 工作週期 100% 跟 Pin.value(1) 有什麼不同？

對燈來說一樣：腳位一直開著，燈全亮。差別在後面：PWM 隨時可以改工作週期讓燈變暗，Pin.value() 只能開或關。反過來也要小心：已經當 PWM 用的腳位，用 Pin(16, Pin.OUT) 重建一次，PWM 就被關掉了（P8）。

④ 蜂鳴器頻率調到 30 kHz，聽得到嗎？

聽不到。頻率就是音高，愈高愈尖（W6）；30 kHz 已經高過人耳聽得到的範圍。腳位照樣一秒開關 3 萬次，只是你聽不到，這一頁到這麼高也不出聲。

⑤ 旋鈕轉到 90%，這一頁讀 3686；真板會一樣嗎？

不一定。90% 是 2.97 V。Wokwi 在 11 dB 這一檔是 0–3.3 V 一直線到底（W2），所以讀得出 3686；真板 11 dB 讀數超過 3000（大約 2.45 V）以上就不準了（A10），每顆晶片也不一樣（A12）。按下面的鈕，看 2.97 V 落在電壓尺灰色那一段。

想看更深：六個小問題

「輸入範圍檔位」到底在選什麼？

選 ADC 量得準的電壓範圍。真板四個檔位大約是：0 dB 100–950 mV、2.5 dB 100–1250 mV、6 dB 150–1750 mV、11 dB 150–2450 mV（A9）。範圍外不是讀不到，是沒有官方表上那麼準：100 mV 以下都讀成 0，11 dB 讀數超過 3000 以上變不準（A10）。旋鈕轉到底時真板讀到多少，官方沒有給確切的數字，別自己假設是 3.3 V＝4095。

read_uv() 為什麼比自己乘 3.3 準？

每顆晶片的參考電壓不一樣：設計是 1100 mV，實際從 1000 到 1200 mV 都有，晶片之間讀數差 ±6%（A12）。read_uv() 用出廠校準值把讀數換成微伏（只準到毫伏）；官方說在量得準的範圍內，它比拿 read_u16() 乘一個常數更準、更穩定（A6）。

uv = pot.read_uv()   # 微伏
print(uv // 1000, 'mV')

真板會抖：多量幾次取平均

ESP32 的 ADC 對雜訊很敏感，讀數會差很多；官方建議多量幾次，再濾波或取平均（A11）。最簡單的寫法：

total = 0
for i in range(16):
    total = total + pot.read()
raw = total // 16

Wokwi 不抖（W2），這段在 Wokwi 看不出差別；實驗台①打開「真板會抖」、再勾「取 16 次平均」，看這一頁的示意。

ADC2 跟 Wi-Fi 為什麼打架？

ADC1 在 GPIO32–39，ADC2 在 GPIO0、2、4、12–15、25–27（A2）。Wi-Fi 也要用 ADC2，Wi-Fi 開著的時候讀 ADC2 的腳會出錯（A3）。所以之後做連網的專案，類比感測器一律接 32–39；套件的旋鈕（34）和光感測器（39）本來就在 ADC1。

管 PWM 的硬體有幾路？頻率為什麼不剛好？

ESP32 最多 16 路 PWM，但只有 8 種不同頻率，其餘 8 路要跟別人同頻率（P5）。硬體用 80 MHz 的時脈一格一格數，所以頻率愈高、工作週期能分的格數愈少（P6）；頻率也不一定剛好，要 1000 Hz 實際 998。改了參數，下一個週期才生效（P7）。

建 PWM 不必寫 Pin.OUT；已經當 PWM 用的腳位，別再用 Pin(16, Pin.OUT) 重建一次，那樣會把 PWM 關掉。要改參數，用 freq()、duty_u16()，一次改好幾個用 init()（P8）。

真的類比輸出：DAC

ESP32 另有兩個 8 位元的數位類比轉換器，只接在 GPIO25、26：寫 0–255，輸出電壓＝Vref × 值 ÷ 255，Vref 大約是供電的 3.3 V（D1）。它是真的中間電壓，不是快速開關；但只有 256 階、只有兩支腳。

from machine import DAC, Pin
dac = DAC(Pin(25))
dac.write(128)       # 約 1.66 V

Wokwi 的功能表沒列 DAC，有人回報模擬器裡沒反應（D2）：這段請在真板上試。

按了播放，序列埠一個字都沒有

伺服馬達不動

這一頁的簡化

  • 簡化：Wokwi 的旋鈕讀數不抖（W2），真板會抖（A11）；「真板會抖」開關的抖動幅度是示意，不是量出來的。
  • 簡化：8 位元、4 位元是示意（ESP32 能設 9–12 位元，A7），為了讓格子粗到看得見。
  • 簡化：電阻＋電容那條磨平的線是示意，電阻、電容的大小是為了畫得清楚挑的。
  • 簡化：螢幕畫不出 30 Hz 以上的閃，這一頁 30 Hz 以上改畫平均亮度。
  • 簡化：蜂鳴器的聲音用瀏覽器做的方波近似，音色跟真的蜂鳴器不一樣；工作週期影響音色、不影響音高。
  • 簡化：電壓照 Wokwi 那條直線算（0–3.3 V 對 0–4095）；真板量得準的範圍看「輸入範圍檔位」。
  • 簡化：程式每一行都當成一瞬間做完，只有 sleep 花時間；真的板子上每一行都還要花一點時間。
  • 簡化：③ 管線上的數字即時跟著旋鈕走；真的程式要等下一次讀（04 每 0.2 秒）才會改燈。
  • 簡化：伺服那一檔換頻率時，這一頁讓脈衝寬度維持不變，只改週期。
  • 簡化：示波器是慢動作，畫面上 2 秒走完 4 個週期（2 Hz 以下照真實速度）。
