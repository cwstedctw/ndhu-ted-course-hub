計時器與中斷實驗台

程式在睡的時候，按鈕怎麼辦？

time.sleep(3) 不是「等 3 秒」，是「主程式站在這一行 3 秒，不會往下看按鈕」。一行沒做完、下一行就不會開始，這叫阻塞（blocking）；按鈕在這 3 秒裡按下去，主程式看不見。三條解法：不睡覺，改成每圈看一眼時鐘；把燈交給晶片裡自己會走的碼表，也就是計時器（timer）；把按鈕交給硬體，腳位一變就先記下來、再叫程式來處理，這叫中斷（interrupt）。主程式睡著時，先設好的計時器或中斷照樣會被叫，③④靠的就是這個。

這一頁在做什麼

上週的紅綠燈用 time.sleep() 讓三顆燈輪流亮，這一頁在那支程式上多加一顆按鈕。左邊是程式碼，正在跑的那一行會亮；右邊的時間軸一條一條畫出程式在做什麼、燈、你按的按鈕、程式有沒有看到。四個分頁是同一個紅綠燈的四種寫法，每一種都附一個可以貼進 Wokwi 自己跑的專案。

什麼時候可以這樣寫：只有一件事要做、不用理按鈕的時候，例如純粹讓燈閃。只要多了隨時可能發生的事，就別在它旁邊睡。

把 sleep(3) 拆掉。迴圈每一圈只做很短的事：看一眼按鈕、看一眼時鐘「該換燈了沒」，然後只睡 1 ms 就回來。像這樣一圈一圈輪流去看，叫輪詢（polling）。

燈序寫成一張表 plan，程式用一個數字記住現在輪到第幾列，這個數字就是它的狀態（state）；再用 since 記下這一列是幾點開始亮的，時間到了才換下一列。

按下、放開的那一瞬間，裡面兩片金屬都會彈好幾下，這叫彈跳（bounce）。所以按鈕的值一有變化，程式就記下時間；離上一次變化超過 50 ms 的那個 1 變 0，才算按下。這 50 ms 叫鎖定時間（lockout）。

燈交給晶片裡的計時器：Timer(0) 每 100 ms 叫一次 tick()，tick() 自己數還剩幾格，數到 0 就換燈（綠 30 格＝3 秒、黃 10 格＝1 秒、紅 30 格＝3 秒）。主迴圈只剩一件事：看按鈕，寫法跟②一樣。你怎麼按，燈都照自己的節奏走。

tick() 裡不 print、不建新東西。它是計時器叫的，要短；換了燈只把 changed 設成 1，這種變數叫旗標，像一個待辦記號；主迴圈看到了，再替它印字。

什麼時候用：固定節奏的事（閃燈、每隔一段時間量一次）交給計時器，主迴圈就空出來做別的。

燈故意還用 sleep 輪（主程式跟①一樣會卡住），按鈕改交給硬體：btn.irq() 設好之後，腳位每從 1 變 0 一次，就把 on_edge() 叫起來，主程式正在睡也一樣。這種被中斷叫起來的函式，叫中斷處理函式（interrupt handler）。

按下、放開都會彈，按一下常常叫它十幾、二十次，所以 on_edge() 只做一件事：把 20 ms 的一次性計時器重新啟動。最後一下過了 20 ms，confirm() 再看一次按鈕，還是 0 才算按了一次。要印出來，得等主程式醒來、跑到下一個 print，所以最下面那條有兩種勾：記住（confirm() 加一那一刻）和印出（主程式醒來、把累計數印出來那一刻）。

這個分頁在講這個

阻塞：一行沒做完，下一行不會開始

time.sleep() 是最常見的一種。睡 3 秒＝主程式在這一行站 3 秒，下面看按鈕、看感測器、換燈的那幾行全部排在後面。解法不是「睡短一點」（睡得再短，睡著的時候主程式照樣不會往下看按鈕），而是別在需要一直注意的地方睡，分頁②就是這樣改的。

這個分頁在講這個

計時器：晶片裡一顆自己走的碼表

設好時間，它自己數，到點就叫你的函式一下，不用主程式盯著。08 用它每 100 ms 數一格來換燈，09 用它做 20 ms 的確認。

想看原理

官方文件寫「The ESP32 port has one, two or four hardware timers, depending on the ESP32 device type」（ESP32 依型號有一、二或四顆硬體計時器），編號從 0 開始：Timer(0)、Timer(1)……；又寫「Virtual timers are not currently supported on this port」（ESP32 版目前不支援虛擬計時器），所以不能寫 Timer(-1)。

period 的單位是毫秒；mode 選 Timer.ONE_SHOT（只叫一次）或 Timer.PERIODIC（每隔一段時間叫一次）；被叫的函式會收到那個計時器本身，所以 08 的 tick(t) 要留一個 t。09 的 Timer(1) 設成只叫一次，當 20 ms 的確認鬧鐘。

tim0 = Timer(0)
tim0.init(period=5000, mode=Timer.ONE_SHOT, callback=lambda t:print(0))

官方範例（節錄）：5000 ms 之後叫一次，印出 0。

這個分頁在講這個

中斷：腳位一變，硬體先記下來

按鈕從 1 變 0 的那一瞬間，硬體先記下來，很快把你的處理函式叫起來，不管主程式在做什麼、有沒有在睡。處理函式要短：記一下就返回，印字這種事留給主程式。

想看原理

09 寫 btn.irq(trigger=Pin.IRQ_FALLING, handler=on_edge)：IRQ_FALLING＝按鈕從 1 變 0 的那一瞬間。官方說處理函式「must take exactly one argument which is the Pin instance」（一定要剛好收一個參數，就是那支腳位本身），09 的 on_edge(pin) 那個 pin 就是它。

腳位事件本來就是硬體發出的。預設 hard=False：硬體先記下、直譯器很快再叫你的函式，叫軟中斷；hard=True：直接在硬體中斷裡跑你的函式，這時不可以配置記憶體。

保守寫法：處理函式都保持短小；尤其 hard=True 時不可配置記憶體。官方《Writing interrupt handlers》的三句：

  1. 「Keep the code as short and simple as possible」：越短越簡單越好。
  2. 「Avoid memory allocation: no appending to lists or insertion into dictionaries, no floating point」：不要配置記憶體，不往串列加東西、不往字典插東西、不用浮點數。
  3. 「updating shared data to indicate that the interrupt has occurred, and it will return」：改一下共用的資料（主程式和處理函式都讀得到的變數），表示中斷發生過，然後就返回。

09 的 on_edge() 除了把 edges 加一，還重新啟動計時器，跟第三句不完全一樣。這支用的是預設的軟中斷，所以可以在裡面重啟計時器；別把這段直接搬去 hard=True——硬中斷處理函式只改旗標或事先準備好的變數。deb = Timer(1) 在主程式開頭就建好了，on_edge() 只是把它重新啟動，不是在中斷裡建新東西。

09 是交給主迴圈換燈時印；想在中斷之後「立刻印」又不能在處理函式裡 print，才用 micropython.schedule()：官方說那件事會被「queued for execution which will take place at a time when the heap is not locked」，意思是先排進待辦，等記憶體沒被鎖住的時候再執行。用法見下面「想看更深」。

寫法按鈕會不會漏燈準不準程式好不好讀要注意什麼什麼時候用
① sleep 版會漏：只在每一輪開頭看一眼準：照 sleep 的秒數最好讀：照順序一行一行寫睡著的時候主程式不會往下看按鈕；睡短一點只是漏得少一點只有一件事要做，例如純粹讓燈閃
② 看時鐘不睡覺本實驗的 150 ms 按鍵不會漏：約每 1 ms 看一次，遠短於這次按住的時間準：時間到的那一圈就換，最多晚 1 ms 左右要多想一步：燈序寫成表，記住第幾列、幾點開始每一圈都要很短，圈裡不能睡太久；按下、放開的彈跳都要擋大多數小專案：同時顧燈、按鈕、感測器
③ 燈交給計時器本實驗的 150 ms 按鍵不會漏：主迴圈仍是每 1 ms 輪詢（寫法同②），只有燈脫鉤了準：晶片裡的碼表自己數，不受主迴圈影響燈的邏輯搬進 tick()，要記得它隨時會被叫tick() 要短：不 print、不建新東西；不能用 Timer(-1)固定節奏的事：閃燈、每隔一段時間量一次感測器
④ 按鈕交給中斷本實驗的 150 ms 按鍵不會漏：主程式在睡也記得到照 sleep 的秒數（這支故意沿用 sleep）「記住」和「印出」分在兩個地方寫處理函式要短；按一下會叫它很多次，要等最後一下過了 20 ms 再確認一般按鈕先用輪詢；訊號出現的時間很短、要精確計數，或主程式沒辦法常常去看時，再考慮中斷

# 燈用 time.sleep() 一顆一顆輪；按鈕只在迴圈開頭看一眼。

from machine import Pin
import time

red = Pin(16, Pin.OUT)              # 套件紅燈 GPIO16（板面 IO4）
yellow = Pin(12, Pin.OUT)           # 套件黃燈 GPIO12（板面 IO5）
green = Pin(13, Pin.OUT)            # 套件綠燈 GPIO13（板面 IO6）

    yellow.value(0)
    green.value(0)
    light.value(1)

while True:

    only(green)
    print('綠燈 3 秒')

    only(yellow)
    print('黃燈 1 秒')
    time.sleep(1)
    only(red)
    print('紅燈 3 秒')
    time.sleep(3)

# 07 紅綠燈＋按鈕（看時鐘、不睡覺）
# 迴圈每一圈只做很短的事：看一眼按鈕、看一眼時鐘（ticks_ms）「該換燈了沒」。
# 沒有 sleep(3)，所以按鈕每 1 ms 就被看一次，幾乎不會漏。
from machine import Pin
import time

red = Pin(16, Pin.OUT)              # 套件紅燈 GPIO16（板面 IO4）
yellow = Pin(12, Pin.OUT)           # 套件黃燈 GPIO12（板面 IO5）
green = Pin(13, Pin.OUT)            # 套件綠燈 GPIO13（板面 IO6）
btn = Pin(5, Pin.IN, Pin.PULL_UP)   # 套件按鍵 A GPIO5（板面 IO11）：沒按＝1、按下＝0


def only(light):
    red.value(0)
    yellow.value(0)
    green.value(0)
    light.value(1)


# 燈序寫成一張表：(哪顆燈, 亮幾毫秒, 名字)。改順序、改時間只改表。
plan = [(green, 3000, '綠燈 3 秒'), (yellow, 1000, '黃燈 1 秒'), (red, 3000, '紅燈 3 秒')]
state = 0                           # 現在輪到表的第幾列
since = time.ticks_ms()             # 現在的燈是幾點幾分開始亮的
only(plan[state][0])

seen = 0
prev = 1
last_edge = 0                       # 上一次按鈕 0↔1 變化的時間
print('看時鐘不睡覺：按鈕每 1 ms 看一次')
print(plan[state][2])
while True:
    now = time.ticks_ms()

    # 一、看按鈕：彈跳＝一堆變化擠在 1 ms 內（按下、放開都會抖）。
    #    只有「離上一次變化超過 50 ms」的那個 1→0 才算按下；其餘變化只是把時間記下來。
    v = btn.value()
    if v != prev:
        if v == 0 and time.ticks_diff(now, last_edge) > 50:
            seen = seen + 1
            print('看到按鈕了，第', seen, '次')
        last_edge = now
        prev = v

    # 二、看時鐘：現在的燈亮夠久了嗎？夠了就換下一列
    if time.ticks_diff(now, since) >= plan[state][1]:
        state = (state + 1) % len(plan)
        since = now
        only(plan[state][0])
        print(plan[state][2])

    time.sleep_ms(1)                # 只睡 1 ms，馬上回來再看一次

# 08 燈交給計時器（machine.Timer）
# 計時器每 100 ms 叫一次 tick()，tick 自己數「還剩幾格」、到了就換燈。
# 主迴圈只剩一件事：看按鈕。燈的節奏跟按鈕互不干擾。
from machine import Pin, Timer
import time

red = Pin(16, Pin.OUT)              # 套件紅燈 GPIO16（板面 IO4）
yellow = Pin(12, Pin.OUT)           # 套件黃燈 GPIO12（板面 IO5）
green = Pin(13, Pin.OUT)            # 套件綠燈 GPIO13（板面 IO6）
btn = Pin(5, Pin.IN, Pin.PULL_UP)   # 套件按鍵 A GPIO5（板面 IO11）：沒按＝1、按下＝0


def only(light):
    red.value(0)
    yellow.value(0)
    green.value(0)
    light.value(1)


# 燈序寫成一張表：(哪顆燈, 亮幾格, 名字)。一格＝100 ms，30 格＝3 秒。
plan = [(green, 30, '綠燈 3 秒'), (yellow, 10, '黃燈 1 秒'), (red, 30, '紅燈 3 秒')]
state = 0                           # 現在輪到表的第幾列
left = plan[state][1]               # 現在的燈還剩幾格
changed = 0                         # 旗標：tick 換了燈，主迴圈看到再印字


def tick(t):
    # 計時器叫的：要短，只改幾個數字和腳位；不 print、不建新東西
    global state, left, changed
    left = left - 1
    if left <= 0:
        state = (state + 1) % len(plan)
        left = plan[state][1]
        only(plan[state][0])
        changed = 1


tim = Timer(0)                      # ESP32 的硬體計時器 0
tim.init(period=100, mode=Timer.PERIODIC, callback=tick)   # 每 100 ms 叫一次 tick
only(plan[state][0])

seen = 0
prev = 1
last_edge = 0                       # 上一次按鈕 0↔1 變化的時間
print('燈交給計時器；主迴圈只看按鈕')
print(plan[state][2])
while True:
    now = time.ticks_ms()

    # 看按鈕：只有「離上一次變化超過 50 ms」的那個 1→0 才算按下（按下、放開的彈跳都擋得住）
    v = btn.value()
    if v != prev:
        if v == 0 and time.ticks_diff(now, last_edge) > 50:
            seen = seen + 1
            print('看到按鈕了，第', seen, '次')
        last_edge = now
        prev = v

    # 計時器換了燈，主迴圈替它印一行
    if changed:
        changed = 0
        print(plan[state][2])

    time.sleep_ms(1)

④ 09 按鈕交給中斷

要做什麼：燈故意還用 sleep 輪；按鈕交給 btn.irq()，每個 1 變 0 都叫 on_edge()，再由 20 ms 後的 confirm() 確認。

跑起來會看到：每換一次燈印一行「到目前中斷記到 N 次；被叫 M 次」。在綠燈那 3 秒裡按，要等換黃燈時數字才跳上來。實跑按 8 下：記到 8 次，被叫 170 次。

# 09 按鈕交給中斷（Pin.irq）＋ 一次性計時器確認
# 按鈕 1→0 那一瞬間，硬體會把 on_edge() 叫起來——就算主程式正在 sleep 也一樣。
# 燈故意還用 time.sleep() 輪（跟 06 一樣會卡住），證明中斷不受它影響。
# 彈跳：按下、放開都會有一堆 1→0 的邊緣擠在 1 ms 內。所以 on_edge() 只做一件事——
# 啟動一個 20 ms 的一次性計時器；20 ms 後 confirm() 再看一次按鈕，還是 0 才算真的按下一次。
# 中斷處理函式要短：不 print、不建新東西（MicroPython 官方的規則）。
from machine import Pin, Timer
import time

red = Pin(16, Pin.OUT)              # 套件紅燈 GPIO16（板面 IO4）
yellow = Pin(12, Pin.OUT)           # 套件黃燈 GPIO12（板面 IO5）
green = Pin(13, Pin.OUT)            # 套件綠燈 GPIO13（板面 IO6）
btn = Pin(5, Pin.IN, Pin.PULL_UP)   # 套件按鍵 A GPIO5（板面 IO11）：沒按＝1、按下＝0


def only(light):
    red.value(0)
    yellow.value(0)
    green.value(0)
    light.value(1)


presses = 0                         # 確認過的按下次數
edges = 0                           # 中斷被叫了幾次（含彈跳，統計用）
deb = Timer(1)                      # 去彈跳用的一次性計時器（硬體計時器 1）


def confirm(t):
    # 最後一個邊緣之後 20 ms 才會跑到：按鈕還是 0 ＝ 真的按著，算一次
    global presses
    if btn.value() == 0:
        presses = presses + 1


def on_edge(pin):
    # 硬體叫的：每個 1→0 邊緣都會進來（包括彈跳）。只做一件事：重新啟動 20 ms 的一次性計時器
    global edges
    edges = edges + 1
    deb.init(period=20, mode=Timer.ONE_SHOT, callback=confirm)


btn.irq(trigger=Pin.IRQ_FALLING, handler=on_edge)   # 按鈕 1→0 就叫 on_edge

print('按鈕交給中斷；燈還是用 sleep 輪')
while True:
    only(green)
    print('綠燈 3 秒；到目前中斷記到', presses, '次；被叫', edges, '次')
    time.sleep(3)                   # 主程式在睡，中斷還醒著
    only(yellow)
    print('黃燈 1 秒；到目前中斷記到', presses, '次；被叫', edges, '次')
    time.sleep(1)
    only(red)
    print('紅燈 3 秒；到目前中斷記到', presses, '次；被叫', edges, '次')
    time.sleep(3)

Wokwi 的按鈕預設就會彈跳（官方說明：約 1 ms 內來回 10 到 100 次），實跑也看到放開的時候一樣會彈。所以 07、08 用 50 ms 的鎖定時間、09 用 20 ms 的確認把它擋掉；序列埠印出來的次數，就是擋完之後的結果。

試試看：五個問題

① 把 sleep(3) 改成 sleep(0.1)，還會漏嗎？

會，只是機率變小。一輪裡還是有大半時間在睡（黃燈那個 sleep(1) 也還在），睡著的時候主程式照樣不會往下看按鈕；你按的那一下只要整個落在睡著的時候，就看不到。睡得短，只是「剛好碰上看一眼」的機會多一點。

② 07 把 sleep_ms(1) 拿掉會怎樣？

照樣看得到按鈕，還看得更勤。少了那 1 ms，主迴圈會高速空轉、幾乎吃滿可用的處理時間，也更耗電；有設中斷的話，中斷仍會被叫。留著 1 ms 不影響反應（最多晚 1 ms 左右），卻讓晶片每圈喘一口氣。

③ 08 把 period 改 50，燈變快還是變慢？

變快。一格從 100 ms 變成 50 ms，表上的 30 格就只剩 1.5 秒，程式註解寫的「30 格＝3 秒」也跟著不對了。想讓燈速不變，表上的格數要一起改成兩倍。

④ 09 拿掉 20 ms 確認，按一下記到幾次？

一下就記好幾次。按下、放開的時候金屬片都會彈，每彈一下就是一次 1 變 0，中斷就叫一次 on_edge()；沒有確認，叫幾次就算幾次。Wokwi 實跑按 8 下，中斷被叫 170 次，確認之後剛好 8 次。這一頁把確認拿掉，看「記到」怎麼暴增。

⑤ 按住按鈕不放，四支程式各記到幾次？

①每一輪開頭看一眼，看到還按著就再算一次：按住多久，大約每 7 秒多算一次。②③只算「1 變 0」那一下，按住不放只算 1 次。④按下那幾下只觸發一次確認，按住不放也只記 1 次。

慢動作 0.5× 要看 30 秒；先把慢動作調到 2× 比較快。

想看更深：四個小問題

比時間為什麼要用 ticks_diff()，不直接相減？

ticks_ms() 是一個一直往上數的數字，數到上限就會從 0 重新數，這叫繞回。剛好跨過那一刻時，「現在 − 上一次」會變成一個很大的負數，程式就以為時間倒退了。ticks_diff(現在, 上一次) 會自己處理繞回，所以比時間一律用它。

放開按鈕也要擋？

要。07、08 的第一版只從「看到按下」那一刻起算 50 ms，Wokwi 實跑按 8 下算成 9 次；09 的第一版用 50 ms 鎖定、沒有計時器確認，實跑記到 16 次。多出來的都是放開時的彈跳：按住 150 ms 才放開，早就過了 50 ms；金屬片分開的時候又彈回去碰一下，那也是一次 1 變 0，就又算了一次。所以現在的寫法是：任何變化都重新計時（07、08），或等最後一下過了 20 ms 再確認（09）。

軟中斷、硬中斷差在哪？

腳位事件本來就是硬體發出的，差在你的函式在哪裡跑。預設 hard=False＝硬體先記下、直譯器很快再叫你的函式，這叫軟中斷（這一頁畫成「一被按就叫」，是簡化）；hard=True＝直接在硬體中斷裡跑你的函式，這時不可以配置記憶體，官方原文是「Hard interrupt handlers may not allocate memory」。初學先用預設的就好。

Pin.irq(handler=None, trigger=Pin.IRQ_FALLING | Pin.IRQ_RISING, *, priority=1, wake=None, hard=False)

官方文件裡 Pin.irq() 的完整寫法；09 只用到 trigger 和 handler 兩個。

中斷裡想印字怎麼辦？

處理函式裡只記數，印字這種重的事交給 micropython.schedule()，它會等到安全的時候再執行：

import micropython

def report(n):                     # 重的事放這裡：可以 print
    print('中斷記到', n, '次')

# 在 confirm() 裡、presses 加一之後，多寫這一行：
micropython.schedule(report, presses)

這一頁的簡化

  • 簡化：時間軸把 1 ms 畫成看得見的寬度；一瞬間就做完的那幾行（看按鈕、only()、print），畫成細線和小點。
  • 簡化：②③ 迴圈裡那幾行本身花的時間幾乎不算，一圈差不多就是 sleep_ms(1) 那 1 ms；真的板子上每一行都還要花一點時間。
  • 簡化：MicroPython 的中斷處理函式預設是軟中斷（硬體先記下、直譯器很快再叫它），這裡畫成「一被按就叫」；計時器叫 tick()、confirm() 也畫成立刻。
  • 簡化：彈跳照 Wokwi 的說法，按下、放開各在約 1 ms 內跳好幾下；時間軸上每一撮只畫幾根直線，實際被叫幾次看數字。這一頁每下跳幾次是隨機生的，跟 Wokwi 實跑的次數不會一樣。
  • 簡化：時間從程式開始跑算 0 秒；真的板子上 ticks_ms() 開機就開始數，數字會不一樣。
