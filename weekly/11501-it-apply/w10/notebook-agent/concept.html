0全景地圖：兩條路，到同一本筆記本

為什麼要懂這個：先看清楚「誰在跟誰講話」，後面每一個詞才有地方放。

點任何一個方塊（鍵盤：Tab 移動、Enter 選）

先點左邊的方塊

每一塊都有一句白話說明。建議先從左邊「手動」那一條點下來，再點右邊。

記住一句話：右邊那條路只是幫你把東西搬進去。真正要問問題、點引用回原文，還是回到左邊的網頁。
想一想：右邊那條路多了四個方塊。如果只要放一個來源，你會走哪一條？要放三十個呢？

1Gemini Notebook 是什麼

為什麼要懂這個：它只根據你給的來源回答，所以「來源放對」是後面所有事情的基礎。

Gemini Notebook（原本叫 NotebookLM）是 Google 的 AI 研究工具。它跟一般聊天 AI 最大的不同：回覆內容一律根據你提供的來源生成，而且附上編號引用，點下去可以回到原文那一句。

同一個問題，換一種方式回答：
你問
空氣品質指標（AQI）的等級變高時，我該怎麼調整戶外活動？

來源面板 示意，不是真的來源

下面四句是為了示範而編的短文，不是任何機關的公告，請不要當成真的規定。

[1]這份示意手冊把空氣品質指標分成幾個等級，每個等級配一種顏色。

[2]等級愈高，代表空氣愈不好，建議的戶外活動量也愈少。

[3]手冊提醒：敏感族群在中間的等級，就應該開始減少長時間的戶外劇烈運動。

[4]這份手冊沒有寫各等級對應的數字範圍，要查數字請看主管機關的公告。

引用對得上，只代表「這句話真的出自你給的來源」，不代表來源本身是對的。放進去的東西不可靠，回答也不會可靠。
想一想：「筆記本」那個回答的最後一句說「來源沒有寫」。一個會承認沒寫的工具，和一個什麼都答得出來的工具，寫報告時你比較敢用哪一個？為什麼？

2API 能做／還不能做

為什麼要懂這個：知道 agent 走 API 做得到哪些事，你才知道哪些要交給它、哪些一定得自己來。

API（應用程式介面）是程式跟服務講話的窗口。Gemini Notebook 的 API 目前是公開預覽階段（Public Preview），功能還不多。下面每一項，你覺得是哪一邊？

    3四個詞一次懂：用一間旅館來想

    為什麼要懂這個：agent 安裝設定時畫面上會一直出現這四個詞，看得懂才知道現在該不該按同意。

      房卡一小時就失效：玩玩看

      真實世界是 60 分鐘。這裡加速：畫面上 1 秒＝2 分鐘，大約 30 秒就過期。模擬，不會真的拿權杖

      還沒有權杖

      先按「讓 agent 送一個請求」看看沒帶權杖會怎樣，再按「拿一張權杖」。

      過期之後，agent 要做的事只有一件——重新拿一張：

      gcloud auth application-default print-access-token
      權杖就是房卡。不要印在畫面上、不要存成檔案、不要貼到聊天室。誰拿到，在它過期之前誰就能用你的名義進你的筆記本。
      想一想：一小時就過期很麻煩。但如果權杖永遠不過期，哪一種意外會變得更嚴重？

      5來源狀態：送進去不等於能用
      
  
      為什麼要懂這個：來源是送出後才慢慢處理的，「送出成功」和「真的能用」是兩回事。
      
  
      來源送進去之後先是 PROCESSING（處理中），之後變成 ACTIVE（可以用了）或 FAILED（失敗，會附原因）。有些東西連門都進不去，當場就被退回（HTTP 400）。選一種來源試試看：
      
  
      
  
      
    400 當場退回
    PROCESSING
    →
    ACTIVE
    ／
    FAILED
  
      
  
      （選一種來源，再按「送出這個來源」）
      
  
      
    
    模擬，不會真的送出
  
      
  
      
  
      所以 agent 加完來源之後，要每隔 2 秒查一次狀態，查到 ACTIVE 才算完成。只回報「已送出」不算做完。
      
  
      想一想：agent 回報「三個來源都加好了」。你要它再給你看哪一個詞，才相信真的能用？

      7監督 agent 三件事
      
  
      為什麼要懂這個：你讓 agent 在你的電腦裝東西、連你的帳號，出了事負責的是你，不是它。
      
  
      
    
      一先看計畫：動手之前請它先列出要做什麼，看過再說好。
      
    
      二登入同意只有你能按：瀏覽器跳出來的那一步，要你本人看清楚再按。
      
    
      三做完自己讀回：打開筆記本網頁，自己確認真的有、數量對。

      8MCP 一張圖：同一組功能，換一種接法
      
  
      為什麼要懂這個：MCP 只是把同樣七件事包成 agent 可以直接拿來用的工具，並沒有多出新功能。
      
  
      前面講的做法，是 agent 自己一行一行組出請求（這種「網址加動作」的呼叫方式叫 REST）。MCP 是讓 agent 把一組工具直接接上的規格：接好之後，agent 的工具箱裡就多了七個現成的工具。點任何一邊，看它對到另一邊的哪一個。
      
  
      
    
      自己組請求（REST 的七個方法）
      
    
      MCP 的七個工具
      
  
      
  
      七對七，一個不多、一個不少。
      
  
      MCP 伺服器的位置是 notebook.googleapis.com/mcp，用的是同一張權杖、同樣兩個標頭。所以權杖過期了，MCP 這邊也要重新設定；API 還不能做的事（提問、刪除、語音摘要），MCP 一樣不能做。
      
  
      想一想：左右兩邊能做的事完全一樣。那接 MCP 到底省了誰的力氣？
