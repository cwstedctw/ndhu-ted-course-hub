Kernel：板子作業系統的核心

KERNEL & MODULES回目錄

這節回答：kernel 是什麼？下半節為什麼是「載入模組」，而不是「安裝軟體」？

電腦裡的程式分兩層。最底下那層叫核心（kernel）：它是唯一能直接碰硬體（CPU、記憶體、USB 控制器、網路卡）的程式，它的地盤叫核心空間（kernel space）。其他程式——Chrome、Python、adb、轉接程式——都住在上面那層使用者空間（user space），想用硬體就得開口請 kernel 幫忙。

想像銀行：金庫（硬體）只有櫃台人員（kernel）進得去；客人（一般程式）填單子請櫃台辦。那張單子就叫系統呼叫（system call），例如 open（打開）、read（讀）、write（寫）。

驅動程式（driver）

kernel 裡專門管某一種硬體的那段程式碼。USB 攝影機、USB 網卡、LED，各有各的驅動。

模組（module，.ko 檔）

開機之後才「插」進 kernel 的驅動或功能，像外掛。插進去之後，它就是 kernel 的一部分。

/sys（sysfs）

kernel 把裝置的狀態和開關做成「檔案」給你讀寫。W3、W4 點燈用的 echo 1 > /sys/class/leds/…/brightness 就是它。

configfs（/sys/kernel/config）

跟 sysfs 很像，但專門讓你「建立」東西：mkdir 建一個功能、ln -s 把功能放進設定、echo 寫開關。今天的 USB gadget 就住在這裡。

深入一層：一行 echo 背後發生什麼

以下午會用到的 echo "" > /sys/kernel/config/usb_gadget/g1/UDC 為例：

  1. user space：shell 用 open 打開 UDC 這個「檔案」，再用 write 寫進一個空字串。到這裡都只是「填單子」。
  2. kernel：這個檔案不在硬碟上，是 configfs 做出來的。kernel 收到寫入，交給 USB gadget 的程式碼處理：「把 gadget 從 USB 控制器上拿下來」。
  3. 硬體：板子的 USB 控制器斷開，電腦那頭看到「裝置被拔掉了」。

同一個道理，W3、W4 寫 brightness 點燈，真正去扳 GPIO 的是 kernel 的 LED 驅動，不是 echo。「一切皆檔案」的意思是：檔案只是 kernel 開給你的窗口。

深入一層：什麼時候才真的要動 kernel？

能力不是「有或沒有」，是「編 kernel 的那一刻有沒有編進去」。同一塊板 〔實測 2026-07-27〕：

# NCM 網卡這一側：模組已經編好、configfs 開關有開
CONFIG_USB_F_NCM=m
CONFIG_USB_CONFIGFS_NCM=y
# UAC2 音效卡這一側：整個沒開
# CONFIG_USB_CONFIGFS_F_UAC2 is not set

所以 NCM「一行 modprobe」就有；UAC2 得照 vermagic 自己交叉編譯一顆模組（W15 的 kernel 模組 lab 走的就是這條）。今天下半節完全不用編譯、不用換 kernel。

同一份盤點也提醒：發行版的 kernel 常照抄預設值、沒為這塊板裁剪，例如板上沒有紅外線硬體，kernel 卻編好了 138 種遙控器按鍵表 〔實測 2026-07-24〕。「kernel 裡有」不代表「板子上有那個硬體」。

深入一層：容器跟 kernel 是什麼關係？

Docker 容器不是虛擬機：它共用板子的 Linux kernel，只是把行程、檔案、網路隔開 〔原始碼〕。所以在 --privileged（特權）容器裡執行 insmod，模組會進到唯一的那顆 kernel——也就是板子的 kernel。7 月的手動版就是這樣做的（用自帶 insmod 的 busybox 容器） 〔原始碼〕；本週的 hook 不用容器，由 adbd 的 systemd 服務（以 root 身分）直接 modprobe。

W5 講過：在 docker 群組裡，幾乎等於 root。板子的 arduino 帳號同時在 sudo 和 docker 群組 〔實板 10/14〕——能載模組、改 gadget，方便，也代表要小心。

2

USB：一條線、好幾個身分

USB GADGET回目錄

這節回答：一條 USB 線怎麼同時是 adb、序列埠、網卡？為什麼不能在執行中硬改它？

USB 永遠是「一主一從」。主機（host）負責發問、供電、安排誰什麼時候說話；裝置（device）只回答。攝影機插在電腦上：電腦是 host。UNO Q 插在電腦上：電腦還是 host，UNO Q 是 device。Linux 把「自己扮演 device 的那一方」叫做 USB gadget。

插上去的那一秒發生什麼？host 先問：「你是誰？你有哪些功能？」device 交出一份自我介紹，叫描述元（descriptor），裡面有：

  • VID:PID（廠商編號:產品編號）：UNO Q 正常是 2341:0078，恢復模式（EDL）是 05c6:9008 〔原始碼〕。
  • 有幾個介面（interface），每個介面屬於哪一類（class）——host 照類別去找驅動。

這整段問答叫列舉（enumeration）。重點：host 只在插上時問一次。之後想改功能組合，就得讓它「重新插一次」。

類別是什麼今天在哪
UVC（USB Video Class）標準 USB 攝影機教室電腦上的攝影機；電腦是 host
CDC ACM序列埠板子的 acm.GS0（序列監看走這條）
CDC NCM（Network Control Model）網路卡板子的 ncm.usb0，下半節加上去
UAC2（USB Audio Class 2）音效卡老師的板有 uac2.usb0（自己編的模組）；出廠板沒有
功能檔案系統（FunctionFS）把一個 USB 功能交給 user space 的程式自己實作板子的 ffs.adb，背後是 adbd

一個裝置、好幾個介面，叫複合裝置（composite device）。所以同一條線在電腦眼裡同時是 adb、序列埠、音效卡，等一下還會多一張網卡 〔實測 2026-07-27〕。老師的板接 Windows 11：裝置管理員看到一個 USB Composite Device（2341／0078），底下四個介面——ADB、序列埠、UsbNcm 網卡、音效卡 〔實板 10/14〕。這些功能在板子上的 configfs 長這樣：

/sys/kernel/config/usb_gadget/g1/
├── functions/      ← 每個功能一個資料夾：acm.GS0、ffs.adb、ncm.usb0…
├── configs/c.1/    ← 這個設定「用了哪些功能」（指向 functions/ 的捷徑）
└── UDC             ← 寫進控制器名字＝接上 USB；寫空＝拔掉

老師板上的 UDC（USB 裝置控制器，USB Device Controller）是 4e00000.usb 〔實板 10/14〕，ls /sys/class/udc 也看得到它 〔實板 10/14〕。

    USB 網卡（NCM）：下半節自己做
    USB NETWORK回目錄
    
  
    這節回答：怎麼把板子變成一張 USB 網卡？要不要改 kernel？為什麼要把設定「掛進 adbd」，而不是在執行中硬改？
    
  
    
    
    要不要改 kernel？不用。
    
    
    usb_f_ncm.ko 是 kernel 本來就編好的模組，就放在 /lib/modules/$(uname -r)/kernel/drivers/usb/gadget/function/，modprobe usb_f_ncm 就載得進去 〔實板 10/14〕。下半節裝的 hook 只做兩件事：把它載進 kernel，再把它加進 gadget 的設定。真的要動 kernel，是你要的功能根本沒編進去（像 UAC2 音效卡），或需要一個全新的驅動——那是 W15 自己編 kernel 模組那週的事。
    
  
    
  
    先認識網路上的幾個角色：
    
  
    
    
    網路卡（網路介面）

      瀏覽器攝影機與安全內容
      SECURE CONTEXT回目錄
      
  
      這節回答：板子的網頁明明打得開，為什麼一按「開始辨識」就說不支援攝影機？下半節的轉接程式在解決什麼？
      
  
      網頁要攝影機，得呼叫瀏覽器的 navigator.mediaDevices.getUserMedia()。但瀏覽器有一條硬規則：這個 API 只在「安全內容（secure context）」裡存在——也就是 HTTPS，或本機（localhost）。不符合時，瀏覽器不是「拒絕」，而是讓 navigator.mediaDevices 整個消失 〔原始碼〕。
      
  
      下半節板子變成網卡後，板子的網頁在 http://192.168.7.2:7000。直接開它：頁面載得出來，按下「開始辨識」卻跳出「這個瀏覽器不支援攝影機功能」——Chrome、Safari 都一樣 〔實測 2026-07-28〕。那句話就寫在網頁程式裡：找不到 getUserMedia 時丟出的錯誤 〔原始碼〕。

      怎麼變快
      SPEED UP回目錄
      
  
      這節回答：教室版為什麼是 8 FPS？把 8 改大會不會變快？同一顆模型怎麼跑到 20 以上？換 kernel、調 kernel 會不會變快？實際要怎麼做？
      
  
      先分清楚是哪一個 FPS。一條管線上同時有好幾個「每秒幾張」，回答的問題不一樣 〔原始碼〕：
      
  
      
    
      攝影機供幀（Camera FPS）
      攝影機實際產生幾張。暗房會被曝光時間壓低。
      
    
      傳輸（Transport FPS）
      網頁「送出速度」那格，和它下面那行小字「板子實際收到幾張」。
      
    
      AI 結果（AI FPS）
      模型每秒完成幾次推論。教室版在瀏覽器的 F12 主控台數：每一行 classification 就是一次結果 〔實板 10/14〕。
      
    
      顯示（Display FPS）
      你每秒看到幾次更新。
      
  
      
  
      教室版現況：網頁每秒送 8 張（TARGET_FPS = 8） 〔原始碼〕，板子這頭 WebSocketCamera(fps=8) 也只每秒取 8 張 〔原始碼〕。可是 AI 每秒只回 5.5 次結果 〔實板 10/14〕——那改大會不會變快？按下面兩個鈕對照 10/14 在老師板上的實測：
      
  
      
    
    
  
      
  
      
  
      ⚠️ 另一個數字：7/22 在 Mac 上用另一種數法（數 Edge Impulse 頁面每秒更新幾次）量到 AI 7.99 次/秒、每張 89 ms，當時推估「官方管線單 worker 上限約 11.2」 〔實測 2026-07-22〕；10/14 在老師板上直接把兩處改成 20，AI 只到 6.3 次/秒 〔實板 10/14〕。兩次的數法、機器都不同，來源沒有拆開比較；本週內容規格依 10/14 的實測下的結論是「送更多不會更快」。
      

  
      互動：瓶頸會移動——兩條路的階梯
      
  
      
    
    
  
      
  
      
  
      
  
      點上面任何一列。
      
  
      ⚠️ 推論毫秒數各次量到的不一樣：7/20 純推論 92 ms（同一份表格另寫「單核推論 ~98ms」）、7/22 Mac 89 ms、10/14 教室版中位 90 ms（送 8）／93 ms（送 20）、10/14 快速版每張 96–97 ms 〔實板 10/14〕。來源沒有說明差在哪，本頁照原樣列出。
      

  
      互動：FPS 計算器——誰是瓶頸？
      
  
      
    
      
      
      
        
        
      
      
      
      
        
        
        
        
        
        
      
      
      
      快選：
      
      
      
        
        
        
        
      
      
    
      
    
      
      
      
      
      
    
      
  
      
  
      計算方式：每一站各有自己的上限，整條路的上限＝最小的那一個 〔估算〕。教室版的「官方管線每秒最多回幾次」預設填 10/14 送 20 時量到的 6.3 〔實板 10/14〕；快速版的 AI 算力＝worker 數 × 1000 ÷ 單張推論毫秒。實際上增加 worker 不會永遠等比例變快，還會受 CPU、記憶體、解碼、供幀與電力限制 〔原始碼〕。
      

  
      換 kernel、調 kernel，會不會變快？
      
  
      先講結論：這條管線的瓶頸不在 kernel。7/20 的速度調查實測 CPU 已經跑在滿速 2.016 GHz、SoC 溫度 50–57°C，沒有熱節流（thermal throttling，太熱時自動降頻） 〔實測 2026-07-20〕。10/14 教室版的 runner 容器只用了 76–113% 的 CPU（四核的板子只用一核多一點），快速版跑同一顆模型用到 213% 〔實板 10/14〕——卡住的是 user space 的架構：推論只用一顆核心、官方管線一次只處理一幀。點開每一個問題：
      
  
      把 CPU 調速器（governor）改成全速，會變快嗎？幾乎不會
      
    
      調速器（cpufreq governor）是 kernel 決定「CPU 現在跑多快」的策略。老師的板：4 核，調速器是 schedutil（可以選 ondemand、userspace、performance、schedutil），9 個頻率檔從 300000 到 2016000 kHz；量的時候四核都在 1804800 kHz、thermal_zone0 是 43.7 °C 〔實板 10/14〕。schedutil 會看負載調頻率：7/20 跑 AI 時實測已經到 2.016 GHz 〔實測 2026-07-20〕，在最高檔了，改成全速也沒有空間再往上 〔估算〕。
      
    
      想自己看（唯讀）：
      
    
      # 溫度（單位是千分之一 °C）
cat /sys/class/thermal/thermal_zone*/temp
# CPU 0 的 cpufreq 有哪些檔案
ls /sys/devices/system/cpu/cpu0/cpufreq/
# 目前用哪個調速器（老師的板：schedutil）
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
      
    
      路徑出自 10/14 實板查到的 /sys/devices/system/cpu/cpu0/cpufreq/ 〔實板 10/14〕。⚠️ 改調速器要 root，本頁的來源沒有「改了之後重量 FPS」的實驗。
      
  
      
  
      是不是過熱降頻了？不是
      
    
      SoC 50–57°C、CPU 維持滿速 2.016 GHz，速度調查把「熱節流」列在實測無影響的那一欄 〔實測 2026-07-20〕。同一欄還有：輸入節流（10→30 完全沒差）、長時間執行劣化（重啟後仍 3.8）。
      
  
      
  
      改走 USB 網卡（另一個 kernel 驅動），FPS 會變高嗎？不會
      
    
      頻寬本來就不是瓶頸：教室版影像只用 35–52 KB/s 〔實板 10/14〕，USB 網卡下載 100 MB 不到 1 秒 〔實板 10/14〕。10/14 改走 USB 網卡＋轉接程式時，網頁照樣送 8.0、板子收到 8.0、AI 4.8 次/秒（走 adb 時 5.5） 〔實板 10/14〕——同一個量級。換 USB 網卡換到的是穩定（不會自己掉）和不依賴 adb。
      
  
      
  
      自己編 kernel、換一個 kernel 呢？對這題沒幫助
      
    
      編 kernel（或編模組）是為了多一個功能，例如 UAC2 音效卡。這條管線慢的原因——官方管線一次只處理一幀、攝影機曝光、單核推論——都在 kernel 之上 〔實測 2026-07-20〕。⚠️ 本頁的來源沒有任何「換 kernel 後重量 FPS」的實驗；這個結論是從瓶頸解剖推出來的。
      
  
      
  
      用 GPU 跑 AI 呢？官方還沒接通
      
    
      板上的 GPU 做通用運算（OpenCL）是可用的，但「GPU 跑 AI 推論」官方仍沒接通，兩件事別混在一起 〔實測 2026-07-24〕。
      
  
      
  
      那真正有效的是什麼？改 user space 的架構
      
    
      上面的階梯就是答案：繞過官方管線直連 .eim、用共享記憶體餵資料、開多個 worker 用上更多核心、開燈或縮短曝光讓攝影機供得上。10/14 快速版在老師板上，網頁送 20、AI 回 20.0 FPS（3 個 worker、每張 96–97 ms） 〔實板 10/14〕——這時卡住的反而是「網頁只送 20」。

      B. 快速版：直連 .eim＋多 worker（老師示範）

      D. ⚠️ 供電警告

    深入一層：吞吐量、延遲與「丟掉舊畫面」
    
      
      
      吞吐量（throughput）是每秒完成幾張；延遲（latency）是一張從拍下到你看到結果等多久。可以每秒處理很多張、卻都是一秒前的畫面——只要讓畫面排隊就會這樣 〔原始碼〕。
      
      
      攝影機（生產者）比 AI（消費者）快時，系統只能三選一：讓佇列越排越長、擋住上游、或丟掉舊畫面。下游太慢時讓上游減速的機制叫背壓（backpressure）；即時 AI 通常選「只留最新一張」 〔原始碼〕。教室版兩頭都這樣做：網頁發現還沒送出去的資料超過 512 KB 就跳過這一張 〔原始碼〕；板子這頭佇列只有 1 張，滿了就丟舊的 〔實測 2026-07-22〕。
