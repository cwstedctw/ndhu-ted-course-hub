2　桌上其實有兩台電腦

這是今天唯一要先懂的事。UNO Q 裡面有兩顆處理器，所以桌上其實是兩台電腦：

哪一邊跑什麼平常怎麼碰它
眼前這台教室的 Ubuntu鍵盤滑鼠，就是你現在用的
UNO Q 的 Qualcomm QRB2210Debian LinuxApp Lab、ADB、SSH
UNO Q 的 STM32U585Arduino sketch（Zephyr RTOS）App Lab 幫你編譯、燒錄

打之前先看提示字元

你等一下打的每一行，要先知道是打給哪一台。看游標前面那一串就知道：

你的帳號@教室電腦:~$    ← 眼前這台 Ubuntu
arduino@板子名稱:~$      ← UNO Q 裡的 Linux

App Lab 也分兩部分：電腦上有桌面程式，板子上有另一組套件。兩邊的版本號不必一樣，不要拿「主版本號相同」當相容性的判準。本課的判準是：老師指定的那一組組合、全班一致。

3　Ubuntu 三句話：我在哪、有什麼、換去哪

Linux 不會告訴你你在哪，你要自己問。三個指令就夠：

pwd      # 我在哪
ls       # 這裡有什麼
cd 名字   # 換去哪

pwd 印出來通常是 /home/你的帳號——那是你的家目錄。

教室機的家目錄不是你的私人硬碟。下課後可能會被清掉。今天寫的東西、抄的版本，存到 USB 或雲端，或者直接寫在紙本清單上。

4　軟體從哪來、sudo 是什麼

軟體從哪來

Windows 是你去網站抓一個 exe 回來裝；Ubuntu 是跟套件倉庫要。一行就好：

sudo apt install <名字>

它去學校設定好的倉庫拿，然後裝到整台機器，所有人共用。

sudo 是借權限，不是變厲害

sudo 會問密碼，因為你正在動整台機器共用的東西。判準很簡單：

動到哪裡要不要 sudo
我自己的家目錄不必
整台機器共用的東西（/etc、udev、systemd、裝軟體）要

教室機的規矩：學生先跑唯讀探針

教室機的相依套件與 USB 權限規則應該由老師或資訊組先裝好。學生不要一上來就用 sudo 改整台教室機。

起步包裡的 probe-my-setup.sh 是唯讀的：它只看，不改，一行都不會動到系統。

chmod +x probe-my-setup.sh
./probe-my-setup.sh | tee probe-normal.txt

它印三段：這台電腦是什麼、USB 上看不看得到板子、App Lab 附的 adb 在哪。有紅字或「找不到」就把 probe-normal.txt 給老師。

三條今天不准做的事：不要自己寫 USB 權限規則（尤其不要寫 0666）、不要自己重刷板子、不要自己按系統更新。這三件今天都由老師統一處理。

5　接上板子：三個看得到的證據

  1. 接線。用 USB-C 資料線把 UNO Q 直接接到電腦，不要先經過 hub。只能充電的線不算。
  2. 等心跳。LED 點陣會從旋轉的 Arduino 圖案變成心跳動畫，通常要 30～60 秒。還在轉就先等，不要拔。
  3. 證據一：USB 看得到。
    lsusb | grep -E '2341:0078|05c6:9008'
    正常開機應該看到 2341:0078。
  4. 證據二：找到 App Lab 附的 adb。ADB 不用另外裝，它在 App Lab 附的工具夾裡。整段照抄貼進終端機：
ADB=$(find "$HOME/.arduino15/packages/arduino/tools/adb" \
    -type f -name adb -perm -u+x -print 2>/dev/null | sort -V | tail -n 1)

if [ -z "$ADB" ]; then
    echo "找不到 App Lab 附的 adb，請把 probe-normal.txt 給老師"
else
    echo "本次使用：$ADB"
    "$ADB" devices -l
fi

證據三：剛好一台。上面最後一行應該列出剛好一塊板，狀態是 device。列出兩台以上就拔掉手機或別人的板子——不要讓工具去猜第一台是哪一塊。

05c6:9008 跑出來了？那是恢復模式（EDL，燒韌體時才會用到），平常不該出現。舉手叫老師，不要自己重刷。
這兩組 ID 來自 Arduino 官方 UNO Q User Manual，不是我們自己編的。

後面每一次用到 adb，都是打 "$ADB" 這四個字加引號，不是打 adb。上面那段跑過之後，這個視窗裡的 $ADB 才有值；換一個終端機視窗要重跑一次。

6　更新與抄版本

今天的更新，老師指定一條，全班跑同一條，跑完把版本抄下來。
不是每個人自己按自己的更新鈕——那樣 30 台會長成 30 種，下週誰壞了都查不出來。這就是「環境統一日」的統一。

要跑的那一條老師會寫在白板上，這一頁不印。原因是它會因為教室機的狀態而不同，照抄舊的比不抄還糟。

跑完抄這三行

怎麼拿到抄什麼
① 板端作業系統"$ADB" shell 'cat /etc/os-release'VERSION= 那一行
② 板端核心"$ADB" shell 'uname -r'整行
③ 電腦端 App Lab不是指令，用看的：App Lab 視窗最上面那條標題列版本號

抄到起步包裡的 版本抄寫單.txt，或直接打進 e學苑 那一格。行有餘力再多抄一行 "$ADB" shell 'arduino-cli core list'，不抄不扣分。

為什麼要抄？因為下週（或下下週）有人的板子壞了，第一件事就是比對版本。沒抄就只能猜。

7　跑 Blink：要看板上的燈真的閃

  1. 開 App Lab 的 Examples 頁，找到 Blink。
  2. 按右上角 Run。第一次可能要編譯，等一下。
  3. 看板子。板上紅色 LED 要真的閃。App Lab 畫面說成功不算數。

這是這門課的第一條規矩：它說成功不算，你自己看到才算。今天之後每一週都會再用到這句。

跑不動的時候

先看 adb 還在不在，不要重刷。多數問題是連線狀態或線材，重刷只會把板子改掉。offline 的處理在第 9 節。

行有餘力：網頁型 App

有些 App 是網頁介面，要把板子的埠轉到自己電腦上才開得起來：

"$ADB" forward --remove tcp:7000 2>/dev/null || true
"$ADB" forward tcp:7000 tcp:7000
xdg-open http://127.0.0.1:7000

不是每個 App 都用 7000 埠，以那支 App 的說明或啟動時印出來的訊息為準。
另外：你在板子上做的 App 存在板子的 /home/arduino/ArduinoApps/。重刷或學期末收板前要先備份，今天先知道有這件事就好。

8　裝 Antigravity（Ubuntu）

這是今天最後一件，也是唯一一件沒做完可以回家做的事。

  1. 拿檔案。Linux 版官方只給 .tar.gz（x64／ARM64），沒有 deb、沒有 snap。老師可能已經先下載好放共用目錄或 USB——先問，不要 26 台一起下載。
  2. 解壓。tar -xzf 檔名.tar.gz，解開就能跑，不必安裝。
  3. 登入。用個人 Gmail。

東華信箱登不進去，那是 Google 的規定，不是你的問題。官方寫得很明白：Antigravity 目前開放給個人 Google 帳號，Workspace 帳號有問題時請改用 @gmail.com。
另外官方明文不開放未滿 18 歲使用。未滿 18 的同學這一格跳過，在 e學苑 那一格寫一句原因，一樣算完成；下週用另一個工具練同一件事。

系統需求：glibc 2.28 以上（Ubuntu 20 以上都符合）。
教室機如果有還原卡，重開機可能會被清掉——那不是你裝壞了，回家再裝一次也算完成。
今天只要「裝好、登入成功」就停手，不必開始用它做事。

9　卡住怎麼辦＋今天交什麼

ADB 顯示 offline：三步

  1. 關掉 App Lab。
  2. 拔掉 UNO Q 的 USB 線，等幾秒再插回。等 LED 點陣恢復心跳，再開 App Lab。
  3. 重跑 "$ADB" devices -l。

不要一看到 offline 就想重刷。重刷會改動板子，而且多數 offline 是連線狀態或線材問題。

完全找不到板子：六查

  • 確認是資料線，不是只能充電的線。
  • 直接接電腦，先不要經過 hub。
  • 換一個 USB 埠，或換一條已知可傳資料的線。
  • 拔掉可能干擾的杜邦線。
  • 看 LED 點陣有沒有心跳。
  • 回讀 probe-normal.txt 的 udev 與 USB 段落（第 4 節跑出來那份）。

卡住時怎麼問 AI：把事實填滿

以下模板照抄自 UNO Q 設定指南（arduino-q labs/w01-same-board/ubuntu/學生設定指南.md）的「卡住時怎麼問 AI」，本週不另寫版本。

我在 Ubuntu <版本> 上使用 Arduino UNO Q。
我現在做的是 <App Lab 啟動／USB 偵測／ADB／Blink>。
我執行的完整指令是：<指令>
我預期看到：<結果>
實際看到：<完整錯誤原文>
probe-normal.txt 對應段落是：<貼相關段落，不貼密碼>

請先判斷問題在 Ubuntu 主機、USB／udev、ADB、板子 Linux、App Lab
或 STM32 哪一層。先只給我下一個唯讀檢查，不要直接更新、重刷或
修改系統檔案。

三條底線

  1. 密碼、帳號權杖與私人資料不貼給 AI。板子上 arduino 的密碼跟 Ubuntu 電腦的密碼是兩件事；不知道就問老師，不要寫進作業、不要貼進聊天視窗。
  2. AI 叫你改 /etc、udev、systemd 或重刷映像時，先給老師看。那些收不回來。
  3. 它說成功不算。回到 LED、lsusb、adb devices 或實際檔案再驗一次。
