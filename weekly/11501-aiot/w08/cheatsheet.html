2-4 雙向驗聲音（📸 證據 2 下半）

板子要有 card 1: UAC2Gadget [UAC2_Gadget], device 0: UAC2 PCM [UAC2 PCM]

aplay -l
arecord -l
cat /proc/asound/cards

電腦設定教室機（Ubuntu）⚠️ 現場為準：先 pactl list short sources／sinks 抄名字，再 module-loopback 各接一條（學生頁 2-4）；接不起來就跳過嗶聲與 peak，第三部分走網頁模式。在家用自己的 Windows 電腦：Win+R → mmsys.cpl → 錄製：① 麥克風 (UNO Q Audio) 接聽 → 聆聽此裝置 → 播到你的喇叭；② 電腦自己的麥克風 接聽 → 聆聽此裝置 → 播到 喇叭 (UNO Q Audio)。macOS ⚠️ 沒驗。

板子板→電腦：5 秒 440 Hz 嗶（卡住不動＝電腦沒在收）。電腦→板：播放軟體輸出指到 喇叭 (UNO Q Audio) 或對麥克風講話，板子錄 3 秒、算峰值（要明顯大於 0，接近 0＝沒流進板子；老師 peak 32000）

timeout 5 speaker-test -D plughw:UAC2Gadget,0 -c 2 -t sine -f 440
arecord -D plughw:UAC2Gadget,0 -f S16_LE -c 1 -r 16000 -d 3 /tmp/in.raw
python3 -c "import struct;d=open('/tmp/in.raw','rb').read();n=len(d)//2;print('peak',max(abs(v) for v in struct.unpack('<%dh'%n,d[:n*2])))"

🔑 p_ 板→電腦（麥克風、48k）、c_ 電腦→板（喇叭、64k）；電腦沒在收，板上的 aplay 就塞住不報錯。

第三部分 16:10–17:00板子裡的語音小助理

3-1 金鑰進板子

電腦網頁Google AI Studio（aistudio.google.com，個人 Gmail）建一把金鑰、複製（⚠️ 按鈕字樣現場為準）。金鑰是密碼：不截圖、不貼給 AI、不進 git。

板子貼上、Enter（畫面不顯示）；最後印字數，0＝沒貼進去

read -s -p "貼上金鑰再按 Enter（畫面不會顯示）: " K; printf %s "$K" > ~/.gemini_key; chmod 600 ~/.gemini_key; echo; wc -c ~/.gemini_key

~/.gemini_key 變成資料夾（先跑了 docker）：rmdir ~/.gemini_key 再建一次。

3-2 跑起來、開網頁

板子找映像（:0.13.1 或 :0.10.1 都行）、跑（一整行；這個視窗一直跑，Ctrl-C 停）；第一行要印 語音小助理：模型 …

IMG=$(docker images --format '{{.Repository}}:{{.Tag}}' | grep python-apps-base | head -1); echo $IMG
docker run --rm -it --name voice -u 0 --network host --device /dev/snd -v ~/w08-starter:/w08 -v ~/.gemini_key:/key:ro --entrypoint python3 "$IMG" /w08/voice_agent.py

電腦接通 7790，瀏覽器開 http://localhost:7790（一定要 localhost，網頁模式才開得了麥克風）

"$ADB" forward tcp:7790 tcp:7790

標題旁寫「改用這個」＝自動換成 2.5 模型，正常。找不到金鑰檔 /key → 3-1。

下面兩行出錯時才打（照順序打會把正在跑的小助理殺掉）：/key 是資料夾不是檔案 → 視窗 B Ctrl-C，打第一行，再做 3-1、重跑；名字衝突（Conflict）→ 視窗 C 打第二行再重跑

rmdir ~/.gemini_key

3-3 電腦聲音設定

教室機＝網頁模式：網頁上「輸入」切「這個網頁的麥克風」、「輸出」切「這個網頁」；麥克風＝教室機攝影機內建那支，Chrome 第一次問權限按允許（⚠️ 字樣沒驗）；"$ADB" forward tcp:7790 tcp:7790 照打。E307 的 USB 模式（loopback）⚠️ 沒驗。在家用自己的 Windows 電腦：2-4 設的兩個「聆聽此裝置」就是（①板子回話出你的喇叭、②你的麥克風進 喇叭 (UNO Q Audio)）。按住才講、放開就閉嘴、分組輪流。

3-4 問三題、看四個數字（📸 證據 3）

網頁按住大按鈕（或空白鍵）講、放開等。目標：①讓它說出板子現在的溫度（要看到 🔧 get_board_status＋JSON）②問出現在幾點或星期幾（🔧 get_time）③要它介紹自己（沒有 🔧）。用自己的話問。

四個數字：放開到開口（老師 1.07–1.57 秒；2.5 模型約 4.2）、回答長、收到音量（0＝聲音沒進板子）、輸入／輸出。「你說」是 Gemini 的簡體逐字稿，正常。綠條不動 → ①段（Windows ②）；紅字 聲音送不出 USB → ⑥段（Windows ①）或輸出切網頁。

3-5 兩條路比一比　3-6 讀程式、收尾

切網頁模式再問溫度一次，比秒數（老師 USB 1.57、網頁 2.08）。哪段壞對照表在學生頁 3-5。讀 voice_agent.py：PERSONA（人設與規矩）、TOOLS（它只能叫的兩個工具）、receiver（收到 toolCall 真的去讀板子）、player_loop（餵 aplay，塞 4 秒就放棄）。

板子視窗 B Ctrl-C 停；卡住視窗 C docker rm -f voice。三張證據上傳 e學苑（截圖裡不能有金鑰）。回家挑戰：照 get_time 加 get_wifi（函式＋TOOLS＋TOOL_FUNCS＋PERSONA），工具只讀不改。
