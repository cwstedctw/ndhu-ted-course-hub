UNO Q 是兩台電腦放在同一塊板子上：左邊跑 Linux 的 MPU，右邊跑即時作業系統的 MCU，中間只有一條序列線相連。點任何一塊，看它是什麼、數字多少、這週哪段程式碼碰到它。

右邊（手機在下面）會出現：它是什麼、有多大多快、這週哪一行程式碼碰到它，還有可以展開的「深入一層」。

深入一層：有沒有 MMU，差在哪裡

MMU（Memory Management Unit，記憶體管理單元）把程式看到的「虛擬位址」翻成實體位址。有它，Linux 才能讓每個行程（process）各有一個獨立的位址空間；沒有它，就只能跑「大家共用一片記憶體」的即時作業系統。

MPU：QRB2210（Cortex-A53）MCU：STM32U585（Cortex-M33）
晶片Qualcomm QRB2210另一顆獨立晶片，不在 QRB2210 裡面
指令集Armv8-A，64 位元Armv8-M，32 位元（只有 Thumb）
記憶體管理完整 MMU：4 KB 分頁、48 位元虛擬位址、4 級頁表 〔原始碼〕沒有 MMU；晶片有 MPU（區段權限保護、不做位址轉譯），但這板沒開：# CONFIG_ARM_MPU is not set 〔實板 07-25〕
位址空間每個行程一個一個實體位址空間，sketch 和 loader 共用
記憶體約 3.58 GiB LPDDR4X（4 GB 版）〔實板 07-25〕786 KB SRAM＋2 MB Flash 〔原始碼〕
時脈300–2016 MHz，9 檔（DVFS，動態調電壓頻率）〔實板 07-25〕160 MHz 〔原始碼〕
作業系統Debian 13、kernel 7.0（下游 BSP，有 PREEMPT、沒有 PREEMPT_RT）〔實板 07-25〕Zephyr RTOS（Real-Time Operating System）；常駐 loader 是一整套 Zephyr 4.2.0 〔原始碼〕
即時性分時排程，最壞延遲說不準固定優先權，中斷延遲算得出來
程式寫錯位址只有那個行程收到 segmentation fault，別人沒事可能靜靜踩壞 loader：CONFIG_USERSPACE、CONFIG_HW_STACK_PROTECTION 都沒開，TrustZone TZEN=0 〔實板 07-25〕——「信任模型，不是保護模型」
這週誰住這裡main.py、arduino-router、Wi-Fi、LED 1–2sketch.ino、點陣、LED 3–4

一句話分工：A53 有 MMU＋GB 級記憶體＋Linux，適合「複雜但不趕時間」；M33 沒有 MMU＋KB 級 SRAM＋RTOS，適合「簡單但要準時」。（MPU 深度版〈收束〉）

Zephyr 的優先權數線（這塊板的設定）

數字越小越優先。負的是合作式（cooperative，不被別的執行緒搶）、0 以上是可搶占（preemptible）、15 是 idle。

  • CONFIG_MAIN_THREAD_PRIORITY=14：只比 idle 高一格，等於把 Arduino 主迴圈當背景工作（Zephyr 一般預設是 0）〔實板 07-25〕。講義另註：setup()/loop() 是跑在 main thread 還是另一條 thread，還待接板核對。
  • 時間切片（time-slicing）是開的：CONFIG_TIMESLICE_SIZE=20（每片 20 ms），優先權 0–14 的執行緒同級會輪流跑 〔實板 07-25〕。
  • 系統時脈每秒 10,000 個 tick（每 tick 100 µs），而且是 tickless（沒事就睡到下一個逾時）〔實板 07-25〕。
  • Bridge 在 MCU 這邊用了 4 顆 k_mutex（read／write／bridge／call）＋一條名叫 bridge 的背景執行緒（thread）〔實板〕。

容器不是虛擬機

每支 App 的 Python 跑在自己的 Docker 容器裡 〔實板 10-02〕。容器是作業系統層的虛擬化：跟主機共用同一顆 Linux 核心，用 namespace（看到自己的行程樹與掛載點）、cgroup v2（資源上限）、overlayfs（分層檔案系統）隔開；虛擬機（VM）則是 hypervisor 底下各跑一顆核心。講義特別提醒：在 docker 群組幾乎等於 root（能把主機根目錄掛進容器），「免 root」不等於「安全沙盒」。（MPU 深度版 §3）

App 解剖：檔案與每一行

ANATOMY回目錄

app new my-aqi 建出的資料夾，每個檔案在不同時間、被不同的腦讀走。先點檔名，再點程式碼的任何一行，右邊會說這一行在做什麼、跑在哪顆腦上。下面的程式碼跟這週的 starter 檔逐字相同。

~/ArduinoApps/my-aqi/ ├─ ├─ python/ │ ├─ │ └─ └─ sketch/ ├─ └─

點檔名或任何一行

例如 main.py 第 47 行（快取有沒有過期）、第 29 行（真的上網）、sketch.ino 第 16 行（跨兩顆腦的那一行）。

深入一層：app start 那 100 秒在做什麼
  1. 讀設定：app.yaml（掛哪些積木）、sketch.yaml（平台＋函式庫）。第一次要上網下載 ArduinoGraphics 1.1.4，教室網路擋住就編不過。
  2. 在板子上編譯 sketch：編成 llext（Linkable Loadable EXTension，可載入的 ELF，型別 ET_REL）——不是一整支韌體 〔原始碼〕。
  3. 燒進 MCU：Linux 用三支 GPIO 以軟體「敲」出 SWD 燒錄訊號（OpenOCD 的 linuxgpiod 驅動），不用另買燒錄器 〔實板 07-25〕。燒錄設定 flash_sketch.cfg 先 verify、內容不同才 erase＋write 到 0x08100000 〔實板 08-17〕，燒完在 TAMP 備份暫存器寫 magic 0xCAFFEEEE 當「落地握手」〔原始碼〕。
    所以第一次或換了 sketch，一定會看到紅字 Error: verify failed in bank at 0x08000000 starting at 0x00100000：OpenOCD 把整顆 2 MB 當一個 bank，0x08000000 + 0x00100000 = 0x08100000＝sketch 區。最後有 ✓ App "…" started successfully 就是過。
  4. loader 接手：看到 magic → 從 0x08100000 讀 llext → 載入、重定位（relocation）、接符號 → 跑 setup()，再一直跑 loop()。
  5. 起容器跑 Python：log 會有 Container w5-aqi-main-1 Started 這種行 〔實板 10-02〕。
  6. 完成：✓ App "my-aqi" started successfully。第一次 96–108 秒（含下載函式庫），同一支第二次 23 秒 〔實板 10-02〕。

MCU 的 2 MB Flash 地圖

分割表 〔原始碼〕＋OpenOCD 實燒落點 〔實板 07-25〕。loader 的 .bin 是 226,548 bytes 〔實板 07-25〕，放在 768 KB 的槽裡。

開機序：從 MCUboot 到你的 loop()

  1. MCUboot 驗映像，跳到 loader。
  2. loader 讀 TAMP 備份暫存器的 magic 0xCAFFEEEE（TAMP 在 backup domain，軟體重置不會清掉）。
  3. 有 magic → 從 0x08100000 讀 sketch：llext_load → relocate → 接符號 → llext_bringup。sketch 被複製進 LLEXT heap（CONFIG_LLEXT_HEAP_SIZE=256，單位 KB）〔實板 07-25〕——sketch 跑在 RAM，不是直接從 Flash 執行。
  4. 把 setup()/loop() 包成一條 Zephyr 執行緒去跑。

為什麼需要跳板（trampoline）

Thumb 的 BL／B.W 指令只跳得到 ±16 MB。sketch 被搬到 SRAM（約 0x2000_0000），loader 在 Flash（0x0801_0000），兩邊相距約 400 MB，直接發 Thumb BL，重定位時會出現 truncated to fit 錯誤。ArduinoCore-zephyr 的做法：在原名底下放一段跳板，用 movw/movt 把完整 32 位元位址載進暫存器，再 blx 間接呼叫 〔原始碼〕。這跟 W15 的 Linux 核心模組（.ko 疊在跑著的核心上）是同一個母題：把外掛動態載入到正在執行的核心。

Bridge 一步一步

RPC OVER UART回目錄

Bridge.call 一行字，底下是一次 RPC（Remote Procedure Call，遠端程序呼叫）：打包成 MessagePack、過 UART、總機查表轉送、對方執行、再原路回來。按「下一步」走一次；也可以換成〈Color your LEDs〉的反方向，或把 call 換成 notify 看差別。




深入一層：MessagePack 的型別標記

序列化（serialization）＝把程式裡的值變成一串位元組。MessagePack 像「二進位版的 JSON」：每個值前面一個標記位元組說「我是什麼、多長」，小的整數和短字串把長度直接塞進標記裡，所以很省 〔原始碼〕。

型別標記位元組本週用到的例子
positive fixint（0–127）0x00–0x7f（值就是標記本身）type 0、msgid 1
fixarray（0–15 個元素）0x90–0x9f（低 4 位元＝元素數）外層 [type, msgid, method, params] → 0x94；空的 params [] → 0x90
fixstr（0–31 位元組）0xa0–0xbf（低 5 位元＝長度）"get_aqi_text" 12 位元組 → 0xac
nil0xc0回應的 error 欄（沒出錯）
false／true0xc2／0xc3LED 4 的 r != 0
uint 8／16／320xcc／0xcd／0xce＋後面 1／2／4 位元組LED 3 顏色值 128–255 → 0xcc＋1 位元組
str 8／16／320xd9／0xda／0xdb＋長度字串超過 31 位元組時
array 16／320xdc／0xdd＋長度（本週用不到）

MessagePack-RPC 在這上面約定三種訊息：request [0, msgid, method, params]、response [1, msgid, error, result]、notify [2, method, params] 〔原始碼〕。

深入一層：UART 線上，一個位元組長什麼樣

UART 平常停在高電位；送一個位元組＝1 個起始位元（低）＋8 個資料位元（最低位先送）＋1 個停止位元（高）。這叫 8N1，假設板子這樣設定，每個位元組佔 10 個位元時間 〔估算〕。

深入一層：msgid 怎麼配對、call 為什麼會卡住 loop()
  • msgid 配對：request 帶一個 32 位元的 msgid，response 帶回同一個 msgid；規格允許伺服器不照順序回覆，所以發問的那邊靠 msgid 把回覆對回原本的呼叫 〔原始碼〕。router 中間怎麼轉換，留到 W15 的 Bridge 原始碼導讀。本頁的 msgid 是示範值。
  • call 不會立刻卡住，.result() 才會：MCU 上 Bridge.call(...) 先回一個 RpcCall 物件；.result(text) 才阻塞等待，而且只能取一次。等待的方式是輪詢：k_mutex_lock＋K_MSEC(10)＋k_yield／k_msleep(1) 〔原始碼〕。
  • 所以 AQI 的 loop() 是「問 → 等 → 捲 → 再問」：.result() 等到回答，接著 endText(SCROLL_LEFT) 一步一步捲（每步 delay(60)），捲完才回到 loop() 開頭再問一次。log 大約 12 秒一行就是這樣來的 〔實板 10-02〕。
  • 冷啟動：nightlight lab 在 notify 處理函式裡用 Bridge.call，第一發逾時 10 秒，還把處理函式卡住；改成 Bridge.notify 後零逾時 〔實板 07-27〕。bridge-rtt 也量到第 1 發比較慢：7.7 ms，之後中位數 4.99 ms 〔實板 07-27〕。過橋前先問：我需要回覆嗎？不需要就用 notify。
深入一層：上網那一步拆開：DNS → TCP → TLS → HTTP
  1. DNS：把 data.moenv.gov.tw 換成 IP 位址。
  2. TCP：連到伺服器的 443 埠（HTTPS）。
  3. TLS（Transport Layer Security）握手：伺服器送出憑證鏈，Python 檢查三件事——鏈得到受信任的根憑證、沒過期、名字對得上 data.moenv.gov.tw。通過才開始加密傳資料。
  4. HTTP GET：/api/v2/aqx_p_432?api_key=…&format=JSON&filters=sitename,EQ,花蓮。金鑰就在網址裡，整段走在 TLS 加密裡面。
  5. 回應：一個 JSON 陣列、一筆資料；aqi、pm2.5 都是字串 〔實板 10-02〕。金鑰錯或用完時 HTTP 照樣是 200，內容是一行中文、不是 JSON——所以程式先 json.loads，失敗才判斷成 KEY?。

深入一層：跨晶片的 UART-RPC vs 課本上同晶片的 RPMsg

兩顆異質核心各跑各的作業系統、靠訊息合作，叫 AMP（Asymmetric Multiprocessing，非對稱多處理）。UNO Q 的做法跟課本常見的不一樣：

UNO Q課本常見（一顆 SoC 裡面 A 核＋M 核）
拓樸跨晶片：QRB2210 ↔ STM32U585同一顆晶片
傳輸實體 UART /dev/ttyHS1 @115200＋MessagePack-RPC＋arduino-router（星狀拓樸的中央總機）OpenAMP／RPMsg：共享記憶體＋硬體 mailbox
延遲／頻寬毫秒級／約 11.5 KB/s微秒級／記憶體匯流排等級
換到什麼物理隔離（Linux 當掉不會踩到 MCU）、各自重置、實作簡單快、頻寬大，代價是緊耦合

出處：MCU 深度版 §7.4 〔原始碼〕。所以 UNO Q 的兩顆腦適合交換「指令與結果」，不適合高速資料流。

深入一層：字串長度的門檻、4.99 ms 裡面有什麼

字串標頭什麼時候變長

  • 0–31 位元組：fixstr，標頭 1 位元組（0xa0 | 長度）。
  • 32–255 位元組：str 8，標頭 2 位元組（0xd9＋長度）。上面「加長到 34 字」就跨過這條線。
  • 256–65,535 位元組：str 16，標頭 3 位元組。
  • 算的是 UTF-8 位元組，不是字數：一個中文字通常 3 位元組。

4.99 ms 是怎麼量的

bridge-rtt 這個 lab 讓 Python 呼叫 MCU 上一個什麼都不做的 echo(i)，連打 200 發：中位數 4.99 ms、p95 5.08、最小 4.48、最大 5.20、冷啟動第 1 發 7.7 ms 〔實板 07-27〕。那個封包很小：request [0, id, "echo", [i]] 約 10 位元組、response [1, id, nil, i] 約 5 位元組（以 id、i 都小於 128 估），純傳輸約 1.3 ms 〔估算〕。

所以那次量測裡，UART 以外的成本大約 3.7 ms：打包解包、router 查表轉送、unix socket、兩邊執行緒排程。哪一段各占多少沒有分開量。AQI 這發的封包比 echo 大，如果其他成本差不多，往返大概 7–8 ms 〔估算〕——要確定，就用 bridge-rtt 的方法量 get_aqi_text。

  1. #include <ArduinoGraphics.h> 放在前面 → Arduino_LED_Matrix.h 用 __has_include 偵測到 → 點陣類別繼承 ArduinoGraphics，建構時給 13×8 畫布 〔原始碼〕。
  2. println 把字串一個位元組一個位元組收進文字緩衝（遇到 0xC2、0xC3 直接丟掉）。
  3. endText(SCROLL_LEFT)：總步數＝位元組數×5＋1；每一步把文字畫在 x＝−i、y＝1，畫完 delay(textScrollSpeed) 〔原始碼〕。
  4. 每畫一格就 renderBitmap：把 8×13 的 0/1 陣列打包成 4 個 32 位元字 → loadFrame → reverse() → matrixWrite()。
  5. 點陣本身由中斷常式掃描，標頭檔註解寫它支援 8 階灰階 〔原始碼〕。
