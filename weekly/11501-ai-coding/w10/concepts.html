0　這週做的東西，一張圖

你會做一個手機投票網站，而且是你自己部署上線的。

題目是「哪一關想看老師再做一次？」，三個選項：找不到部署按鈕／送出後試算表沒新增一筆／同學的手機打不開。同學在手機按一下，你的試算表 Votes 就多一列；電腦按「更新票數」看計數。規格 §〇·這週做什麼規格 §〇·三個選項

點一站，看它做什麼、住在哪台電腦。

三層＝前端（手機看得到的畫面）／後端（跑在 Google 機房的 Code.gs）／資料儲存（試算表 Votes，不同裝置看同一張表）。規格 §〇·三層

3　存檔不等於上線

部署（deploy）＝把程式變成一個別人打得開的網址。版本（version）＝部署當時那份程式的快照。

開店掛招牌是部署；菜單改版重印、招牌不換，是出新版本。改了程式只按「儲存」，/exec 不會變；要「部署 → 管理部署作業 → 選原本的 → 編輯 → 版本：新版本 → 部署」，網址不變、內容更新。按成「新增部署作業」會多一條新網址，發出去的舊網址不會更新。規格 §〇·存檔≠上線Google 官方·版本更新

/dev＝試吃口

/exec＝正門

正式網址。跑「部署當時那個版本」，給同學用的是這條。認尾巴就好。

6　做完改一行：兩條路

目標一樣：把投票板的標題改成「下一段想看老師重做哪一關？」，手機重新整理後看到新標題。兩條路同分。

路線 B＝瀏覽器問 AI，自己貼回編輯器，再出新版本。路線 A＝agent 加 clasp：agent 是會替你動手的 AI，改檔、下指令，但每一步你看計畫、你同意；clasp 是 Google 出的 Apps Script 命令列工具，讓 agent 把改好的程式直接推上你的專案、更新同一個網址。跟 W3 的 gh、W6 的 gws 同一套：它下指令、你同意。有自己的筆電、W6 或 W7 裝過 Node.js 的人走 A，其他人走 B。W6 的 gws 登入還在的人，做完還能叫同一個 agent 用 gws 讀 Votes 分頁數票（只准讀），操作頁路線 A 底下的〈延伸〉有寫。規格 §〇·兩條路規格 §〇·clasp 是什麼

① 問 AI貼上 Code.gs，請它找出 BOARD_TITLE，改成新標題，列出原本和改完的那一行。
② 自己貼回確認 AI 指的是畫面上看得到的那一行，貼回編輯器，儲存。
③ 新版本部署 → 管理部署作業 → 選原本的 → 編輯 → 版本：新版本 → 部署。
④ 手機重整原本的 /exec 重新整理，看到新標題。

操作頁·路線 B

① 裝 clasp（只做一次）開 PowerShell 貼三行：
winget install --id OpenJS.NodeJS.LTS -e --accept-package-agreements --accept-source-agreements --silent
$env:PATH += ";$env:ProgramFiles\nodejs;$env:APPDATA\npm"
npm install -g @google/clasp
裝過 Node.js 的只要最後一行。
② 登入、開開關打 clasp login，瀏覽器跳出來，選同一個個人 Gmail。再到設定頁把 Google Apps Script API 切成開啟。
③ 把專案抓下來專案設定裡複製 指令碼ID，在空資料夾打 clasp clone-script 貼上指令碼ID。會多出 Code.js、Index.html、appsscript.json；.gs 變 .js 是正常的。
④ 交給 agent用 Antigravity 或 Codex 開這個資料夾，講目標：改 BOARD_TITLE，先列計畫等你同意，改完 clasp push -f。先看計畫、再看改了哪幾行、不對就退回。
⑤ 更新同一個部署打 clasp list-deployments，找有版本號的那個 部署ID，再打 clasp create-deployment -i 貼上部署ID -d v2。手機重新整理看到新標題。
⑥ 收尾教室機下課前打 clasp logout，登入檔等於鑰匙。.clasp.json 不要放進 git。

8　名詞表

只放這週用到的詞，每個一句白話，加上「這週在哪一步碰到」。

前端（front end）
手機看得到、按得到的畫面。這週：Index.html，第 2 步貼進去。
後端（back end）
跑在 Google 機房的那支程式，收單、檢查、記帳。這週：Code.gs，第 2 步貼進去。
資料儲存
試算表 Votes，一票一列；誰開都是同一張。這週：第 3 步執行後長出來。
記憶體
機器記東西的地方；這週是試算表，下週 Python 來讀它。這週：第 2 節。
部署（deploy）
把程式變成一個別人打得開的網址。這週：第 4 步。
版本（version）
部署當時那份程式的快照；改了程式要出新版本，網址才會更新。這週：〈卡關時〉「想更新同一個網址」。
新增部署作業
再開一條新網址；舊網址不會跟著更新。這週：別按錯，第 3 節。
/dev、/exec
試吃口（只有編輯者、永遠最新存檔）／正門（給同學、跑部署版本）。這週：第 4 步認尾巴。
授權
你簽名同意這支程式替你動試算表；Google 問一次，少勾一項它就做不到。這週：第 3 步。
尚未驗證
Google 不認識這支程式，因為它是你自己剛貼的；不是壞掉。這週：第 3 步授權畫面。
誰可以存取
店門開給誰：只有我／要登入 Google 的人／所有人。這週：第 4 步選「所有人」。
更新票數
再問一次後端「現在幾票」。這週：第 4 步最後一下。
agent
會替你動手的 AI：改檔、下指令，但每一步你看計畫、你同意。這週：路線 A 第 ④ 步。
clasp
Google 的 Apps Script 命令列工具；讓 agent 把程式推上你的專案、更新同一個網址。像跑腿送菜單到店裡。這週：路線 A。
命令列（終端機）
用打字下指令的那個黑視窗（PowerShell）。這週：路線 A 第 ① 步。
指令碼ID／部署ID
專案的門牌號／那條網址的門牌號；抓專案用前者、更新網址用後者。不要貼進作業或公開頁面。這週：路線 A 第 ③、⑤ 步。
