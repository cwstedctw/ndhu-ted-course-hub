2　兩把鑰匙

config.js 會跟著網頁送到每個人的瀏覽器，所以裡面只放本來就可以公開的東西。

Supabase 有兩把鑰匙。publishable key 是公開鑰匙：讓網頁找得到你的 Supabase，放網頁、可以公開。secret key 是萬能鑰匙：能讀改所有人的資料，只能放在伺服器，瀏覽器裡用不了。真正擋住別人看你資料的是門禁，不是把鑰匙藏起來。規格 §〇·兩把鑰匙起步檔 config.js

🚨 只拿 publishable key。secret key 不進 config.js、不進 GitHub、不貼給 AI。操作頁 第 3 步

3　門禁模擬器

兩道關：這排櫃子有沒有開放給登入的人（grant），每一格是不是只認自己的學生證（RLS）。

RLS（資料列門禁）＝資料庫自己檢查「這一列是不是你的」，不是你的就當作不存在。grant（開放權限）＝這張表開放給「登入的人」用；沒開放，刷卡也進不去。規格 §四·白話與比喻

這兩件事 Supabase 都不會替你做：在 SQL Editor 建的表，RLS 預設沒開；2026 年起新建的表也不再自動開放，沒有 grant 就用不了。所以 schema.sql 裡一定要有下面這兩行。規格 §〇·RLS 預設規格 §〇·2026 新規則

      7　名詞表

      只放這週的十個詞：每個一句白話、一個置物櫃那一套的比喻，加上這週在哪一步碰到。

      資料表
      一張表，一列＝一筆紀錄。比喻：一整排置物櫃，一格放一筆。這週：learning_logs，第 3 步用 schema.sql 建。
      登入
      Supabase 認出你是誰，發你一張通行證。比喻：刷學生證。這週：第 6 步兩個帳號各登入一次。
      RLS（資料列門禁）
      資料庫自己檢查「這一列是不是你的」，不是你的就當作不存在。比喻：每格只認自己的學生證，別人的櫃子刷不開，連看都看不到。這週：第 3 步打開、第 6 步驗收。
      grant（開放權限）
      這張表開放給「登入的人」用。比喻：這排櫃子有沒有開放給學生；沒開放，刷卡也進不去。這週：schema.sql 最後那一段，第 3 步跑。
      publishable key
      公開鑰匙：讓網頁找得到你的 Supabase，本來就看得到。比喻：置物櫃區的地址和開放時間，大家都知道。這週：第 3 步貼進 config.js。
      secret key
      萬能鑰匙：能讀改所有人的資料，只能放在伺服器。比喻：管理員的萬能鑰匙，絕不能掛在門口。這週：第 3 步的紅框，不拿它。
      repo
      GitHub 上放這個網站所有檔案的地方，每一版都留著。比喻：作品的檔案櫃。這週：第 4 步建 learning-log。
      deploy（部署）
      把檔案放到一個大家打得開的網址。比喻：把作品貼到校門口的公告欄；倉庫換新版，公告欄自動換。這週：第 5 步接上 Cloudflare、第 7 步改版。
      pull request（PR）
      「我想改你的東西」的申請，看過再合併。比喻：別人遞給你的修改單，簽了才算數。這週：第 5 步合併 Cloudflare 開的那一個。
      agent
      會自己寫檔、下指令的 AI。比喻：你請來的工讀生，你說清楚、它動手、你驗收。這週：路線 A 在第 2 步把需求卡交給它。

      沒有符合的名詞，換個字試試。
