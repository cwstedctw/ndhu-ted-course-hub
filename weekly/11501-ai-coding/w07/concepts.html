1　Webhook：誰打給誰

  1. Webhook 一句話：不是你去問 LINE，是 LINE 主動打到你給它的網址。
  2. 所以那個網址要「外面連得到、而且一直開著」——Apps Script 的 /exec 就是。
  3. 你的筆電沒有公開網址，LINE 打不到它，所以才需要通道（第 3 節）。

你給它的網址Apps Script 的 /exec：外面連得到、一直開著

按「傳一句話」，看那一小點怎麼走。

Webhook＝人家主動找你、要有公開網址；polling＝你主動去問、不用公開網址但一直在問。這週的 bot 走 Webhook，所以接收端一定要住在雲端（第 2 節）。

2　雲端在哪：這週的東西各住在哪台電腦

  1. 雲端就是別人機房裡的電腦：永遠開著、有公開網址。
  2. 你的筆電躲在分享器後面：沒有公開網址，關了就不在。
  3. 這週把 bot 留在雲端，只有「查 …」那條路回到你的電腦——所以關掉轉接站，待辦照常。

3　為什麼要通道

  1. 通道借你一個外面連得到的門牌（https://….trycloudflare.com），把打來的東西送進分享器後面的筆電。
  2. 門牌每次重開都會換：換了只要改指令碼屬性，不用重新部署。
  3. Webhook 不用動：LINE 還是打 Apps Script 的 /exec；是 Apps Script 走通道來找你的筆電。

4　轉接站與密碼：試著打打看

  1. 轉接站只聽 127.0.0.1:8787：外面只能從通道進來，而且要帶對密碼（x-relay-key）。
  2. 一次一題（429）、最多想 45 秒（504）：因為 LINE 的回覆碼只能用一次、而且很快就失效（官方沒給確切秒數）。
  3. 密碼不印在畫面上、只放剪貼簿和家目錄的 .line-search-relay.key 檔——螢幕可能正在投影。

5　金鑰放哪：程式碼，還是指令碼屬性？

  1. 會被偷走的（密碼、通行碼）、會換的（通道網址）、指著你資料的（試算表代號）→ 指令碼屬性。
  2. 規則與邏輯（「查 」才轉、分類五選一、等 50 秒）→ 程式碼。
  3. 程式碼會上 GitHub、會被截圖、會整份貼給 AI；指令碼屬性只有你看得到。

7　名詞表

Webhook
不是你去問 LINE，是 LINE 主動打到你給它的網址；那個網址要外面連得到、而且一直開著。
polling（輪詢）
你的程式每隔幾秒去問一次有沒有新訊息；不用公開網址，但一直在問。
雲端（cloud）
別人機房裡的電腦——永遠開著、有公開網址；LINE 機房、Apps Script、Gemini 都在那裡。
通道（tunnel）
借一個外面連得到的門牌（https://….trycloudflare.com），把打來的東西送進分享器後面的電腦；每次重開門牌會換。
轉接站（relay）
你電腦上的一支小程式（line-search-relay.mjs）：只聽本機 127.0.0.1:8787、對密碼、叫本地模型查、一次一題、最多想 45 秒。
指令碼屬性
Apps Script「專案設定」最下面的一張表，放網址與密碼；程式用 PROPS.getProperty 讀，不寫進程式、換了不用重新部署。
本地模型
跑在你電腦上的模型（Ollama 的 gemma4:e4b）：會上網搜、附來源；電腦關了就沒了。
JSON
電腦之間傳資料用的大括號寫法，一個名字配一個值（例如 {"question":"問題"}），轉接站收的、回的都是這種。
