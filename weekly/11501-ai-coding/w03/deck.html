卡 7 · 改壞再救回
卡 7：改壞了，救得回來
還沒存的錯用 restore；已經出去的錯用 revert。
restore還沒 commit 的錯一秒回到上一版
revert已經 push 出去的錯再加一筆改回去，歷史不改寫
v0→v1→故意弄壞→Revert
7a 弄壞
請把 index.html 裡整段 <script>…</script> 刪掉並存檔，但不要 commit。然後顯示 git diff，告訴我現在工作區有什麼變化。
7b 救回
我不要這個修改。請用 git restore 把 index.html 救回上一版，然後證明 diff 已經是空的、工作區乾淨。不要用 reset。
7c 再弄壞
請再把 <script> 那一段刪掉一次，這次 commit（訊息寫「練習：故意刪掉 script」）並推上 GitHub。推完告訴我這筆 commit 的 hash。
7d 撤銷
剛剛那筆是故意弄壞的。請用 git log 找到它，用 git revert 撤銷它（會新增一筆撤銷 commit，原本那筆留在歷史裡），然後推上 GitHub。全程不准 reset、rebase、force push。做完顯示最近四筆歷史，並確認本機與 origin/main 一致。
檢查點：歷史四筆都在，網址又活了
