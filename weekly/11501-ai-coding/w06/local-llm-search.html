本地模型也能上網搜：我們在 msi 試過的四條路

你電腦裡跑的模型（本地模型，local LLM）本來不會上網。這一頁示範四種「幫它接上搜尋」的做法：哪一條最像 ChatGPT、哪一條最看得清機制、哪一條我們試了但不推薦。每一條都附實走時間、截圖和踩過的坑。

先講清楚一件事：模型本身不會上網

會搜尋的不是模型，是「app 幫模型接了一個搜尋工具」。模型做的只有兩件事：決定要不要搜、搜什麼；以及讀搜尋結果、寫出答案。真正連到網路、把網頁抓回來的，是 app（或你寫的程式）。

ChatGPT 看起來會上網，也是同一回事：背後有個程式替模型執行搜尋，再把結果塞回去給模型讀。所以「本地模型＋搜尋」＝本地模型＋一個會給它工具的程式。四條路差別只在「那個程式是誰」：Ollama 桌面 app、LM Studio、你自己的 Python 小程式、還是一個瀏覽器擴充功能。

術語對照（這頁只用這幾個）
  • 工具呼叫（tool calling）：模型回一段「我要用某個工具、參數是什麼」，由程式去執行、再把結果送回去。
  • 系統提示（system prompt）：放在對話最前面、給模型的工作說明。路 A 的 gemma4-search 就是靠這個，模型才會「不確定就先搜」。
  • MCP（Model Context Protocol）：一種讓 app 接外部工具的共同格式；路 B 用它接 DuckDuckGo 搜尋。
  • 思考模式（thinking／reasoning）：模型先自言自語推理再回答。對這類「要不要搜」的判斷，Gemma 4 開著思考反而拖慢、甚至拒搜（見〈共同的坑〉）。

路 A・Ollama 桌面 app＋gemma4-search 課堂用・最像 ChatGPT

已勾 0／0 步

做什麼

Ollama 的桌面 app 內建「網頁搜尋」開關（輸入框旁的地球圖示）。開著之後，模型覺得該查就會查，app 幫它搜、再把結果交回去。我們多做一件事：用一個 Modelfile 幫 gemma4:e4b 加上系統提示，做成 gemma4-search，模型才會「不確定就先搜，不要以還沒發生為理由拒查」。

要裝什麼

  • Ollama 桌面 app（實走版本 0.40.1，winget 套件 Ollama.Ollama，不需要管理員權限）
  • 模型 gemma4:e4b（6.6 GB；msi 實拉 211 秒、約 36 MB/s）
  • 一個文字檔 Modelfile（內容在第 3 步，複製即可）

逐步做

  1. 到官網下載安裝，或在 PowerShell 打：

    winget install Ollama.Ollama

    第一次開 app 會問「Create an account／Sign in／No thanks」。選 No thanks 就能先本機用，搜尋也照樣能跑（當天連跑 3 次都通）。免費帳號是選用的（可以提高搜尋額度、用雲端模型），不是必要。⚠️沒登入的搜尋額度上限官方文件沒寫，我們沒驗到。

  2. ollama pull gemma4:e4b

    6.6 GB，看網速；msi 上 211 秒。

  3. 從課程網的 W6 starter 資料夾取得，或把下面內容複製後存成一個叫 Modelfile 的檔案（沒有副檔名；記事本存檔時「存檔類型」選「所有檔案」，編碼用 UTF-8）。

    starter/Modelfile（建置時從原檔塞入）

    FROM gemma4:e4b
SYSTEM """你是研究助理。你有網路搜尋與讀網頁的工具。今天的日期可能在你的訓練資料之後，所以遇到「最近發生的事、某一年的得獎名單、版本號、價格、新聞」或任何你不確定的事實，一律先用搜尋工具查，查到再回答，並附上來源網址；不要以「還沒發生」為理由拒絕查詢。回答用繁體中文（台灣用語）。"""
PARAMETER num_ctx 16384

    三行意思：以 gemma4:e4b 為底、加一段系統提示（「日期可能在訓練之後，不確定一律先搜、附來源、不要以還沒發生為由拒查」）、把對話長度（num_ctx）拉到 16384，搜尋結果才塞得下。

  4. 在 Modelfile 所在的資料夾開 PowerShell：

    ollama create gemma4-search -f Modelfile

    大約 1 秒，不會重新下載（它只是在 gemma4:e4b 外面包一層設定）。

  5. 模型名在輸入框右下角。app 預設選的是雲端模型 glm-5.3-flash:cloud（中國模型，本課不用），一定要換掉。點模型名、在清單裡搜 gemma4-search。

  6. 亮起來（有藍色外框）才是開著。

  7. 例如〈三道考題〉的第 1 題。題目照平常問就好，不必寫「請搜尋」。

你應該看到

卡住了？（路 A 常見狀況）
  • 模型清單裡預設是雲端的 glm：那是 glm-5.3-flash:cloud，請換成 gemma4-search（第 5 步）。
  • app 卡在「Loading…／Run Ollama」導覽頁：通常是之前從指令列另外啟動過 Ollama 伺服器。把工作管理員裡的 ollama app.exe 和 ollama.exe 都結束，再開 app。
  • 模型想了一陣子後說「2026 年還沒到」、不搜：你用的是原始的 gemma4:e4b（實測想 19 秒後拒搜）。app 沒有地方放系統提示，所以才要第 3、4 步做出 gemma4-search。
  • 搜到了卻回「請告訴我你要我做什麼」：原始 gemma4:e4b 在第 3 題出現過這種不穩。再問一次，或換 gemma4-search。
  • 找不到地球圖示：Settings 裡有「Cloud：Enable cloud models and web search」開關（預設開），搜尋功能歸它管。⚠️我們沒有把它關掉再試，關了會怎樣未驗。

優點

  • 最像 ChatGPT：有視窗、有搜尋開關、答案附來源。
  • 不用帳號、不用終端機（只有 pull／create 兩行指令）。
  • 搜尋結果可以展開看原始資料，機制看得到。

缺點

  • 系統提示要靠 Modelfile 另做一個模型，app 本身沒地方改。
  • 模型判斷不穩，同一題偶爾會拒搜或答非所問。
  • ⚠️沒登入的搜尋額度上限不明。

路 B・LM Studio＋MCP 模型自己呼叫 DuckDuckGo，有核准框

已勾 0／0 步

做什麼

LM Studio 也是桌面 app，但工具是用 MCP（Model Context Protocol）接的：你在一個 mcp.json 裡宣告「有一個叫 duckduckgo 的工具伺服器」，模型想搜時 LM Studio 會跳一個核准框「Model wants to call search」，你按 Proceed 它才去搜。跟路 A 是同一個機制，只是把「模型要呼叫工具」那一刻亮給你看。

要裝什麼

  • LM Studio（實走版本 0.4.25，winget 套件 ElementLabs.LMStudio）
  • 兩個 GGUF 模型檔（lmstudio-community）：gemma-4-E4B-it-Q4_K_M.gguf 5.34 GB＋mmproj-gemma-4-E4B-it-BF16.gguf 0.99 GB
  • uv（Python 套件工具，實走版本 0.9.7；mcp.json 用它的 uvx 啟動搜尋伺服器）

逐步做

  1. winget install ElementLabs.LMStudio

    指令列工具 lms 在 %USERPROFILE%\.lmstudio\bin\lms.exe，要等第一次開過視窗才會出現。

  2. app 內建下載（lms get gemma-4-e4b）在 msi 只有 0.45–0.8 MB/s，估要 2.5–3.75 小時；改用瀏覽器到 Hugging Face 的 lmstudio-community 頁面直接抓那兩個 GGUF，29–42 MB/s、182 秒。

  3. lms import <gguf 檔路徑> --user-repo <自己取個名字> --copy --yes

    ⚠️mmproj 那支是給模型看圖用的附屬檔；紀錄只寫了主模型這一行指令，文字問答需不需要它、怎麼一起匯入，我們沒單獨驗。

  4. pip install uv

    或 winget install astral-sh.uv。裝好要有 uvx 這個指令。

  5. 檔案位置 %USERPROFILE%\.lmstudio\mcp.json，內容：

    {"mcpServers":{"duckduckgo":{"command":"uvx","args":["duckduckgo-mcp-server"]}}}

    意思：有一個叫 duckduckgo 的工具伺服器，用 uvx duckduckgo-mcp-server 啟動（第一次會自動下載）。

  6. 載入 msi 上約 15 秒。

  7. LM Studio 載 Gemma 4 預設思考是開的。開著時模型想了 7 分 31 秒才決定呼叫工具（見下圖），關掉才可用。⚠️這一步的開關位置我們沒截圖，在聊天輸入區的設定裡找 Think／Reasoning。

  8. 核准框會顯示模型自己填的搜尋關鍵字（Arguments）。下面有「Always allow search from mcp/duckduckgo」可勾，之後就不用每次按。

你應該看到

卡住了？（路 B 常見狀況）
  • app 內建下載極慢：這台只有 0.5–0.8 MB/s。改用 Hugging Face 直接下載再 lms import（第 2、3 步）。
  • 模型檔明明在、lms ls 卻看不到：中斷過的官方下載會把同名資料夾卡住。lms import 時換一個 --user-repo 名字就好。
  • 問了很久都沒動靜：多半是 Think 開著（第 7 步）。
  • 用程式打 API 帶 "integrations":["mcp/duckduckgo"] 回「Permission denied to use plugin」：要先在 LM Studio 的 Server Settings 開「Allow calling servers from mcp.json」，而這個開關要先把「Require Authentication」（API 要帶 token）打開才按得下去（設定鍵 pluginUse 從 deny 改 allowAll）。學生走視窗操作不需要這一步，只有自己寫程式呼叫 API 才會碰到。
  • Ollama 同時在跑、回 CUDA 錯誤：8 GB 顯示卡只能載一套，見〈共同的坑〉。

優點

  • 「模型要呼叫工具」那一刻看得見，連它填的搜尋關鍵字都能改（Edit）。
  • MCP 是通用格式，之後想接別的工具也是同一套 mcp.json。
  • 不用帳號。

缺點

  • 要裝的東西最多（app、兩個模型檔、uv、mcp.json）。
  • 模型檔要另外想辦法下載，app 內建下載在這台太慢。
  • Think 忘了關就要等很久；⚠️完整三題我們沒跑完。

路 C・終端機（terminal）小程式 search_agent.py 最透明，看得到每一次工具呼叫

已勾 0／0 步

做什麼

一支一百行不到的 Python 程式：把「web_search」「fetch_page」兩個工具的說明交給模型，模型回「我要呼叫 web_search、關鍵字是…」，程式就真的去 DuckDuckGo 搜，把結果送回去，最多來回六輪。終端機上每一次呼叫都印出來——這是這一頁裡唯一能讓你把流程圖每一格都對上程式碼的做法。

要裝什麼

  • Ollama 在跑＋已經 ollama pull gemma4:e4b（路 A 第 2 步）。實走是用指令列 ollama serve 當後端；桌面 app 開著時背後也是同一個伺服器，⚠️但我們沒用 app 當後端跑過這支程式
  • Python 3（程式只用標準函式庫＋一個套件 ddgs）

逐步做

  1. pip install ddgs

  2. 從課程網的 W6 starter 資料夾取得，或展開下面的〈程式全文〉複製後存成 search_agent.py。

  3. python search_agent.py

    輸入問題按 Enter；打 q 離開。

  4. python search_agent.py "2026 年諾貝爾物理獎得主是誰？得獎理由是什麼？"

你應該看到

終端機會先印模型名，然後每當模型決定用工具就印一行 🔍，最後印秒數與答案（下面是依實走紀錄整理的示意，不是逐字截圖）：

本地模型 gemma4:e4b，輸入問題（q 離開） 你：2026 年諾貝爾物理獎得主是誰？得獎理由是什麼？ 🔍 模型決定呼叫 web_search：{"query": "…"} ⏱ 7–23 秒（首題含載入約 27 秒） 模型：（答案，附實際用到的來源網址）

msi 實測三題（見〈三道考題〉）全部由模型自己決定呼叫工具、全對、都附來源：

  • 第 1 題物理獎：搜一次，答 Halzen＋IceCube，附兩個來源。
  • 第 2 題醫學獎：搜一次，答三位得主＋光遺傳學，附來源。
  • 第 3 題 Ollama 版本：搜一次、再用 fetch_page 讀 GitHub releases 頁，答 v0.40.2／10 月 8 日並說明那是快照（snapshot）版。對照標準答案（releases/latest 查到的 v0.40.1、10-07）——同一天問「最新版」，看的頁面不同答案就不同，這正是第 3 題答案會變的原因。

配方要點：think: false＋系統提示＋題目本身不提搜尋。三樣都在程式裡，不用自己設。

程式全文 search_agent.py（建置時從 starter 原檔塞入） 
# 本地模型＋網路搜尋：模型自己決定要不要搜（工具呼叫）
# 需要：Ollama 在跑、已 pull gemma4:e4b；pip install ddgs
# 用法：python search_agent.py            （互動模式，輸入 q 離開）
#       python search_agent.py "你的問題"  （問一題就結束）
import json, sys, time, urllib.request, re, html
from ddgs import DDGS

MODEL = "gemma4:e4b"
OLLAMA = "http://127.0.0.1:11434/api/chat"
SYSTEM = ("你是研究助理。你有 web_search 與 fetch_page 兩個工具。遇到最近發生的事、日期在你知識之後的事、版本號、價格，"
          "或任何你不確定的事實，先呼叫 web_search；搜尋結果不夠明確時，用 fetch_page 讀官方頁面確認。"
          "回答用繁體中文，附上你實際用到的來源網址；查不到就老實說查不到。")
TOOLS = [
    {"type": "function", "function": {"name": "web_search", "description": "用 DuckDuckGo 搜尋網路，回傳前幾筆的標題、網址、摘要。",
     "parameters": {"type": "object", "properties": {"query": {"type": "string", "description": "搜尋關鍵字"}}, "required": ["query"]}}},
    {"type": "function", "function": {"name": "fetch_page", "description": "讀取一個網頁，回傳主要文字（前 3000 字）。",
     "parameters": {"type": "object", "properties": {"url": {"type": "string"}}, "required": ["url"]}}},
]

def web_search(query):
    rows = DDGS().text(query, max_results=5)
    return json.dumps([{"title": r.get("title"), "url": r.get("href"), "snippet": r.get("body")} for r in rows], ensure_ascii=False)

def fetch_page(url):
    req = urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0"})
    raw = urllib.request.urlopen(req, timeout=20).read(400000).decode("utf-8", "replace")
    txt = re.sub(r"<script.*?</script>|<style.*?</style>", " ", raw, flags=re.S | re.I)
    txt = html.unescape(re.sub(r"\s+", " ", re.sub(r"<[^>]+>", " ", txt)))
    return txt[:3000]

def ask_model(messages):
    body = json.dumps({"model": MODEL, "messages": messages, "tools": TOOLS, "stream": False,
                       "think": False, "options": {"num_ctx": 16384}}).encode()
    req = urllib.request.Request(OLLAMA, data=body, headers={"Content-Type": "application/json"})
    return json.loads(urllib.request.urlopen(req, timeout=900).read())["message"]

def answer(question, log=print):
    msgs = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": question}]
    t0 = time.time()
    for _ in range(6):                      # 最多六輪工具呼叫
        m = ask_model(msgs); msgs.append(m)
        calls = m.get("tool_calls") or []
        if not calls:
            break
        for c in calls:
            fn = c["function"]["name"]; args = c["function"].get("arguments") or {}
            log(f"  🔍 模型決定呼叫 {fn}：{json.dumps(args, ensure_ascii=False)}")
            try:
                out = web_search(args.get("query", "")) if fn == "web_search" else fetch_page(args.get("url", ""))
            except Exception as e:
                out = f"ERROR: {e}"
            msgs.append({"role": "tool", "content": out, "tool_name": fn})
    log(f"  ⏱ {time.time() - t0:.0f} 秒")
    return msgs[-1].get("content", "")

if __name__ == "__main__":
    if len(sys.argv) > 1:
        print(answer(" ".join(sys.argv[1:])))
    else:
        print(f"本地模型 {MODEL}，輸入問題（q 離開）")
        while True:
            q = input("\n你：").strip()
            if q.lower() in ("q", "quit", "exit"): break
            if q: print("\n模型：" + answer(q))

讀法：TOOLS 是交給模型的工具說明書；ask_model 打本機 Ollama 的 /api/chat（think: false、num_ctx 16384）；answer 那個迴圈就是流程圖——模型回 tool_calls 就去執行、把結果以 role: tool 送回，直到模型不再呼叫工具。

卡住了？（路 C 常見狀況）
  • 第一題特別慢：含模型載入，約 27 秒；之後單題 7–23 秒。
  • 印出 ERROR: … 當工具結果：程式把搜尋或讀網頁的錯誤原樣交給模型，讓它決定下一步（換關鍵字或老實說查不到）。
  • 模型沒搜就答：系統提示已要求「不確定就先搜」，但模型判斷不是百分之百；再問一次或把題目講具體。
  • LM Studio 同時載著模型、Ollama 回 CUDA 錯誤：見〈共同的坑〉。

優點

  • 每一次工具呼叫都印出來，機制完全透明。
  • 三題全對附來源，單題 7–23 秒，是四條路裡實測最穩的。
  • 程式短，可以自己改：換工具、換模型、加規則。

缺點

  • 沒有視窗，要在終端機操作。
  • 搜尋靠 DuckDuckGo 的 ddgs 套件，被擋或改版就要修。

路 D・Page Assist（Chrome 擴充功能） 試過、不推薦

為什麼不推薦

Page Assist（實走版本 1.5.86）是一個瀏覽器擴充功能（extension），把 Ollama 的模型包成聊天視窗，也有「網路搜尋」開關。我們裝了、設了、三題都問了，結論是不當主線，理由有三：

  • 不是模型自己決定搜：它是擴充功能先去搜、把結果塞給模型，模型只能照單讀。跟這一頁要教的「模型判斷要不要搜」不是同一件事。
  • 要多裝一個嵌入模型：ollama pull nomic-embed-text（274 MB），沒裝會顯示「Please set an embedding model on the Settings > RAG page」。
  • 在這台搜尋引擎幾乎都被擋：DuckDuckGo 對擴充功能回 HTTP 202（機器人驗證頁，14 KB、沒有結果；同一網址用 curl 是 200 有結果，所以是針對瀏覽器端的擋）；Google 回一頁要 JavaScript 的空頁；只有 Bing 真的回結果，但中文結果差。結果三題都答不出。

留著這條是為了對照：同樣是「本地模型＋搜尋」，誰決定搜、誰去搜，差很多。

三道考題：不開搜尋問一次、開搜尋問一次

這三題都是「要搜尋才答得對」：兩題是 2026 年 10 月初剛公布的諾貝爾獎，一題是軟體版本號。建議同一題問兩次——先不開搜尋（路 A 把地球關掉），再開搜尋——只看兩件事：答對沒、有沒有附來源。msi 實測不開搜尋時，Gemma 4 e4b 三題都答「不知道／尚未公布」。

共同的坑（四條路都會踩到）

  • 8 GB 顯示卡一次只能載一套：Ollama 和 LM Studio 同時把 Gemma 4 e4b 載進顯示卡記憶體（VRAM）會撞，Ollama 回 500「CUDA error」。只裝一套，或換邊前先 lms unload --all（LM Studio）／關掉另一邊。實測 Ollama 載 gemma4:e4b 用掉 6.0 GB。
  • 思考模式會拖慢、甚至拒搜：LM Studio 開著 Think 想了 7 分 31 秒才下工具；Ollama app 用原始 gemma4:e4b 想 19 秒後認定「2026 還沒到」不搜。路 C 的程式直接 think: false，路 A 靠 Modelfile 的系統提示，路 B 要手動關 Think。
  • 第一次載入要等：Ollama 首問含載入 150 秒（不開搜尋量到的）、之後每題約 6 秒（82–87 tok/s）；LM Studio 載入約 15 秒、31 tok/s，思考預設開時每題 32–43 秒。
  • 模型政策：本課只用美國公司的開放模型——Gemma 4（Google）與 gpt-oss（OpenAI）；不用 Qwen、DeepSeek、GLM。Ollama app 預設的 glm-5.3-flash:cloud 就是要換掉的那一個。
  • 下載速度差很多：ollama pull 約 36 MB/s；LM Studio 內建下載在這台只有 0.5–0.8 MB/s；Hugging Face 直接下載 29–42 MB/s。課堂若用 LM Studio，模型檔要另外給下載法。
  • 模型判斷不是百分之百：同一題偶爾會拒搜或答非所問（路 A 的「請告訴我你要我做什麼」）。再問一次、把題目講具體、或換有系統提示的版本。
  • 題目不用寫「請搜尋」：三題實測題目本身都不提搜尋，模型照樣自己決定搜。寫了反而測不出「它會不會判斷」。
