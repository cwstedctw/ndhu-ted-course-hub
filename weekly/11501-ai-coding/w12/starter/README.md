# 最近 7 天（W12 起步檔）

這個資料夾只做一件小事：算出「最近 7 天學了幾分鐘、記了幾筆」。
重點不在這個功能，在做法：先寫規則，先寫測試，再寫功能。

| 檔案 | 做什麼 | 誰來改 |
|---|---|---|
| `rules.md` | 你的規則：哪些紀錄算、哪些不算 | 你 |
| `tests.js` | 測試：一條測試＝一個情況，加上它應該算出的答案 | 請 AI 照規則寫 |
| `recent7.js` | 功能本體：照規則寫的版本 | 請 AI 寫，寫到測試全過 |
| `recent7-quick.js` | 對照用：只用一句話請 AI 寫的版本 | 請 AI 寫 |
| `tests.html` | 測試頁：打開就看到每條測試過了沒 | 不要改 |
| `README.md` | 這份說明 | 不用改 |

## 怎麼看測試結果

用瀏覽器打開 `tests.html`。表格有四欄：名字、我預期、實際上、一樣嗎。
全部一樣是綠燈；有一條不一樣就是紅燈。改了檔案之後，重新整理這一頁。
想看一句話版過了幾條，按頁面上的「考一句話版」。

在 GitHub 網頁上改的檔，不會跑進你電腦裡的資料夾。那種情況用測試頁最下面的「貼上模式」：把內容貼進去，按「用貼上的內容跑測試」。

## 資料長什麼樣

一筆學習紀錄：

    { log_date: '2026-11-23', minutes: 30 }

- `log_date`：哪一天，寫成 `'年-月-日'`。
- `minutes`：學了幾分鐘。沒填的時候是 `null`。
- 紀錄可能還有別的欄位（例如 `topic`），這個功能用不到。

## 功能的格式（recent7.js 和 recent7-quick.js 都一樣）

    function recent7(records, today) {
      // records：一串紀錄（陣列）
      // today：今天的日期，例如 '2026-11-23'
      return { minutes: 0, count: 0 };   // minutes＝總共幾分鐘，count＝幾筆
    }

「今天」一律用傳進來的 `today`，不要自己去問電腦現在幾號。這樣同一條測試哪一天跑都是同樣的結果。
要怎麼算，不寫在這裡，看 `rules.md`。

## 測試的格式（tests.js）

一條測試呼叫一次 `addCase`：

    addCase({
      name: '規則 1：（這條測試在檢查什麼）',
      today: '2026-11-23',
      records: [
        { log_date: '2026-11-23', minutes: 30 }
      ],
      expect: { minutes: 30, count: 1 }
    });

- `name` 開頭寫它對應 `rules.md` 的第幾條規則。
- `expect` 寫「照規則應該算出什麼」。測試頁只比 `expect` 裡寫到的欄位。

## 給 AI 的三條約定

1. 用一般的 `function recent7(records, today) { ... }`。不要用 `export`、`import`、`require`、`module.exports`，測試頁會讀不到。
2. 不要改 `tests.html`，也不要新增其他檔案。
3. 一次只做被交代的那個檔。寫測試的時候不寫功能；寫功能的時候不改測試。
